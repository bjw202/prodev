`evo-count.js allow` 가 `prodev-orchestrator/SKILL.md` 16 · 17 · 31행의 `` `find` `` 를 셸 명령으로 셌다. 직접 읽으니 셋 다 **`find` 스킬의 이름**이다("`research` (먼저 `find`)" · "`find` 로 간다"). 실측은 0 이고, 판정 뒤 도구가 낱말 하나짜리 백틱을 이름으로 보게 고쳤다. 칸도 예측도 안 고쳤다.

### 3.2 prodev 가 지시 밖에서 한 판단 셋 — 전부 기록에 남는다

| 판단 | 어디 | meta 가 본 것 |
|---|---|---|
| `Grep` · `Glob` 을 allow 에 **이름으로** 넣음 (셸 grep·find 를 빼면 내장 쪽이 열려 있어야 찾기가 승인 창으로 안 샌다) | `settings.template.json` · ADR-033 | 맞는 판단. 에이전트의 `tools:` 선언은 고르는 자리이지 허락하는 자리가 아니다. **다만 실제로 승인 창이 안 뜨는지는 봇 세션에서만 안다** — 관문 B 의 대본이 그 자리다 (들이기 · 찾기 걸음에서 승인 창 수를 기록만 한다) |
| 뺄 열여섯에 다섯을 더 뺌 (sha256sum · cp · chmod · basename · dirname) | 〃 | A7 이 0 이므로 봇이 부르는 자리는 없다. `intake-copy.js` 가 node 로 한다 |
| `test/server/setup.test.js` 한 건을 새 목록에 맞춰 고침 · `setup.js` 를 두 함수로 가름 | PR #9 | 시험이 **실제로 쓰인 settings.json** 을 보게 됐다 — 틀만 보면 치환이 빠져도 안 걸린다는 까닭이 맞다 |
