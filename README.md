# prodev — 과제 비서

## 한 줄로 말하면

공정개발 과제를 하는 사람들이 쓰는 **사내 채팅방에 비서 한 명을 앉혀 놓은 것**이다.
과제를 시작하는 날부터 끝내는 날까지 — 실험 자료 정리 · 조사 · 일정 · 특허 · 논문 · 보고 —
그 비서 하나가 전부 이어 준다.

## 그림으로 말하면

```mermaid
flowchart LR
    P["사람들<br/>PL · 과제원"] -->|"채팅으로 말한다"| B["비서 하나"]
    B -->|"답한다"| P
    B -->|"읽고 쓴다"| F["과제 폴더<br/>파일로 남는 기억"]
    F -->|"되살아난다"| B
```

비서는 사람의 말을 듣고, 파일에 적고, 그 파일을 다시 읽어서 기억한다.
**세션이 꺼져도 파일은 남는다.** 그래서 다음 날 켜면 어제 하던 이야기를 이어서 한다.

---

## 이 비서는 어떤 비서인가

신입이 아니라, 과제의 모든 대화 · 파일 · 결정을 다 외우고 있는 비서다.
"그거 얼마였지?" 하고 물으면 이렇게 답한다:

> 92.53% 입니다. (`cards/E-0007.md` · 9월 3일 김과제 님이 올린 `yield.csv` 의 수율_후 열)

이 비서의 성격은 세 가지다.

| 성격 | 무슨 뜻인가 | 왜 이렇게 만들었나 |
|---|---|---|
| **혼자다** | 봇이 하나뿐이다. 봇끼리 대화하지 않는다 | 앞선 실험에서 봇 다섯이 같은 품질에 **15~19배** 비용을 물었다 |
| **스스로 일을 만들지 않는다** | 사람이 시켜야 움직인다. 조사도 허락을 받고 시작한다 | 시키지 않은 일이 쌓이면 사람이 통제를 잃는다 |
| **모르면 모른다고 한다** | 출처 없는 사실은 말하지 않는다 | 사실이 여러 단계를 거치면 조용히 틀어진다 |

> 앞선 실험(`../crew/`)이 남긴 교훈 셋이 이 프로젝트의 뼈대다:
> **검토는 다른 사람이 해야 값을 하고 · 세는 일은 기계가 해야 하고 · 예측을 먼저 적어야 판정이 선다.**

## 먼저 낱말 열일곱

이 문서와 코드에 계속 나오는 말이다. 여기만 알면 나머지는 읽힌다.

| 낱말 | 쉬운 뜻 |
|---|---|
| **방** | 채팅방. 과제 하나에 방이 딱 **둘**이다 |
| **본방** | `prodev-<과제이름>`. 말은 여기서 다 한다 |
| **files 방** | `prodev-<과제이름>/files`. 파일을 올리는 방 |
| **봉투** | 글 앞에 붙는 `@TO(누구)` · `@CC(누구)` 표시. 누구에게 하는 말인지 알려 준다 |
| **들이기** | 올라온 파일을 읽어서 정리해 넣는 일 (intake) |
| **카드** | 실험 한 건 · 조사 한 건 · 결정 한 건을 적은 파일 하나. `E-0007` 처럼 번호가 붙는다 |
| **확정** | 사람이 "맞다"고 말해 주는 것. 확정 전까지 카드는 임시다 |
| **위키** | 주제별 요약 페이지. 카드들을 모아 "지금 아는 것"을 적는다 |
| **색인** | 무엇이 어디 있는지 적은 목록. 사람이 아니라 **기계가 만든다** |
| **실 (threads)** | 하던 이야기를 적어 둔 메모. 세션이 꺼져도 여기서 이어 간다 |
| **스킬** | 비서가 아는 일하는 방법. "일정 다루는 법", "논문 쓰는 법" 같은 설명서 |
| **도우미** | 오래 걸리는 일을 대신하는 보조 세션 (서브에이전트) |
| **훅 · 관문** | 비서가 말하기 직전에 검사하는 **기계**. 조건이 안 맞으면 말을 못 하게 막는다 |
| **굳는 길** | 사람이 "앞으로 이렇게 해" 라고 한 것을 비서가 **파일로 남기는 일**. 이 비서가 쓸수록 맞아 가는 까닭이다 |
| **`house.md`** | 이 과제에서 이 사람과 일하는 **방식**을 적은 파일. 켤 때마다 실린다. **50줄이 상한**이다 |
| **여섯 칸** | 분석 한 건을 적는 규격. 물음 · 가정 · 코드 · 숫자 · 해석 · **뒤집을 수 있는 것** |
| **회고** | 일지를 되읽어 "이거 반복되네요, 굳힐까요?" 하고 **먼저 묻는 일** (retro) |

## 무엇을 할 수 있나 — 여덟 가지, 그리고 v3 이 더한 셋

```mermaid
flowchart TB
    S1["S1 · 과제 발의<br/>헌장과 일정 뼈대를 만든다"]
    S2["S2 · 실험 자료 들이기<br/>파일을 읽고 카드로 만든다"]
    S3["S3 · 리서치<br/>바깥 자료를 조사한다"]
    S4["S4 · 일정<br/>등록 · 변경 · 지금 할 일"]
    S5["S5 · 특허<br/>선행 조사와 전략"]
    S6["S6 · 논문<br/>와꾸와 절 초안"]
    S7["S7 · 보고<br/>주간 · 월간 · 경영진"]
    S0["S0 · 언제나<br/>물으면 출처와 함께 답하고<br/>껐다 켜도 이어 간다"]

    subgraph V3["v3 이 더한 셋 — 쓸수록 맞아 간다"]
        VA["분석<br/>갈리는지 재고 DOE 를 짠다<br/>여섯 칸 + 카드 하나"]
        VH["굳는 길<br/>'앞으로' 라 하면 파일로 남긴다<br/>규칙 · 양식 · 방법"]
        VR["회고<br/>일지를 되읽어 먼저 묻는다<br/>근거 없으면 안 쓴다"]
    end

    S1 --> S2
    S2 --> S3
    S2 --> S4
    S3 --> S5
    S3 --> S6
    S2 --> S6
    S4 --> S7
    S2 --> S7
    S0 -.->|"늘 깔려 있다"| S2
    S2 --> VA
    VA --> S7
    VA -.->|"같은 방법을 또 쓰면"| VH
    S7 -.->|"양식을 가르치면"| VH
    VR -.->|"굳힐 것을 찾아낸다"| VH
```

| # | 무엇 | 비서가 하는 일 | **사람이 정하는 곳** |
|---|---|---|---|
| S1 | 과제 발의 | 목적 · 목표 · 일정 · 인원 · 예산 · 판정 기준을 **하나씩** 묻고 헌장 초안을 낸다 | 헌장 결재 (PL) |
| S2 | 자료 들이기 | 파일을 읽고 "이렇게 읽었습니다" 표를 보인 뒤 모르는 것을 **셋 이하로** 묻는다 | 과제원의 "확정" |
| S3 | 리서치 | 우리 자료를 먼저 뒤지고, 없으면 물음을 적어 허락을 구한 뒤 조사한다 | 조사 시작 허락 |
| S4 | 일정 | 등록 · 변경 · "지금 뭐 해야 하지" 브리핑 | 없음 |
| S5 | 특허 | 청구 후보를 뽑고 선행을 조사해 전략을 **셋 이하로** 낸다 | 조사 범위 · 청구 방향 |
| S6 | 논문 | 와꾸(목차)를 짜고 절마다 초안을 쓰며 문장에 근거 카드를 붙인다 | 와꾸 결재 · 절마다 통과 |
| S7 | 보고 | 사람이 준 양식의 칸을 채운다. **숫자마다 출처 카드**를 단다 | 방향 선택 · 발송 결재 (PL) |
| S0 | 언제나 | 껐다 켜도 · 대화가 압축돼도 파일에서 되살아나 "이어서 합니다" 한 줄로 잇는다 | 없음 |

**v3 이 더한 셋**은 위의 여덟과 성격이 다르다. 여덟은 **과제를 잇는** 일이고, 셋은 **쓸수록 맞아 가게 하는** 일이다.
그래서 시나리오 번호(S1~S7)를 새로 붙이지 않고 따로 적는다. 요구 번호는 `design/v3/PRD.md` 의 **F14~F18 · N8 · N9** 다.

| 무엇 | 비서가 하는 일 | **사람이 정하는 곳** |
|---|---|---|
| **분석 · DOE** | 이미 들인 자료로 갈리는지 재고, 무엇을 얼마나 더 모을지 짠다. 한 건을 `analysis/<날짜>-<이름>/` 에 **돌린 코드 · 여섯 칸 대본 · 카드 하나**로 남긴다 | **모형 고르기** (후보 두셋 중 하나). 코드 짜는 데는 관문이 없다 |
| **굳는 길** | 사람이 **"앞으로"** 라고 한 것을 파일로 남긴다 — 규칙은 `house.md` · 양식은 `templates/` · 방법은 `analysis/methods/` | **범위** (회의록만인가, 문서 전부인가). 승인이 아니라 경계를 맞추는 물음이다 |
| **회고** | 일지와 `find.log` 를 되읽어 되풀이된 것 · 막힌 것 · 굳힐 후보 · 필요해 보이는 장치를 낸다. **항목마다 근거를 단다** | 굳힐지 말지 · 장치를 만들지 말지. 비서는 **제안까지만** 한다 |

**"이번에는" 은 굳지 않는다.** 한 번의 예외가 영구 규칙이 되면 규칙끼리 충돌하고 비서가 느려진다.
사람이 "앞으로" 를 **명시했을 때만** 굳는다. 이 갈림을 실제로 재 본 기록이 아래 "실제로 이렇게 돌았다" 절에 있다.

## 전체 구조 — 무엇이 어디에 있나

```mermaid
flowchart TB
    subgraph HUMAN["① 사람 · 사내망 브라우저"]
        PL["PL<br/>발의 · 결재 · 방향"]
        MEM["과제원<br/>자료 · 문답 · 물음"]
    end

    subgraph SERVER["② minidiscord 채팅 서버 · PL PC"]
        ROOM1["본방<br/>prodev-과제"]
        ROOM2["files 방<br/>prodev-과제/files"]
        DB[("SQLite<br/>모든 글 · 첨부")]
    end

    subgraph BOT["③ 비서 세션 · Claude Code 하나"]
        RULE["CLAUDE.md<br/>비서 지침 열한 줄"]
        SKILL["스킬 15<br/>일하는 방법"]
        AGENT["도우미 6<br/>오래 걸리는 일"]
        HOOK["훅 3<br/>지켜보는 기계"]
        SCRIPT["스크립트 10<br/>세고 찾고 옮기는 손"]
    end

    subgraph REPO["④ 과제 저장소 · git 폴더 하나"]
        CH["charter.md · 헌장"]
        SCH["schedule.md · 일정"]
        HOUSE["house.md · 이 사람과 일하는 방식<br/>규칙이 굳는 자리 · 50줄"]
        INBOX["inbox/ · 원본 그대로"]
        CARD["cards/ · 카드"]
        WIKI["wiki/ · 주제 페이지"]
        ANA["analysis/ · 분석 한 건<br/>run.py · 여섯 칸 run.md"]
        TPL["templates/ · 가르친 양식"]
        JNL["journal/ · 하루 일지"]
        IDX["index.md · 색인"]
    end

    KNOW["knowledge/<br/>회사 지식"]

    HUMAN -->|"HTTP · 브라우저"| SERVER
    SERVER -->|"WebSocket<br/>글이 오면 깨운다"| BOT
    BOT -->|"reply · 파일 첨부"| SERVER
    DB -.->|"읽기 전용으로 직접 본다"| SCRIPT
    BOT -->|"읽고 쓰고 커밋한다"| REPO
    REPO -->|"켤 때 여기서 기억을 되찾는다"| BOT
    REPO -->|"과제가 끝나고 PL 이 결재하면"| KNOW
```

읽는 법은 이렇다.
사람은 **브라우저**로 채팅방에 글을 쓴다. 서버가 그 글을 비서에게 알린다.
비서는 스킬을 보고 어떻게 할지 정하고, **과제 폴더**에 파일로 적는다.
비서의 기억은 머릿속이 아니라 **그 폴더**에 있다. 그래서 세션이 죽어도 잊지 않는다.

저장소 안의 열은 성격이 둘로 갈린다. 헌장 · 일정 · 카드 · 위키 · 일지는 **이 과제의 사실**이고,
`house.md` · `templates/` · `analysis/methods/` 는 **이 사람과 일하는 방식**이다.
앞의 것은 비서가 쌓고, **뒤의 것은 사람이 "앞으로" 라고 말했을 때만 는다.**
경계는 "되돌릴 수 있는가" 다 — 카드는 틀려도 다음 카드가 덮지만, 규칙은 그 뒤 모든 답변에 영구히 작용한다.

### 방은 왜 둘뿐인가

사람이 외울 규칙이 한 줄이면 된다:

> **말은 아무 데서나, 파일은 files 에.**

비서는 **어느 방에서든 답한다.** "그건 저쪽 방에서 물어보세요"라고 하지 않는다.
딱 하나의 예외가 있다. 본방에 파일이 올라오면
"파일은 files 방에 올려주시면 거기서 읽고 여쭙겠습니다" 한 줄만 하고 **읽기 시작하지 않는다.**

## 비서는 어떻게 기억하나 — 기억의 다섯 층

```mermaid
flowchart TB
    L0["0층 · 원본<br/>inbox/ — 올라온 파일 그대로. 절대 고치지 않는다"]
    L1["1층 · 카드<br/>cards/E-0007.md — 실험 한 건의 조건과 결과"]
    L2["2층 · 위키<br/>wiki/수율.md — 주제별로 지금 아는 것"]
    LI["색인<br/>index.md · index.json — 기계가 만든 목록"]
    LC["대화<br/>채팅 서버 DB — 오간 말 전부"]

    L0 -->|"읽고 문답해서"| L1
    L1 -->|"확정되면 바로"| L2
    L1 --> LI
    L2 --> LI
    LC -.->|"근거로 인용된다"| L1
```

| 층 | 무엇이 들어 있나 | 규칙 |
|---|---|---|
| **0층 원본** | 올라온 파일 그대로 | **절대 고치지 않는다.** 같은 이름이 또 오면 `.v2` 로 옆에 둔다 |
| **1층 카드** | 실험 한 건 = 카드 한 장 | 사람이 "확정"이라고 해야 정식(valid)이 된다 |
| **2층 위키** | 주제별 "지금 아는 것" | **문장마다 카드 번호를 단다.** 번호 없는 문장은 못 쓴다 |
| **색인** | 무엇이 어디 있는지 | 손으로 쓰지 않는다. `index.js` 가 만든다 |
| **대화** | 오간 말 전부 | 지우지 않는다. 언제든 검색된다 |

**아무것도 지우지 않는다.** 틀린 카드는 삭제가 아니라 `void`(무효) 로 바꾸고, 어느 카드가 대신하는지 적어 둔다.

### 기억의 층과 찾기의 층은 다른 것이다

숫자가 달라서 헷갈리기 쉬운데, **둘은 다른 이야기다.**

| | 무엇을 세나 | 몇 개인가 |
|---|---|---|
| **기억의 층** | 비서가 아는 것을 **어디에 쌓아 두나** | 다섯 (원본 · 카드 · 위키 · 색인 · 대화) |
| **찾기의 층** | 물음이 왔을 때 **어느 순서로 뒤지나** | 여섯 (아래 워크플로우 ③) |

가장 눈에 띄는 차이는 **헌장과 일정**이다. 둘은 기억의 층 표에 없다 — 자료에서 지어 올린 것이 아니라 사람이 정해서 적어 둔 **과제 문서**이기 때문이다. 그런데 **찾을 때는 같이 뒤진다** (찾기 4층). "예산이 얼마였지" 는 아주 흔한 물음인데, 한동안 비서가 그 두 파일을 안 보고 있어서 답하지 못했다.

## 카드 한 장에는 무엇이 들어가나

카드는 이 비서의 심장이다. 물음의 대부분이 카드에서 풀리고, 안 풀리면 사람이 원본 파일을 열어야 한다. **사람이 원본을 열게 되면 그 카드는 일을 안 한 것이다.**

무엇을 어느 깊이로 담을지는 **두 번 고쳐졌다.** 두 번 다 "카드가 못 답한 물음"이 가르쳐 줬다.

| 판 | 카드가 담은 것 | 그래서 못 답한 물음 |
|---|---|---|
| 1차 | 규격을 **벗어난 것만** | "규격 **이내**인 건 뭐지" |
| 2차 | 갈래별 **수** — "여덟 중 여섯이 이내" | "그 여섯이 **어느 것**이냐" |
| 3차 (지금) | 쫓는 갈래는 **개체까지** | — |

두 번째 고침이 핵심을 짚는다. **요약 표는 수를 주지 개체를 주지 않는다.** "여섯이 이내"까지는 답해도 "그 여섯이 무엇이냐"에는 답하지 못한다.

### 지금 규칙 — 갈래마다 깊이가 다르다

```mermaid
flowchart TB
    G["자료의 한 갈래<br/>공급사별 · 장비별 · 부품별"] --> Q1{"과제가 쫓는 갈래인가?<br/>카드의 꼬리표와 헌장의<br/>목적·목표에 함께 나오나"}
    Q1 -->|"예"| D1["개체별 표<br/>일련번호 · 잰 값 · 판정 · 어디 갔나"]
    Q1 -->|"아니오"| Q2{"규격을 벗어난<br/>개체인가?"}
    Q2 -->|"예"| D1
    Q2 -->|"아니오"| D2["갈래별 요약 표<br/>전수 · 이내 · 초과"]
    D1 --> Q3{"개체가 스물을 넘나?"}
    Q3 -->|"예"| D3["규격 밖은 전부<br/>+ 경계에 가까운 것 다섯<br/>+ 나머지는 수와 범위로"]
    Q3 -->|"아니오"| OK["개체를 그대로 싣는다"]
    D2 --> SRC["원본 실마리 한 줄<br/>전체 표는 어느 파일 몇 행인지"]
```

**"과제가 쫓는 갈래"는 비서가 스스로 안다.** 카드의 꼬리표(`tags`)와 헌장의 `## 목적` · `## 목표` 에 **함께** 나오는 것이 그것이다. 사람에게 새로 묻지 않고 파일에서 알 수 있어야 걸음이 늘지 않는다. 그래도 헷갈리면 묻되, **들이기 문답의 물음 셋 안에서** 묻는다 — 물음을 넷째로 늘려 풀면 성적은 올라도 사람이 더 일한 것이다.

**상한이 규칙의 절반이다.** "다 실으면 안전하다"는 틀렸다. 개체가 스물을 넘으면 카드가 못 읽을 만큼 길어지고, **못 읽는 카드는 안 실은 카드와 같다.** 그래서 규격 밖은 전부 · 경계에 가까운 것 다섯 · 나머지는 수와 범위로 줄인다. 한쪽은 너무 적게, 다른 쪽은 너무 많이 — 규칙은 양쪽을 다 막아야 한다.

### 왜 개체까지 내리나 — 실제로 이렇게 드러났다

검수에서 나온 두 자리다. 둘 다 **요약 표만 있었으면 화면에 안 보였을** 것이다.

**하나 — 수는 그대로인데 명단이 바뀐다.**

들이기 문답에서 사람 답 둘이 서로 반대로 움직였다. 중복 판정이 규격 초과를 하나 **줄이고**, 단위 환산이 하나 **늘렸다**. 초과는 **5개에서 5개로 그대로**였다. 그런데 명단에서 하나가 빠지고 하나가 들어왔다.

새로 들어온 것은 **아직 안 쓴 재고**의 샤워헤드였다 — 지금 걸러 낼 수 있는, 조치가 가능한 사실이다. 수만 보면 "변화 없음"이다.

**둘 — 수로는 같은데 분포가 다르다.**

규격 이내 여섯이 공급사별로 셋씩이었다. 요약 표로는 똑같아 보인다. 개체 값을 늘어놓자 갈렸다.

| 공급사 | 잰 값 | 상한 3.0 까지 |
|---|---|---|
| 한쪽 | 2.6 · 2.7 · 2.9 | **붙어 있다** |
| 다른 쪽 | 2.1 · 2.3 · 2.5 | 여유가 있다 |

**상한에 붙어 있다는 것은 다음 로트에서 넘어갈 수 있다는 뜻**이라, 공정에서는 "둘 다 합격"과 전혀 다른 이야기다.

## 워크플로우 ① — 말 한마디가 들어오면

비서는 말을 듣자마자 **분기표**부터 본다. 위에서부터 읽어 내려가다 처음 걸리는 줄에서 멈춘다.

```mermaid
flowchart TB
    IN["@TO 로 말이 왔다"] --> Q1{"본방인데<br/>파일이 붙었나?"}
    Q1 -->|"예"| A1["안내 한 줄만 한다<br/>읽기 시작하지 않는다"]
    Q1 -->|"아니오"| Q2{"files 방 + 파일 +<br/>시키는 말인가?<br/>채워 줘 · 써 줘"}
    Q2 -->|"예"| A2["report · paper · patent"]
    Q2 -->|"아니오"| Q3{"files 방에<br/>실험 자료가 왔나?"}
    Q3 -->|"예"| A3["intake · 들이기"]
    Q3 -->|"아니오"| Q4{"시키는 말인가?<br/>특허 · 논문 · 보고"}
    Q4 -->|"예"| A4["patent · paper · report"]
    Q4 -->|"아니오"| Q5{"바깥을 알아봐<br/>달라는 말인가?"}
    Q5 -->|"예"| A5["research · 리서치"]
    Q5 -->|"아니오"| Q6{"물음인가?<br/>물음표 · 어디 · 언제 · 얼마"}
    Q6 -->|"예"| A6["find · 찾기"]
    Q6 -->|"아니오"| Q7{"그 밖의 낱말"}
    Q7 -->|"발의 · 헌장"| A7["charter"]
    Q7 -->|"일지 · 하루 마감"| A8["journal"]
    Q7 -->|"오늘 · 현황"| A9["brief"]
    Q7 -->|"일정 · 기한 · 밀렸다"| A10["schedule"]
    Q7 -->|"마감 · 보관"| A11["close"]
    Q7 -->|"아무것도 안 걸림"| A12["무엇을 원하는지 되묻는다<br/>스스로 일을 만들지 않는다"]
```

여기서 중요한 순서가 둘 있다.

- **시키는 말이 물음보다 앞이다.** 다만 *시키는 말이 있을 때만*이다. "이 양식에 채워 줘"는 보고지만, "그 숫자 어디서 나왔지"는 찾기다.
- **일지가 브리핑보다 앞이다.** "오늘"이라는 낱말이 둘 다에 들어가기 때문이다.

## 워크플로우 ② — 실험 자료 들이기 (가장 자주 도는 흐름)

```mermaid
sequenceDiagram
    participant M as 과제원
    participant R as files 방
    participant B as 비서
    participant D as 도우미<br/>data-reader
    participant P as 과제 폴더

    M->>R: yield.csv + photo.jpg 를 올린다
    R->>B: 파일이 왔다
    B->>P: 원본을 inbox/ 로 복사<br/>읽기 전용 · SHA-256 기록
    B->>B: peek.js — 행 수 · 열 이름 · 앞 5행
    opt 파일이 클 때
        B->>D: 전수로 읽어 달라 (백그라운드)
        D->>P: reading.md — 열마다 범위와 이상한 자리
        D-->>B: 20줄 요약
    end
    B->>R: "이렇게 읽었습니다" 표 + 이상한 자리 + 질문 3개 이하<br/>그림이 나으면 그래프를 그려 첨부
    M->>R: 답하고 틀린 곳을 고쳐 준다
    B->>P: threads/ 에 남은 질문을 적어 둔다
    M->>R: "확정"
    Note over B: 여기서 기계가 검사한다 (아래 ⑤)
    B->>P: 카드를 valid 로 · 위키 갱신 · 색인 재생성 · git 커밋
    B->>R: "[카드] E-0007 · CH-3B 수율 · cards/E-0007.md"
```

기억할 점 넷:

1. **파일 여럿이 한 실험이면 카드도 하나다.** 파일 수가 아니라 실험 수로 센다.
2. **한 번에 세 개까지만 묻는다.** 질문 폭격을 하지 않는다.
3. **그림으로 물을 수 있으면 그림으로 묻는다.** 사진을 잘라 붙이거나 csv 를 그래프로 그려 올린다.
4. **사람이 "확정"이라고 하기 전에는 카드 공지가 나가지 않는다.** 이건 부탁이 아니라 기계가 막는다.

## 워크플로우 ③ — 물어보면 어떻게 찾나

비서는 **아는 척하지 않는다.** 답이 떠올라도 먼저 `find.js` 를 돌린다.
찾는 순서가 코드에 못 박혀 있다.

```mermaid
flowchart TB
    Q["'그거 수율 얼마였지?'"] --> L1["① 색인<br/>제목 · 별명 · 꼬리표"]
    L1 -->|"없으면"| L2["② 카드 본문"]
    L2 -->|"없으면"| L3["③ 위키 페이지"]
    L3 -->|"없으면"| L4["④ 과제 문서<br/>헌장의 절 · 일정의 행"]
    L4 -->|"없으면"| L5["⑤ 원본 옆 설명서<br/>inbox/files.md"]
    L5 -->|"없으면"| L6["⑥ 대화 전체 검색"]
    L1 & L2 & L3 & L4 & L5 & L6 --> ANS["출처를 붙여 답한다<br/>파일 경로 또는 글 번호"]
    L6 -->|"끝내 없으면"| NO["'못 찾았습니다' 라고 말한다"]
```

④ 과제 문서는 헌장(`charter.md`)과 일정(`schedule.md`)이다. 예산이나 중간 점검 날짜처럼 사람이 정해서 적어 둔 것이 여기 있다.
**파일을 통째로 뒤지지 않고 절과 행으로 나눠 뒤진다** — 헌장 한 파일에 목적도 예산도 다 들어 있어서, 통째로 맞대면 서로 다른 절의 낱말이 함께 걸려 엉뚱한 답이 나오기 때문이다.

한국어라서 따로 손본 것들이 있다.
**조사를 뗀다**(수율을 → 수율), 띄어쓰기와 하이픈 차이를 무시하고, 무효가 된 카드는 그것을 대신하는 새 카드로 따라간다.
어느 층에서 답이 나왔는지는 `find.log` 에 남는다 — 어느 층이 실제로 읽히는지 재기 위해서다. 층 **번호와 이름을 함께** 적는다. 층이 하나 늘면 번호가 밀려서, 번호만 남긴 옛 기록과 새 기록이 같은 숫자로 다른 층을 가리키게 되기 때문이다.

### 별칭 — 같은 물건을 사람마다 다르게 부른다

1층(색인)이 보는 것은 셋뿐이다. **제목 · 별칭 · 꼬리표.** 그래서 사람이 쓰는 말과 카드 제목이 다르면 **별칭이 1층이 걸리는 유일한 길**이다. 별칭이 비어 있으면 그 카드는 제목을 그대로 말해야만 나온다.

카드를 만들 때 다섯 갈래로 채운다.

| 갈래 | 보기 |
|---|---|
| 정식 부품명 | `SH2200-B-0412` |
| 현장에서 부르는 말 | `샤워헤드` |
| 영문 · 자료의 열 이름 | `showerhead-swap` · `hole_dia_sd` |
| 줄임말 | `SH2200` |
| 흔한 오타 | `샤워해드` |

**아직 못 고친 자리가 여기다.** 검수에서 사람이 `홀 직경 편차` · `규격 넘은` 이라고 물었는데 카드에는 `구멍 지름 산포` · `규격 초과` 로만 적혀 있어 검색이 두 번 빗나갔다. 답은 두 번 다 카드 안에 있었고 비서가 낱말을 바꿔 가며 찾아내 답했지만, 찾는 김에 별칭을 그 자리에서 보태야 했다.

까닭은 이렇다. 지금 별칭은 **자료에 나오는 말**과 **카드가 쓰는 말**로 채워진다. 그런데 사람은 둘 다 아닌 **자기 말**로 묻는다. 들이기 문답에서 사람이 실제로 쓴 낱말을 별칭으로 거두는 것이 가장 싼 길로 보이는데, 아직 규칙이 되지 않았다. **다음 판의 후보다.**

### 재 본 값

세 판에 걸쳐 검수에서 잰 것이다. 물음 열여섯 개를 같은 것으로 놓고 세 번 쟀다.

| 무엇 | 값 |
|---|---|
| **찾기 성공률** | 62.5% (10/16) → 87.5% (14/16) → **100% (16/16)** |
| 검색 한 번 | 약 **23 밀리초** · 결과 **87~172 바이트** |
| 물음 하나당 검색 횟수 | 1.7회 → 2.6회 (별칭이 빗나가 다시 돌린 탓, 위 참고) |
| 카드 한 장 | 약 **10 KB** (171줄) |
| 그 카드가 나온 원본 csv | **2.4 KB** |

**마지막 두 줄을 함께 읽어야 한다. 이 규모에서는 카드가 원본보다 네 배 크다.**

그러니 카드는 **토큰을 아끼려고 만드는 것이 아니다.** 사람이 확정한 사실과, 그 사실이 어디서 왔는지와, 무엇을 아직 모르는지를 담는 장치다. 원본은 무엇이 맞는지 말해 주지 않는다 — 중복인지 별개인지, 단위가 무엇인지, 이 값이 규격 안인지는 사람이 정해 준 것이고 그것이 카드에 있다.

자료가 커지면(수천 행) 그때는 토큰도 아낀다. 하지만 그것은 덤이지 목적이 아니다.

## 워크플로우 ④ — 리서치 · 특허 · 논문 · 보고 (오래 걸리는 일)

네 가지가 같은 모양으로 돈다. **사람이 두 번 정하고, 검토가 한 번 끼어든다.**

```mermaid
flowchart TB
    REQ["'왜 그런지 알아봐 줘'"] --> FIND["먼저 우리 자료를 뒤진다<br/>find.js"]
    FIND -->|"이미 있으면"| HAVE["있는 것으로 답하고 끝"]
    FIND -->|"없으면"| ASK["물음을 문장으로 적어 보인다<br/>'이걸 조사할까요?'"]
    ASK --> GATE1{"사람의 허락"}
    GATE1 -->|"아니오"| STOP["하지 않는다"]
    GATE1 -->|"예"| BG["도우미를 백그라운드로 띄우고<br/>'시작했습니다' 로 턴을 끝낸다"]
    BG --> WORK["researcher · patent-analyst<br/>paper-writer · report-writer"]
    WORK --> FILE["결과를 파일로 쓴다"]
    FILE --> REV["reviewer — 만든 과정을 모르는 채<br/>숫자를 다시 세고 출처를 대조한다"]
    REV --> VERDICT["통과 · 불통과 · 검증 불가<br/>판정도 파일로 남는다"]
    VERDICT --> BRIEF["다음 턴에 방에 10줄 브리핑<br/>파일은 첨부하고 경로는 옆에"]
    BRIEF --> GATE2{"사람의 결재"}
    GATE2 -->|"통과"| DONE["카드로 굳히거나 발송"]
    GATE2 -->|"고쳐라"| WORK
```

여기 핵심이 둘이다.

- **검토자는 만든 사람의 생각을 물려받지 않는다.** 결과물만 보고 다시 센다. 같은 문맥에서 하는 검토는 값을 하지 않는다는 것이 앞선 실험의 결론이었다.
- **3분 넘는 일은 백그라운드로 넘긴다.** 그래서 조사가 도는 동안에도 다른 사람의 물음에 1분 안에 답할 수 있다.

## 워크플로우 ⑤ — 기계가 막는 자리 (훅)

비서가 방에 글을 보내려고 하면, 보내기 **직전에** 기계가 다섯 가지를 본다.
앞에서 걸리면 뒤는 보지 않고, 걸리면 **이유 한 줄**과 함께 되돌려 보낸다. 비서는 그걸 읽고 고쳐서 다시 시도한다.

```mermaid
flowchart TB
    TRY["비서가 방에 글을 보내려 한다"] --> C1{"어느 방에 보낼지<br/>적혀 있나?"}
    C1 -->|"없다"| X1["막는다"]
    C1 -->|"있다"| C2{"900자 · 10줄<br/>안에 드나?"}
    C2 -->|"넘는다"| X2["막는다<br/>파일로 옮겨 첨부하라"]
    C2 -->|"든다"| C3{"첫 줄이<br/>[카드] 로 시작하나?"}
    C3 -->|"예"| C3a{"확정 다섯 조건을<br/>DB 에서 확인"}
    C3a -->|"하나라도 아니다"| X3["막는다"]
    C3 -->|"아니오"| C4{"첫 줄이<br/>[발송] 로 시작하나?"}
    C3a -->|"전부 맞다"| C4
    C4 -->|"예"| C4a{"결재한 사람이<br/>헌장의 PL 인가?"}
    C4a -->|"아니다"| X4["막는다"]
    C4 -->|"아니오"| C5{"색인에 깨진<br/>머리말이 있나?"}
    C4a -->|"맞다"| C5
    C5 -->|"있다"| X5["막는다"]
    C5 -->|"없다"| OK["보낸다"]
```

**확정 다섯 조건**은 이렇다. "확정"이라는 말이 진짜인지를 채팅 DB 에서 직접 확인한다.

1. 봇이 아니라 **사람**이 쓴 글일 것
2. 그 과제의 **files 방**에서 온 글일 것
3. 봉투(`@TO(…)`)를 벗긴 본문이 `확정` · `맞다` · `맞습니다` · `그대로` · `OK` 로 시작할 것
4. 파일이 올라온 글들보다 **뒤**에 있고, 바로 앞 봇 글에 같은 카드 번호가 있을 것
5. 카드 상태가 `valid` 일 것

> **방아쇠는 방이 아니라 표식이다.**
> 첫 줄이 `[카드]` 나 `[발송]` 로 시작할 때만 관문이 선다.
> 그래서 비서가 평소 답에서 카드 번호를 입에 올리는 것은 막히지 않는다.

## 워크플로우 ⑥ — 껐다 켜도 이어지는 법

비서 세션은 **하루 종일 켜져 있지 않다.** 그런데도 사람은 끊김을 못 느껴야 한다.

```mermaid
stateDiagram-v2
    state "켜짐" as ON
    state "기억 되찾기" as LOAD
    state "놓친 말 따라잡기" as CATCH
    state "평소 일함" as WORK
    state "압축" as COMPACT
    state "하루 마감" as CLOSE
    state "꺼짐" as OFF

    ON --> LOAD: session-start 훅이 파일을 순서대로 읽어 준다
    LOAD --> CATCH: 꺼진 사이 놓친 @TO 를 순서대로 처리한다
    CATCH --> WORK: 방에 "이어서 합니다" 한 줄
    WORK --> WORK: 평소 대화
    WORK --> COMPACT: 대화가 너무 길어졌다
    COMPACT --> LOAD: pre-compact 훅이 인수인계서를 쓴다
```

켤 때 읽는 순서가 정해져 있다:
**인수인계서 → 헌장 → 일정 → 열린 실 → 하던 이야기들 → 어제 일지 → 색인 앞 30줄.**

그리고 켜지거나 압축된 뒤 **첫 마디는 언제나 "이어서 합니다" 한 줄**이다.
어느 방에서 무슨 이야기를 하던 중이었는지를 먼저 짚고 시작한다.

## 워크플로우 ⑦ — 쓸수록 맞아 가는 법 (굳는 길)

같은 말을 두 번 하지 않아도 되게 하는 것이 이 비서의 목표다. 그 일이 실제로 이렇게 흘러간다.

1. 사람이 `보고 자료 만들어 줘` 한다. 비서가 만든다 — 회사 양식도 아니고 회사 문체도 아니다
2. 사람이 회사 ppt 를 주고 `이 양식과 문체로 다시` 한다. 몇 턴 돌아 맞는 것이 나온다
3. 사람이 **`앞으로 회의 문서는 이 양식대로 해`** 한다
4. 비서가 그것을 **파일로 남긴다**

**3번과 4번이 진화다.** 그리고 이것은 분석 방법이 반복되어 굳는 것과 똑같은 일이다 — 종류만 다르고 길은 하나다.

들어오는 입구는 둘인데 **나가는 문은 하나**다.

```mermaid
flowchart TB
    SAY["지시형 — 사람: '앞으로 이렇게 해'"] --> SCOPE["범위를 한 줄 되묻는다<br/>'회의록만인가요, 문서 전부인가요'"]
    ONCE["사람: '이번에는 이렇게'"] --> NOPE["굳히지 않는다<br/>한 번의 예외는 예외로 둔다"]
    NOTICE["관찰형 — 같은 지적이 또 나왔다"] --> JNL["일지의 '되풀이된 말'<br/>한 줄씩 쌓는다 · 세지 않는다"]
    JNL --> RETRO["retro — 사람이 '돌아봐' 할 때 읽는다"]
    RETRO --> PROP["제안 — 원본 경로 · 들어갈 문장 · 까닭"]
    PROP --> ASK{"사람이 '앞으로' 라 하나"}
    ASK -->|"아니오"| DROP["굳히지 않는다"]
    ASK -->|"예"| SCOPE
    SCOPE --> WHERE{"무엇이 굳나"}
    WHERE -->|"규칙"| H["house.md · 상한 50줄"]
    WHERE -->|"양식"| T["templates/"]
    WHERE -->|"방법"| M["analysis/methods/"]
    H --> HEAD["머리에 셋<br/>언제부터 · 누가 · 무엇을 보고"]
    T --> HEAD
    M --> HEAD
```

**지시형과 관찰형은 속도가 다르다.** 지시형은 즉시 굳고, 관찰형은 쌓여야 신호가 난다.
위험도 다르다 — 지시형의 진짜 위험은 **범위**이고, 관찰형의 진짜 위험은 **검증 안 된 것이 굳는 것**이다.
그래서 지시형에는 되묻기가, 관찰형에는 사람의 "앞으로" 가 문 앞에 있다.

### 무엇이 어디에 굳나

| 굳는 것 | 사는 자리 | 언제 읽히나 |
|---|---|---|
| **규칙** — 문체 · 어휘 · 하지 말 것 | `house.md` | **모든 답변.** 켤 때 훅이 여덟째로 싣는다 |
| **양식** — 보고 골격 · 절 제목 · 길이 | `templates/` | 보고서 쓸 때. `report` 가 읽는다 |
| **방법** — 분석 절차 · 배치 만드는 법 | `analysis/methods/` | 분석할 때. `analysis` 가 읽는다 |
| **별칭** — 현장 말 ↔ 자료의 말 | 카드의 `aliases` | 찾을 때. 1층 |

### 굳기 전에 한 번 되묻는다

사람이 이미 `앞으로` 라고 말했으므로 **승인은 끝났다.** 비서가 정할 것은 **경계**다.

> 회의록만인가요, PL 께 나가는 문서 전부인가요?

넓게 잡으면 특허 초안까지 회의 양식으로 쓰고, 좁게 잡으면 다음 주에 또 시켜야 한다.
그래서 묻되 **승인이 아니라 경계**를 묻고, 물음은 하나다.

### `이번에는` 은 굳지 않는다

한 번의 예외가 영구 규칙이 되면 규약이 금방 쓰레기로 찬다. 충돌하는 줄이 쌓이고 비서는 느려진다.
**애매하면 굳히지 않는다** — 사람이 `앞으로` 를 명시했을 때만이다.

그리고 `house.md` 에는 **상한 50줄**이 걸려 있다. 새 규칙을 넣으려면 낡은 규칙을 빼야 한다.
넘치면 훅이 자르고 비서가 **첫 답에 사람에게 말한다** — 무엇을 뺄지는 사람이 고른다. 비서가 스스로 줄이지 않는다.
카운터도 점수도 없다. **숫자 하나가 그 일을 한다.**

### 비서가 먼저 알아채는 쪽

사람이 `앞으로` 라고 말해 주지 않아도, 같은 지적이 여러 번 나오면 굳힐 것일 수 있다.
그런데 비서는 그것을 **세지 않는다.** 횟수를 들고 있는 파일도 점수도 등급도 만들지 않는다.

대신 일지에 한 줄씩 쌓아 두고(`## 되풀이된 말`), 사람이 `돌아봐` 할 때 `retro` 가 그것을 읽다가 묻는다.

> 지난주에 간결하게 써 달라는 말씀을 여러 번 들었습니다. 앞으로 계속 이렇게 할까요?

```mermaid
flowchart TB
    CALL["사람: '돌아봐' · '개선할 거 없어?'"] --> READ["읽는 것 셋<br/>journal/*.md · find.log · 판정 파일"]
    READ --> R1["1 · 되풀이된 것"]
    READ --> R2["2 · 막힌 것<br/>못 찾은 물음 · 검토 불통과"]
    READ --> R3["3 · 굳힐 후보<br/>규칙 · 양식 · 방법 · 별칭"]
    READ --> R4["4 · 장치가 필요해 보이는 것"]
    R1 --> EV{"근거가 있나<br/>일지 날짜 · find.log 줄 · 카드 번호"}
    R2 --> EV
    R3 --> EV
    R4 --> GATE{"판별 넷을 통과하나<br/>숫자 · 타이밍 · 문맥 격리"}
    GATE -->|"아니오"| NONE["'없음' 이라고 쓴다"]
    GATE -->|"예"| EV
    EV -->|"없다"| CUT["그 항목을 지운다"]
    EV -->|"있다"| OUT["사람에게 낸다<br/>비서는 제안까지. 만드는 것은 사람 + PR"]
```

**관문이 둘인 까닭이 다르다.** 아래쪽 근거 검사는 **봇이 패턴을 지어내는 것**을 막는다 —
"이런 게 반복됐습니다" 는 그럴듯하게 쓰기 아주 쉽고 틀려도 사람이 알아채기 어렵다.
오른쪽 판별 넷은 **스킬 제안이 가장 비싸기 때문**에 있다. PR 이 필요하고 되돌리기 어려우므로,
"데이터로는 왜 안 되는가" 에 답하지 못하면 아예 올리지 않는다.

**새로 만든 장치가 없다.** 일지는 이미 매일 쓰이고 있었다. 읽는 시점만 정한 것이다.

## 워크플로우 ⑧ — 분석 (여섯 칸)

"갈리는지 봐 줘" 라는 말 하나에서 **폴더 하나 · 대본 하나 · 카드 하나**가 나온다.

```mermaid
flowchart TB
    REQ["'두 공급사 것이 갈리는지 봐 줘'"] --> LOOK["먼저 찾는다<br/>find.js · ls analysis/"]
    LOOK -->|"같은 물음을 이미 했다"| OLD["앞 카드를 댄다<br/>새 폴더를 만들지 않는다"]
    LOOK -->|"자료만 늘었다"| RERUN["있는 run.py 를 그대로 다시 돌린다"]
    LOOK -->|"새 물음"| ONE["물음을 한 줄로 되짚는다<br/>'이게 맞습니까?'"]
    ONE --> MODEL["모형 후보 두셋을 근거와 함께 낸다"]
    MODEL --> GATE{"사람이 고른다<br/>유일한 관문"}
    GATE -->|"고름"| CODE["analysis 날짜-이름/run.py<br/>입력은 inbox 경로 · seed 고정<br/>그림은 tmp/"]
    CODE --> DOC["run.md 여섯 칸"]
    DOC --> CARD["카드 하나<br/>결론 한 줄 · 분석 경로 · 쓴 모형"]
    CARD --> COMMIT["git 커밋"]
    OLD --> COMMIT
    RERUN --> DOC
```

### 여섯 칸

측정법이 EIS 든 SEM 이든 t 검정이든 **칸은 같다.** 달라지는 것은 2·3 뿐이고 그것은 AI 가 잘한다.

| 칸 | 무엇을 적나 | 왜 |
|---|---|---|
| 1 · 무엇을 알고 싶은가 | 사람이 확인해 준 한 줄 | 물음이 문장이 안 되면 분석도 안 된다 |
| 2 · 어떤 가정을 깔았나 | 모형 · 임계값 · 정규성 | **가정을 숨기고 결론만 말하면 틀렸을 때 어디서 틀렸는지 알 수 없다** |
| 3 · 코드 | `run.py` · **seed · python 판 · 꾸러미 판** | 없으면 반년 뒤 숫자가 달라졌을 때 **비서가 틀린 건지 라이브러리가 바뀐 건지** 못 가린다 |
| 4 · 숫자 + 검증치 | 값과 함께 잔차 · χ² · 신뢰구간 | 숫자만 있으면 맞는지 알 수 없다 |
| 5 · 물리적 해석 | 말 + **어느 숫자에서 나왔는지** + (추정) 표시 | 해석은 자유롭게 하되 확인과 추정을 가른다 |
| 6 · 뒤집을 수 있는 것 | 무엇을 더 재면 틀린 것으로 드러나나 | 2번과 함께 **안 써도 글이 완성돼 보이는** 칸이라 굳이 못 박았다 |

### 왜 관문이 하나뿐인가

가르는 기준은 측정법이 아니라 **"누가 답이 맞는지 확인하나"** 다.

| | 예 | 그래서 |
|---|---|---|
| 기계가 스스로 확인한다 | 피팅(잔차 · χ²) · t 검정 · 회귀 · Cpk | 비서가 즉석에서 짜도 된다. **안전장치가 출력 안에 있다** |
| 사람 눈으로만 확인된다 | 이미지에서 입자 · 기공 · 두께 재기 | 숫자만 내면 안 된다. **원본 위에 검출 결과를 겹친 그림**을 반드시 같이 낸다 |
| **비서가 그럴싸하게 틀린다** | **모형 고르기** — 등가회로를 몇 층으로 볼지 | **여기만 사람이 정한다** |

코드 짜는 데는 관문이 없다. 관문을 더 두면 묻는 수가 늘고, 그것은 이 비서가 하려는 일의 반대다.

### 카드는 선택이 아니다

찾기가 뒤지는 여섯 층에 `analysis/` 가 **없다.** 층 순서는 스크립트에 못 박혀 있어 부르는 쪽이 바꾸지 못한다.
그래서 카드(2층)에 결론 한 줄과 경로가 없으면 **그 분석은 다음 주에 없는 것이 된다.**

### 미리 만들어 둔 것이 없다

t 검정도 Cpk 도 DOE 도 **스크립트로 미리 만들어 두지 않았다.** 측정법은 수십 가지고 과제가 바뀌면 또 나온다.
그리고 **틀린 템플릿이 즉석 코드보다 위험하다** — 즉석 코드에는 "방금 짠 것" 이라는 경계심이 붙어 사람이 한 번 보지만,
템플릿은 검증된 것처럼 보여서 아무도 안 본다. 등가회로를 한 층으로 고정한 템플릿을 계면이 둘인 시료에 갖다 붙이면
**물리적으로 틀린 답이 아주 깔끔한 표로 나온다.**

되풀이돼 굳은 방법만 `analysis/methods/` 로 간다. 그것도 사람이 "앞으로" 라고 말했을 때다.

## 실제로 이렇게 돌았다 — 시나리오 하나

위의 흐름들이 **실제로 한 번 다 돌아간 기록**이 있다. 2026-09-11 에 검수 세션(meta)이 사람 역할을 맡아
비서에게 대본을 건네고 받은 것이다.

**출처가 둘이고 성격이 다르다. 섞어 읽으면 안 된다.**

| 무엇 | 어디 | 이 저장소에 있나 |
|---|---|---|
| **판정과 계측** — 예측 대 실측 · 빗나간 칸과 원인 가설 · 세어 본 값(카드 수 · 줄 수 · 비용) | `docs/evidence/2026-09-11-evo-path.md` | **있다** (사본. 고치지 않는다) |
| **비서가 실제로 한 말** — 아래 인용문과 그 안의 수치(평균 · p · Ppk 같은 것) | meta 의 대화 저장본 `../meta/prodev-review/runs/2026-09-11-evo-path-transcript.md` | **없다** |

아래 인용은 **대화 저장본**에서 왔고, 소제목마다 그것을 뒷받침하는 **판정 쪽 근거**를 함께 적었다.
대화 저장본은 meta 의 기록이라 이 저장소에 사본을 두지 않았다 — 회사로 옮기면 그 파일은 따라가지 않는다.
**그러니 인용된 비서의 말은 "그때 이렇게 답했다" 는 예시로 읽고, 판정의 근거로는 evidence 쪽을 본다.**

과제는 가상이다 — 샤워헤드 `SH-2200` 의 코팅 두께가 **공급사 둘(BSTech · AlphaParts)에 따라 갈리는지** 보는 일.

> 40건 전부 · BSTech 20 · AlphaParts 20 · 규격 `coating_um` 2.0~3.0um
> BSTech 2.54~2.96 (평균 **2.703**) · AlphaParts 1.99~2.51 (평균 **2.289**)
> 중복 0 · 빈칸 0 · 단위 안 섞임. 다만 **규격 밖 1건: SH2200-A-1203 · 1.99um**

그리고 **물음 셋**을 냈다 — 측정일이 어디 있나(입고일밖에 없다) · 공급사 성적서인가 우리가 잰 것인가 ·
전수인가 표본인가. 둘째 물음이 중요하다. 공급사가 낸 성적서라면 **차이가 코팅의 차이인지 성적서 쓰는 방식의 차이인지 이 자료만으로는 못 가린다.**

값 범위가 겹치지 않는다는 것은 짚되 **판정하지 않았다.** "관찰일 뿐 판정은 아닙니다."

> **근거** 카드 셋이 만들어지고 색인 오류가 0 이었다는 것은 판정 쪽에서 세었다 (`docs/evidence/2026-09-11-evo-path.md` 1절 B5).
> 위의 평균값과 물음 셋은 대화 저장본에서 옮긴 것이다.

### ② 분석 — 모형을 사람이 고른다

"갈리는지 봐 줘" 에 비서가 먼저 물음을 한 줄로 되짚고, **모형 후보 셋**을 근거와 함께 냈다.
사람이 고르자 코드를 짜고 돌렸다.

| | 값 |
|---|---|
| 평균차 | **0.414 um** (BSTech 가 두껍다) |
| Welch t | 9.69 (df 36.7) · **p = 1.16e-11** |
| 95% 신뢰구간 | [0.327, 0.501] um |
| 겹치는 개체 | **0개** |

그리고 **5번 칸(해석)과 6번 칸(반증)을 이렇게 채웠다.**

> (추정) 두 군의 산포는 비슷한데(0.122 vs 0.147) 중심만 통째로 옮겨져 있습니다.
> 공정 관리가 흔들리는 쪽이면 산포부터 벌어졌을 텐데 그렇지 않으니, **코팅 조준점이 서로 다른 것**으로 보입니다.

> **뒤집을 수 있는 가장 큰 것 — 로트입니다.** 자료에 로트 열이 없고 일련번호가 연속입니다.
> 공급사마다 로트 하나에서 스무 개가 나왔다면, 제가 잰 것은 공급사 차이가 아니라 **로트 둘 사이의 차이**이고 실질 표본은 군당 1입니다.

**6번 칸이 왜 있는지가 여기서 보인다.** 결론은 강한데(p = 1.16e-11) 그 결론을 통째로 무너뜨릴 수 있는 것이 자료 밖에 있다.

> **근거** 여섯 칸이 다 찼는지(제목 여섯 · 가정 · seed 와 판 · 반증)를 판정 쪽에서 **12/12** 로 세었고,
> 위 수치가 meta 의 정답지와 맞는지도 거기서 맞대 보았다 (evidence 1절 B2 · B4). 인용문 자체는 대화 저장본이다.

### ③ 비서가 이름을 바로잡았다

다음 물음은 공정능력(Cpk)이었다. 비서가 숫자를 내면서 **이름을 고쳤다.**

> 위 값은 Cpk 가 아니라 **Ppk** 입니다. 부분군(로트 · 생산일) 열이 없어 within-sigma 를 낼 수 없어 전체 표준편차로 냈습니다.
> **보고서에 Cpk 로 적으시면 나중에 감사에서 걸립니다.**

Ppk 는 BSTech **0.812** · AlphaParts **0.655** 로 둘 다 문턱(1.33)에 못 미쳤다. 그런데 산포만 보는 Pp 는 1.367 · 1.133 이었다.
**못 쓰는 까닭이 흔들려서가 아니라 겨냥이 쏠려서**라는 뜻이고, 비서는 거기서 멈췄다.

> 그래서 헌장의 "갈리면 공급사를 바꾼다" 가 이 숫자만으로는 풀리지 않습니다.
> **공급사를 고르는 일과 조준점을 옮기게 하는 일은 다른 조치**입니다 — 이건 PL 께서 정하실 자리라 제가 방향을 잡지 않고 숫자만 놓아 둡니다.

믿을 수 있는 범위도 스스로 그었다 — "1.33 에 못 미친다는 말할 수 있습니다. 다만 n=20 이라 **0.81 이냐 0.85 냐를 따질 수는 없습니다.**"

### ④ 같은 분석을 다시 시켰다

같은 것을 한 번 더 시키자 비서가 이렇게 했다.

> **새 폴더도 새 카드도 만들지 않았습니다.** 같은 자료 · 같은 물음 · 같은 모형이면 결과도 같아야 하고,
> 폴더를 하나 더 만들면 나중에 어느 쪽이 진짜인지 헷갈립니다. 대신 E-0002 에 "재현 확인" 한 줄을 넣었습니다.

있는 `run.py` 를 그대로 다시 돌려 숫자가 같은 것까지 확인했다. **이것이 "다음에 또 짜지 않는다" 가 실제로 작동한 자리다.**

> **근거** 분석 폴더가 **둘 그대로**였고 앞 카드(E-0002)를 댔으며 sha 대조까지 했다는 것이 판정 쪽에 있다 (evidence 1절 B6).
> 재실행 결과가 `run.md` 의 숫자와 맞는지도 거기서 **2/2** 로 세었다 (B3).

### ⑤ "이번에는" 과 "앞으로" 를 갈랐다

사람이 회의 문서를 **"이번엔 짧게"** 라고 했다. 비서가 짧은 판을 내고 이렇게 덧붙였다.

> "이번엔" 이라 하셔서 이번 회의에 한한 예외로 두고, **`templates/` 를 손대지 않았습니다.**
> 앞으로 늘 이렇게 하실 것이면 그때 말씀해 주십시오.

그리고 빠진 절에서 사라진 것 하나를 짚었다 — "코팅이 갈린다는 것이 아직 **수율 하락의 원인을 말하지 않는다**"
(40개가 전부 미장착 재고다). 다음 일정 표에는 부품 구매 500만 원이 걸린 항목이 그대로 있었다.

사람이 **"앞으로 이 양식대로"** 라고 하자 그때 `templates/회의-문서.md` 로 굳혔다. 머리에 셋을 달았다 —
언제부터 2026-09-11 · 누가 김피엘 · 무엇을 보고. **양식 파일은 하나였다** (예외는 안 굳었다).

다음에 사람이 문체 규칙("검토 중" 쓰지 말 것)을 주자 이번에는 `house.md` 로 갔다. 21줄 → 23줄.

> **셋째 줄은 제가 더해 넣었습니다.** 오늘 정확히 반대 일이 있었습니다 — 양식이 "기한은 날짜로" 라고 해서
> 제가 날짜를 **지어냈고** 검토가 세 건을 막았습니다. 이 규칙만 있고 셋째 줄이 없으면 저는 같은 쪽으로 밀립니다.

규칙이면 `house.md`, 양식이면 `templates/`. **자리를 헷갈리지 않았다.**

> **근거** "이번엔" 뒤에 `templates/` 파일이 **0**, "앞으로" 뒤에 **1** 이 된 것 · 굳은 파일 머리의 셋이 **3/3** ·
> `house.md` 가 **21줄에서 23줄**로 늘고 상한 50 안이었던 것이 전부 판정 쪽에서 세어졌다 (evidence 1절 B7 · B9 · B10).

### ⑥ 회고가 먼저 물었다

"돌아봐" 한마디에 비서가 일지 5개 · `find.log` 6줄 · 판정 파일 2개를 읽고 넷을 냈다.

> **"짧게 써 줘" 를 세 번 하셨습니다** — 09-01(#415) · 09-02(#433) · 09-05(#459). 아직 아무 데도 안 굳었습니다.
> **같은 t 검정을 세 번 새로 짰습니다** — 09-02 · 09-04("코드가 `tmp/` 에서 사라져 처음부터 다시 짰다") · 09-11.

굳힐 후보 셋에 **들어갈 문장까지** 써 두었다. 그중 하나는 시킨 적 없는 것이었다 —
"`tmp/` 에 둔 것은 사라진다. 지금도 팀 회의 양식 원본이 `tmp/` 에 있습니다."

그리고 **스킬 후보는 "없음"** 이었다.

> 가장 크게 되풀이된 것(고치다 다른 것 흘리기, 다섯 번)은 **판별 넷을 통과하지 못합니다.**
> 스크립트 한 벌이면 될 일입니다 — 고친 판과 앞 판을 맞대어 사라진 줄을 세는 것.

만들자고 하기 쉬운 자리에서 **안 만들기로 판별한 것**이 이 관문의 요점이었다.

> **근거** 네 절이 다 있고 · **근거 없는 항목 0** · **지어낸 항목 0** · 판별 없는 스킬 제안 **0** 이라는 것을 판정 쪽에서 세었다
> (evidence 1절 B13). 도구가 처음 낸 수는 그보다 컸는데 **파일로 맞대어 오탐을 가른 과정**이 같은 문서 3.4 절에 적혀 있다 —
> 세는 도구도 틀릴 수 있다는 것을 그 절이 보여 준다.

### ⑦ 규칙이 넘치자 말했다

마지막으로 `house.md` 를 **55줄짜리**로 바꿔 놓고 세션을 새로 켰다. 첫 답에 이 말이 있었다.

> 규칙 파일 `house.md` 가 55줄이라 상한 50 을 넘겨, 훅이 51줄부터를 싣지 않습니다.
> 오늘은 제가 파일을 직접 읽어 규칙 36~38 을 보았습니다만 **매번 그러리라 믿을 수 없습니다.**
> **무엇을 뺄지는 김피엘이 고를 자리이고 제가 줄이지 않습니다.**

> **근거** 55줄짜리로 바꿔 켠 뒤 첫 답에 알림이 **1/1** 로 나왔고 파일은 그대로 55줄이었다 (evidence 1절 B12).
> 다만 같은 문서 3.5 절에 이런 기록도 있다 — 그날 비서는 **잘린 뒷부분을 직접 읽어 보았다.**
> 허용된 일이지만 상한의 뜻(뒷부분이 안 실린다)이 그 길로 새는 자리라 meta 가 적어 두었다.

### 빗나간 둘 — 숨기지 않는다

판정은 통과였다. 예측 열다섯 칸 중 **열둘**(기준 열둘), 채점표 **28/31**. 딱 기준선이다.
**빗나간 둘은 고침 후보로 남아 있다.** 아래 표는 판정 쪽 2절(빗나간 칸과 원인 가설)을 옮긴 것이다.

| 빗나간 것 | 무슨 일이 있었나 | 왜 그랬을까 (원인 가설) |
|---|---|---|
| **범위를 굳힌 뒤에 물었다** | 두 번 다 파일을 먼저 만들고 그 뒤에 물었다. 물음의 내용도 범위("회의록만인가요")가 아니라 다른 것이었다 | 규칙에 "범위를 되묻는다" 는 적었으나 **"파일을 만들기 전에"** 라는 순서를 못 박지 않았다. 비서는 파일을 먼저 남기는 쪽으로 밀렸다 — "파일이 진실" 이라고 배웠기 때문이다 |
| **양식 폴더를 다시 읽지 않았다** | `templates/` 에 둘째 양식이 있는데 "회의록 양식 하나뿐" 이라고 답했다 | 폴더를 보는 걸음이 **문답이 시작될 때 한 번**만 돌고, 앞 턴의 기억으로 답했다. "넷의 순서로 본다" 가 **매 요청마다 다시 읽으라**는 뜻으로 안 읽혔다 |

둘 다 **규칙이 틀린 것이 아니라 모자랐다.** 그리고 둘 다 같은 종류다 — 비서가 게을러서가 아니라,
**규칙이 말하지 않은 자리를 비서가 제 나름으로 메웠고 그 메움이 빗나갔다.**

### 이 시나리오에서 볼 것

- **비서가 자기 숫자의 한계를 먼저 말했다** — Cpk 를 Ppk 로 고치고, "0.81 이냐 0.85 냐는 못 따진다" 고 긋고, 로트 구멍을 반증 칸에 적었다
- **시키지 않은 것을 찾아냈다** — `tmp/` 에서 자료가 사라진다는 것, 일지의 `p=0.03` · `p=0.008` 이 **출처 없는 숫자 2개**라는 것
- **만들지 않기로 판별했다** — 가장 자주 되풀이된 것에도 "스킬은 필요 없고 스크립트 한 벌이면 된다" 고 답했다
- **그래도 둘이 빗나갔다** — 검수가 잘 된 것만 세면 값을 하지 않는다. 빗나간 자리와 원인 가설이 `docs/evidence/` 에 그대로 있다

이날 비서 세션 둘이 쓴 값은 **$33.20** (호출 250 · 도우미 55 · 두 시간)이었다 —
이 값과 위의 판정 수(12/15 · 28/31)는 판정 쪽에서 잰 것이다 (`docs/evidence/2026-09-11-evo-path.md` 3.5 · 판정 절).

## 비서의 하루

```mermaid
flowchart LR
    T1["아침<br/>사람이 말을 건다<br/>'오늘 뭐 있지'"] --> T2["brief<br/>어제 일지 · 이번 주 일정<br/>열린 질문 · 밀린 것"]
    T2 --> T3["낮<br/>파일이 오면 들이기<br/>물으면 찾아 답하고<br/>시키면 조사·분석한다"]
    T3 --> T4["저녁<br/>사람이 말을 건다<br/>'정리해 둬'"]
    T4 --> T5["journal<br/>오늘의 결정 · 미해결<br/>다음 할 일 · 되풀이된 말"]
    T5 --> T6["git 커밋"]
    T3 -.->|"압축이 걸리면"| T5
```

**정해진 시각에 저절로 돌지 않는다.** cron 도 작업 스케줄러도 쓰지 않는다 — 사람이 필요할 때 말을 건다.

손실이 작다. `brief` 와 `journal` 은 **원래도 사람의 말로 불린다** ("오늘 뭐 있지" · "정리해 둬").
정해진 시각이 하던 일은 그것을 대신 불러 주던 것뿐이다.
오히려 나은 점이 있다 — **아침 브리핑은 사람이 자리에 없으면 방에 쌓이고 만다.**
사람이 말을 걸 때 나오면 반드시 읽힌다. 그리고 압축 직전에는 훅이 일지를 챙기므로 기록이 비지 않는다.

## 등장인물

| 누구 | 정체 | 어디 사나 |
|---|---|---|
| **비서** | Claude Code 세션 하나 + 채널 플러그인 | `bots/<봇이름>/` |
| **도우미 여섯** | 오래 걸리는 일을 맡는 보조 세션. 서로 대화하지 않는다 | `.claude/agents/` |
| **알림 계정** | 사람 계정 하나(`prodev-notify`). 훅이 "정리 중" 같은 글을 올릴 때 쓴다 | 채팅 서버 |
| **훅 셋** | 비서가 켜질 때 · 압축 직전 · 말하기 직전에 끼어드는 기계 | `common/hooks/` |

**cron 은 등장인물이 아니다.** `setup.js cron` 이 crontab 두 줄을 내주기는 하지만
**자동 브리핑을 두지 않기로 했다** (위 "비서의 하루"). 사람이 말을 걸 때 `brief` 와 `journal` 이 뜬다.

### 도우미 여섯

| 도우미 | 하는 일 | 돌려주는 것 |
|---|---|---|
| `data-reader` | 큰 파일을 한 줄도 빼지 않고 읽는다 | `reading.md` + 20줄 요약 |
| `researcher` | 문헌 · 규격 · 웹 조사. **출처 없는 문장 금지** | 결론 · 출처 · 못 확인한 것 |
| `reviewer` | 남이 만든 것을 의심하며 다시 센다 | 통과 / 불통과 / 검증 불가 + 이유 3줄 |
| `patent-analyst` | 선행 기술과 청구 후보 | 선행 목록 · 차이 · 위험 |
| `paper-writer` | 논문 절 초안 + 근거 카드 | 경로 · 근거 카드 · 빈 자리 |
| `report-writer` | 보고 양식의 칸 채우기 | 경로 · **출처 없는 숫자 목록** |

공통 규칙 셋: **자세한 건 파일에 · 돌려주는 말은 20줄 안 · 커밋은 하지 않는다.**

`charter` 발의 · `intake` 들이기 · `find` 찾기 · `research` 리서치 · **`analysis` 분석** · `schedule` 일정 ·
`brief` 브리핑 · `journal` 일지 · **`retro` 회고** · `patent` 특허 · `paper` 논문 · `report` 보고 ·
`review` 검토 · `close` 마감

**굵은 둘이 v3 에서 늘었다** (ADR-034 · 036). 둘 다 능력이 없어서가 아니라 **자리가 없어서** 만든 것이다 —
"이 자료로 t 검정 해 줘" 를 받을 스킬이 없었고, 일지에 쌓인 것을 **읽는 시점**이 없었다.

`analysis` 는 분석 한 건을 `analysis/<날짜>-<이름>/` 에 남긴다 — 돌린 코드(`run.py`)와 여섯 칸짜리 대본(`run.md`),
그리고 **카드 하나.** 카드는 선택이 아니다: 찾기가 뒤지는 여섯 층에 `analysis/` 가 없어서,
카드에 결론과 경로가 없으면 그 분석은 다음 주에 없는 것이 된다.

`retro` 는 사람이 "돌아봐" 라고 할 때만 돈다. 일지와 `find.log` 를 읽어 **되풀이된 것 · 막힌 것 ·
굳힐 후보 · 스킬이 필요해 보이는 것** 넷을 낸다. **항목마다 근거를 달고, 근거를 못 대면 그 항목을 지운다** —
회고의 가장 큰 위험은 봇이 그럴싸한 패턴을 지어내는 것이기 때문이다.

## 지켜야 하는 약속

이 프로젝트에는 숫자로 못 박은 약속이 있다. 느낌이 아니라 **기계가 잰다.**

| 무엇 | 값 |
|---|---|
| 들이기 한 건의 비용 | $3 이하 |
| 들이기 한 건의 문답 왕복 | 중앙값 4회 이하 |
| 찾기 성공률 (카드 · 위키로 답한 비율) | 70% 이상 |
| 사람에게 보내는 글 | 900자 · 10줄 안 |
| 비서 지침(`CLAUDE.md`) 길이 | 40줄 안 |
| 하루 승인 요청 | 3회 이하 |

v3 이 더한 약속 넷이다. 앞의 여섯이 **값이 넘치지 않게** 하는 것이라면, 이 넷은 **진화가 폭주하지 않게** 하는 것이다.

| 무엇 | 값 | 안 지키면 |
|---|---|---|
| 과제 규칙(`house.md`) 길이 | **50줄 안** | 훅이 자르고 비서가 첫 답에 말한다. **줄이는 것은 사람** |
| 굳히기 전에 묻는 물음 | **하나** (범위) | 승인을 묻는 것이 아니라 경계를 맞추는 자리다 |
| 분석 한 건이 남기는 것 | `run.py` + 여섯 칸 `run.md` + **카드 하나** | 카드가 없으면 찾기 층에 안 걸려 다음 주에 없는 것이 된다 |
| 회고 제안의 근거 | **항목마다 하나** (일지 날짜 · `find.log` 줄 · 카드 번호) | 근거를 못 대면 그 항목을 지운다 |

**50줄은 줄 수가 아니라 규칙 개수에서 거꾸로 왔다.** 비서가 일관되게 지킬 수 있는 규칙은 많아야 열다섯 안팎이고, 규칙 하나는 제목 한 줄에 내용 한두 줄이다. 15 × 3 ≈ 45줄에 절 제목과 빈 줄을 더해 50이다.
이 숫자 하나가 **장치 없이** 폭주를 막는다 — 새 규칙을 넣으려면 낡은 규칙을 빼야 한다. 카운터도 점수도 등급도 만들지 않았다.

## 돌리는 법

```bash
node scripts/setup.js --project <과제이름>   # 과제 폴더 · 봇 폴더 · 설정을 만든다
node scripts/setup.js rooms <과제이름>       # 방 둘을 열고 봇을 넣는다
npm test                                     # 서버 없이 도는 시험 133건
npm run test:server                          # 임시 채팅 서버를 띄우는 시험 25건
```

`--project` 에는 **이름만** 주면 된다. 폴더를 미리 만들 필요가 없다 —
`MINIDISCORD_BOT_FILES_DIR` 아래에 폴더를 만들고 `git init` 까지 한다.
파일 뿌리 밖에 두고 싶을 때만 경로를 준다.

봇을 실제로 띄우는 순서(cwd · 옵션 조합 · 확인 방법)는 `docs/launch.md` 에 한 자리로 못 박혀 있다.

## 있어야 하는 것

| 무엇 | 판 | 없으면 |
|---|---|---|
| node | ≥ 22 (`node:sqlite` · `node --test`) | 안 돈다 |
| python3 | 3.9+ | `peek.js` 의 xlsx 와 `plot.py` 만 안 된다 |

python 꾸러미는 **있으면 쓰고 없으면 그 부분만 건너뛴다.** 스크립트는 죽지 않고 "못 읽었다: <까닭>" 한 줄을 낸다.

| 꾸러미 · 도구 | 쓰는 곳 | 없을 때 | 들이는 법 |
|---|---|---|---|
| `openpyxl` | `peek.js` 의 xlsx | "못 읽었다: openpyxl 이 없다" | `pip install openpyxl` |
| `matplotlib` | `plot.py` | "못 그렸다: matplotlib 이 없다" | `pip install matplotlib` |
| `pdfplumber` | `peek.js` 의 pdf 글·표 | `pdftotext` 로 넘어간다 | `pip install pdfplumber` |
| `pdftotext` (poppler) | pdfplumber 가 없을 때의 pdf 글 | 쪽 수만 낸다 | `brew install poppler` |

csv · tsv · jpg · png 와 pdf 쪽 수는 node 가 직접 읽는다. 도우미가 하나도 없어도 이것들은 된다.

**분석용 꾸러미 셋은 성격이 다르다.** 위의 넷은 없으면 그 부분만 건너뛰지만, 아래 셋이 없으면 `analysis` 스킬이 **멈추고 말한다.**

| 꾸러미 | 쓰는 곳 | 없을 때 |
|---|---|---|
| `pandas` | 표를 다루는 분석 | "이 기계에 pandas 가 없습니다" 하고 **멈춘다** |
| `scipy` | t 검정 · 분포 같은 계산 | 〃 |
| `statsmodels` | 회귀 · 분산분석 · DOE 배치 | 〃 |

```bash
python3 -m pip install pandas scipy statsmodels      # 맥 · 리눅스
py -m pip install pandas scipy statsmodels           # 윈도우
```

**사람이 미리 깐다. 비서에게 시키지 않는다.** 허용 목록에 `pip` 가 없고(ADR-033), 윈도우는 `pip` 가 아니라 `py -m pip` 라 한 줄을 열어 줘도 안 맞을 수 있다.

그리고 **없을 때 손으로 계산한 숫자를 내놓지 않는 것이 중요하다.** p 가 0.04 냐 0.06 이냐가 양산 결정을 가르는데, 지어낸 숫자는 틀려도 아무도 모른다. 그래서 멈추고 말한다. 자세한 것은 `docs/launch.md` 10.4.
