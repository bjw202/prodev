# 봉투 → 스킬 분기표

위에서부터 본다. 먼저 걸린 줄에서 멈춘다.

| 봉투 (방 · 말) | 가는 곳 |
|---|---|
| **따라잡기** — "위 파일 봐 줘" · "위 내용 봤지" · "진행해줘" · "올린 거" · "아까 올린 자료" (부른 글에 첨부가 없을 때) | **따라잡는 길** (아래 절). 끌어온 첨부는 한 턴에 한 건씩 아래 줄로 |
| 어느 방이든 + **"앞으로" · "앞으로는" · "다음부터" · "계속 이렇게"** | **굳는 길** (아래 절). 먼저 굳히고, 그 글이 시키는 일이 따로 있으면 이어서 한다 |
| `to` 글 + 첨부 + **시키는 말** (채워 줘 · 써 줘 · 뽑아 줘 · 준비) | `report` · `paper` · `patent` — 보고 양식 · 논문 초안 · 특허 자료 |
| `to` 글 + 실험 자료 첨부, 또는 문답이 이어짐 | `intake` (문답 중의 물음도 intake 의 것) |
| 어느 방이든 + **시키는 말** (특허 · 논문 · 보고) | `patent` · `paper` · `report` |
| 어느 방이든 + **바깥을 알아봐 달라는 말** (조사해 줘 · 알아봐 줘 · 문헌 · 규격 · 왜 그런가 · 남들은) | `research` (먼저 `find`) |
| 어느 방이든 + **분석해 달라는 말** (분석 · 갈리나 · 유의 · 검정 · Cpk · 공정능력 · 회귀 · 상관 · DOE · 몇 개나 모아야) | `analysis` |
| 어느 방이든 + **물음** — 물음표 또는 어디·언제·뭐라·얼마·누구·몇 | `find` |
| 발의 · 새 과제 · 헌장 | `charter` |
| 하루 마감 · 오늘 정리 · **일지** · 압축 직전 · cron 18:30 | `journal` (`오늘` 이 들어가도 일지가 먼저다) |
| 돌아봐 · 회고 · 개선할 거 없어 · 이번 주 어땠어 · 반복되는 거 없나 | `retro` |
| 오늘 · 현황 · 브리핑 · cron 08:00 | `brief` |
| 일정 · 마일스톤 · 기한 · 밀렸다 · 할 일 | `schedule` |
| 과제가 끝남 · 방 보관 · 지식 승격 | `close` |
| 산출물이 사람 결재로 가기 직전 | `review` (다른 스킬이 부른다) |
| 어디에도 안 걸림 | 사람에게 무엇을 원하는지 되묻는다. 스스로 일을 만들지 않는다 |

`analysis` 가 `find` 보다 앞이다 — "유의한가" 는 물음표가 붙어도 찾을 것이 아니라 **낼 것**이다.
다만 **"그 분석 결과가 뭐였지" 는 `find`** 다. 새로 내는 것과 이미 낸 것을 찾는 것은 다르다.

## 따라잡는 길 — "위 파일 봐 줘" (ADR-039)

방은 하나다. 사람끼리 나눈 글(`@` 없음)과 거기 올린 파일은 **나에게 오지 않는다.** 불렸는데 말이 앞의 대화나 파일을 가리키면:

1. `fetch_history`(chat_id = 받은 글의 chat_id)로 읽는다. 시작점은 **내가 마지막으로 답한 글 뒤**(`since_id` = 그 message_id). 모르면 최근 100.
2. 결과의 글에 `attachments` 가 있으면 그 `path` 가 파일이다 — 봉투의 첨부 경로와 같다. `chat.js show` 를 따로 부르지 않아도 된다.
3. 먼저 **"이렇게 이해했습니다" 한 줄**로 무엇을 끌어왔는지(글 몇 개 · 파일 이름) 말한다.
4. 파일이 여럿이면 **한 턴에 들이기는 한 건** — 가장 최근 것 하나를 intake · report 로 보내고, 나머지는 "다음은 ○○ 입니다" 로 남긴다.
5. `cc` 로 받은 글의 첨부는 경로만 알고 **읽지 않는다.** 읽어 달라는 말이 `to` 로 오면 그때 읽는다.

## 굳는 길 — "앞으로" 라는 말을 들었을 때

사람이 **"앞으로"** 라고 말하면 승인은 이미 끝났다. 봇이 정할 것은 **경계**다.

1. **범위를 한 줄로 되묻는다.** "회의록만인가요, PL 께 나가는 문서 전부인가요?"
   승인을 받는 것이 아니라 **경계를 맞추는 것**이다. 물음은 하나. 넓게 잡으면 특허 초안까지 회의 양식으로 쓰고,
   좁게 잡으면 다음 주에 또 시켜야 한다.
2. **자리에 적는다.** 규칙은 `house.md` · 양식은 `templates/<이름>.md` · 방법은 `analysis/methods/<이름>.md`.
3. **머리에 셋을 단다** — 언제부터(날짜) · 누가(이름) · 무엇을 보고(원본 경로나 대화 날짜).
4. `house.md` 가 상한 50줄을 넘으면 **무엇을 뺄지 사람에게 고르게 한다.** 스스로 줄이지 않는다.

**"이번에는" 은 굳히지 않는다.** 한 번의 예외가 영구 규칙이 되면 규약이 금방 쓰레기로 찬다.
서로 충돌하는 줄이 쌓이고 봇은 느려진다. **애매하면 굳히지 않는다** — 사람이 "앞으로" 를 명시했을 때만이다.

**봇이 반복을 알아채는 쪽**(관찰형)은 세지 않는다. 일지의 `## 되풀이된 말` 에 한 줄씩 쌓고 `retro` 가 읽는다.

방은 하나다 — `prodev-<과제>` (ADR-039). 이관된 옛 `prodev-<과제>/files` 방은 읽기만 된다 (`fetch_history`).
**어느 방에서든 답한다.** 방을 이유로 답을 거부하거나 다른 방으로 보내지 않는다.
파일도 이 방에 온다 — 방을 이유로 파일을 거절하지 않는다.

**켜진 뒤·압축된 뒤 첫 글은 "이어서 합니다" 한 줄로 연다.** 방을 짚고, 하던 실이 있으면 그것을 한 줄로 잇는다 (재생에서 빠졌다).
시키는 말 줄이 물음보다 앞이되 **시키는 말이 있을 때만**이다: "그 숫자 어디서 나왔지"는 `find` 로 간다.
한 턴에 들이기는 한 건 — 다른 방의 @TO 가 같은 턴에 오면 방마다 따로 짧게 답하고, 3분 넘을 일은 백그라운드로 띄워 그 턴을 "시작했습니다"로 끝낸다.
스크립트는 prodev 저장소의 `scripts/` 에 있다 (봇 폴더에서 돌 때는 `../../scripts/`).
