# close — 마감과 승격

## 언제

과제가 끝났을 때.

## 왜 승격이 따로 있나

과제 위키는 이 과제의 말로 적혀 있다. 다음 과제 사람이 읽으면 무슨 말인지 모른다.
그래서 회사 지식(`knowledge/`)으로 올릴 때는 **다시 쓴다.** 그리고 무엇을 올릴지는 PL 이 정한다 —
잘못 올라간 지식은 다음 과제를 잘못된 데로 이끈다.

## 하는 일 — 네 걸음

### 1. 남은 것을 확인한다

닫기 전에 `index.json` 과 파일을 훑는다 (색인은 이미 카드가 바뀔 때마다 다시 만들어져 있다):
- `status: draft` 인 카드가 있나 — 확정 못 받고 남은 것
- `bots/<봇>/threads/*` 에 열린 실이 있나 — 답을 못 받은 물음
- `schedule.md` 에 `진행` 인데 기한이 지난 줄이 있나

있으면 **먼저 사람에게 보인다.** 열린 채로 닫으면 그 자리가 영영 안 메워진다.

### 2. 승격 후보를 뽑는다

`wiki/*.md` 를 훑어 후보 목록을 만든다:
```
승격 후보 <N>개
1. wiki/<topic>.md — 근거 카드 <N>장 · 다른 과제에도 쓰일 자리: <한 줄>
2. …
올릴 것을 골라 주세요. (PL 결재)
```

고르는 기준을 함께 보인다: **이 과제 밖에서도 참인가** · **근거 카드가 있나** · **다음 사람이 읽어서 아나.**
셋 다 맞아야 후보다.

### 3. PL 결재 뒤 승격한다

고른 페이지를 `knowledge/projects/<과제>.md` (과제의 배움) 또는
`knowledge/domain/<topic>.md` (주제 지식)로 **다시 써서** 옮긴다.

옮길 때:
- 이 과제에서만 통하는 말(장비 이름·로트 번호)을 일반화하거나 괄호로 풀이한다
- 근거 카드 번호는 과제 이름과 함께 적는다 (`[수율개선/E-0007]`) — 다른 과제에서도 찾아갈 수 있게
- 확실하지 않은 것은 올리지 않는다. 회사 지식에 `[추정]` 은 둘 수 있어도 근거 없는 문장은 못 둔다

### 4. 방을 보관하고 헌장을 닫는다

방은 봇이 보관하지 않는다. 방은 조종석이 갖고 있으므로 **PL 에게 조종석에서 과제 방 둘(본방 · `<과제>/files`)을 닫아 달라고 한 줄로 청한다** (ADR-038).
`charter.md` 의 `status: closed` · 닫은 날 · 마지막 일지 · 승격한 목록을 `## 마감` 절에 적고 커밋한다.

방 하나만 보관하고 과제는 이어 갈 일은 없다 — 방이 둘뿐이라 둘 다 닫거나 둘 다 둔다 (ADR-022).

## 사람이 정하는 자리

- **승격 — PL 결재.** 무엇을 회사 지식으로 올릴지
- 열린 것을 열어 둔 채 닫을지

## 부르는 것

`git`. 에이전트는 부르지 않는다. (방 보관은 조종석 몫 — ADR-038)

## 다시 불렸을 때

이미 `closed` 인 과제면 새로 닫지 않는다. 승격만 더 하자는 것이면 후보 목록을 다시 뽑고,
이미 올린 것은 "올림"으로 표시해 두 번 올리지 않는다.

## 걸리는 자리

| 일 | 하는 것 |
|---|---|
| draft 카드가 남았다 | 목록으로 보인다. 사람이 그냥 닫자 하면 헌장 `## 마감` 에 "확정 못 받은 카드 <N>장"을 적는다 |
| 보관이 실패했다 | 헌장은 닫되 어느 방이 안 닫혔는지 알린다 |
| 승격할 것이 없다 | "없음"도 결과다. 왜 없는지 한 줄 (근거 카드가 얕다 · 과제 특수하다) |
| 과제가 중단이지 완료가 아니다 | `status: closed` 로 하되 `## 마감` 첫 줄에 중단이라고 적고 어디서 멈췄는지 남긴다 |
