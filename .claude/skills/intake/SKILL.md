# intake — 자료 들이기

## 언제

`/들이기` 방에 첨부가 올라왔을 때. 그리고 이미 시작한 문답이 이어질 때.

**한 턴에 한 건.** 다른 방의 @TO 가 같은 턴에 오면 방마다 따로 짧게 답하고, 들이기는 하나만 진행한다.
왜: 문답 둘이 겹치면 카드 번호가 엇갈리고 사람은 어느 물음에 답하는지 모른다.

## 하는 일 — 다섯 걸음

### 1. 들인다 (원본은 불변)

```
node scripts/intake-copy.js <slug> <파일…> --project <과제폴더>
```
`inbox/<날짜>-<slug>/` 에 그대로 베끼고, 같은 이름이면 `.v2` 로 늘리고, SHA-256 을 재고,
`files.md` 뼈대를 만든다. **원본을 고치거나 지우지 않는다.**

slug 는 사람 말에서 짧게 뽑는다 (`ch3b-showerhead`). 모르겠으면 파일명에서.

### 2. 연다

```
node scripts/peek.js <파일>          행 수 · 열 이름 · 앞 5행 · 형식
```

파일이 크면 (csv·xlsx 2,000행 이상, pdf·docx 20쪽 이상) **`data-reader` 를 백그라운드로 띄운다.**
그 턴은 "읽기 시작했습니다" 한 줄로 끝내고, 다음 턴에 `reading.md` 를 받아 이어 간다.
주 세션이 큰 파일을 통째로 Read 하지 않는다 — 그 턴의 나머지가 전부 밀린다.

이미지는 직접 본다. pdf·docx 는 글로 읽는다.

### 3. "이렇게 읽었습니다" 표를 보인다

방에 표 하나:

| 칸 | 무엇 |
|---|---|
| 실험일 후보 | 파일에서 찾은 날짜와 그 근거 |
| 장비 · 조건 | 열 이름 또는 머리말에서 |
| 결과 열 | 어느 열이 결과인가, 단위는 |
| 이상한 자리 | **중복 행 · 날짜 형식 섞임 · 단위 흔들림 · 빈 칸** — 이 넷을 따로 본다 |

이 넷은 자료가 가장 자주 배신하는 자리다. 표에 안 올라오면 카드까지 그대로 흘러간다.
`reading.md` 가 있으면 그 파일의 이상 자리를 **하나도 빼지 않고** 옮긴다.

### 4. 묻는다 (셋까지)

모르는 것을 **셋 이하로** 묻는다. 넷째부터는 다음 턴으로 미룬다.

**그림이 나은 자리는 그림으로 묻는다:**
- 수치 흐름 — `python3 scripts/plot.py <csv> --y <열> --project <과제폴더>` → `<과제>/tmp/*.png` 를 첨부
- 사진의 한 구석 — 잘라서 첨부
그림은 `<과제>/tmp/` 에 둔다. `/tmp` 는 봇 첨부 뿌리 밖이라 첨부가 조용히 빠진다.

표 끝에 이 한 줄을 붙인다: **"맞으면 '확정'이라고 답해 주세요."**
어휘를 사람에게 고정해 주는 줄이다. 사람이 "네" 라고만 하면 다시 청한다.

### 5. 기다린다 · 확정한다

사람이 고치겠다 하면 `bots/<봇>/threads/<방>-E-0007.md` 에 남은 물음을 적고 기다린다.
카드는 `status: draft` 로 둔다.

사람의 "확정"이 오면:
```
카드 status: valid
→ 위키 갱신 (그 카드 tags 에 걸리는 페이지만)
→ node scripts/index.js
→ /자료 방에 글 (아래 서식) + 원본 첨부
→ git add <카드·위키·index·inbox> && git commit
```

확정이 왔는지는 **기계가 DB 로 판별한다.** 여기서 그 판별을 지침으로 흉내내지 않는다 —
두 곳에서 판별하면 언젠가 갈리고, 갈리면 봇은 지침 쪽을 믿는다.

## 카드

번호는 `node scripts/index.js next E` 가 준다. 스스로 매기지 않는다 (한 턴에 둘이 같은 번호를 받는다).
머리말과 절 구성은 `ARCHITECTURE.md` 5.1 그대로. 특히:

- `date` 는 **측정일**이다. 올린 날이 아니다.
- `source_msgs` 는 첨부가 올라온 글 번호 **전부**.
- `## 한계 · 못 확인한 것` 에 `reading.md` 의 이상 자리를 **전부** 옮긴다.
  요약해서 줄이면 그 자리에서 사실이 떨어진다.
- `## 결과` 절은 **이상 자리만 싣지 않는다.** 이상하지 않은 행도 사람이 나중에 묻는다
  ("규격 이내인 것은 몇 개였지" · "CH-2B 는" · "공급사별로는"). 그 물음이 카드에서 안 풀리면
  사람은 원본을 열어야 하고, 그러면 카드가 일을 안 한 것이다.
  그래서 결과 절에 둘 가운데 하나를 둔다:
  · 갈래가 적으면(≤10줄) **요약 표**를 그대로 싣는다 (장비별 · 공급사별 · 판정별 수)
  · 많으면 **찾아갈 실마리**를 한 줄로 — `전체 표: inbox/<slug>/<파일> (열 A~F · 34행) · files.md`
  둘 다 없으면 카드는 "이상한 것 목록"일 뿐이다.
- 카드 하나 = **실험 한 건**. 파일 셋이 한 실험이면 카드는 하나다.

## 위키

카드가 `valid` 가 될 때 즉시, **그 카드 tags 에 걸리는 페이지만** 손댄다.
페이지를 다시 쓰지 않는다 — `## 지금 아는 것` 에 문장을 더하거나 고치고 `## 이력` 에 한 줄.
문장마다 카드 번호 `[E-0007]` 이 붙는다. 번호 없는 문장은 위키에 넣지 않는다.
새 주제가 필요하면 **이름을 사람에게 묻는다.** 200줄이 넘으면 하위 주제로 나누자고 제안한다.

## 자료 방 글 (6줄)

카드 번호 · 한 줄 · 조건 한 줄 · 결과 한 줄 · 관련 카드 · 경로. 원본 파일을 첨부한다.
`/자료` 방은 비서만 쓰고 사람은 읽는다. 이 방의 말에는 답하지 않는다.

## 사람이 정하는 자리

- 문답의 답 (실험일 · 조건 · 단위 · 이상한 자리의 뜻)
- **"확정" — 과제원이 한다.** 확정 전에 자료 방에 글이 나가지 않는다.
- 새 위키 주제의 이름

## 부르는 것

`data-reader` (큰 파일) · `reviewer` (끝 조건: `reading.md` 의 이상 자리 수 = 카드 한계 항목 수) ·
`scripts/intake-copy.js` · `scripts/peek.js` · `scripts/plot.py` · `scripts/index.js`

## 다시 불렸을 때

- 문답이 이어지는 중이면 `threads/` 의 실을 먼저 읽는다. 앞에 물은 것을 또 묻지 않는다.
- 같은 파일이 다시 오면 `.v2` 로 들어간다. 앞 카드를 고칠지 새 카드를 낼지 **사람에게 묻는다.**
- 확정된 카드를 고치라 하면 값을 덮어쓰지 않는다. 새 카드를 내고 앞 카드를 `void` + `supersedes` 로 잇는다.

## 걸리는 자리

| 일 | 하는 것 |
|---|---|
| 첨부는 없고 말만 왔다 | 파일을 청한다. 말만으로 카드를 만들지 않는다 (메모면 카드 N) |
| 파일이 안 열린다 | 들이기는 그대로 두고(원본은 남는다) "못 읽음"을 표에 적고 사람에게 형식을 묻는다 |
| `data-reader` 가 실패했다 | 한 번 다시 띄운다. 또 실패하면 `peek.js` 결과로만 표를 만들고 "전수 못 읽음"을 카드 한계에 적는다 |
| 자료 방 글이 막혔다 | 막은 이유 한 줄이 온다. 그 자리를 고치고 다시 보낸다. 우회하지 않는다 |
| `index.js` 가 실패했다 | 머리말이 깨진 카드가 있다는 뜻이다. stderr 의 카드를 고치고 다시 돌린다 |
