# review — 다른 문맥의 검토

## 언제

- 다른 스킬이 산출물을 사람에게 내기 직전 (research · patent · paper · report · intake)
- 사람이 직접 "검토해 달라" 할 때

## 왜 다른 문맥인가

같은 문맥에서의 자기 검토는 자기가 만든 오류를 지나친다. 앞선 실험에서 문맥을 끊은 검토 한 번이
오류 셋을 잡았고, 값은 $1.69 였다. 그러니 **만드는 자리와 보는 자리를 나눈다.**

그래서 `reviewer` 를 부를 때 **만든 과정의 설명을 넘기지 않는다.** 파일 경로와 끝 조건만 준다.
"이렇게 만들었으니 봐 달라"고 말하면 검토가 그 설명을 따라가고, 나눈 값이 사라진다.

## 하는 일

### 1. 끝 조건을 정한다

무엇이 맞아야 통과인가. 스킬마다 다르다:

| 부른 스킬 | 끝 조건 |
|---|---|
| intake | `reading.md` 의 이상 자리 수 = 카드 "한계" 항목 수 |
| research | 결론의 문장마다 출처 번호가 있고, 그 출처가 열린다 |
| patent | 선행 문헌이 실재하고, 차이가 청구 후보마다 있다 |
| paper | 절마다 근거 카드가 있고, 번호가 실재하며 status 가 valid |
| report | 숫자마다 카드 출처가 있고, 그 카드의 값과 같다 |

사람이 직접 청했는데 끝 조건이 없으면 "출처가 실재하는가" 하나로 본다.

### 2. `reviewer` 를 부른다

넘기는 것: **산출물 경로 · 과제 폴더 · 끝 조건 · 원본이 있는 자리.** 그것뿐이다.

### 3. 판정을 받는다

판정 파일은 `<산출물>.review.md` 에 남는다. 산출물마다 하나씩 있어야 한다.

| 판정 | 다음에 하는 것 |
|---|---|
| 통과 | 사람에게 낸다 |
| 불통과 | 짚은 자리를 만든 에이전트에게 되돌려 고친다. 사람에게 내기 전에 |
| 검증 불가 | 무엇을 왜 못 봤는지와 함께 **사람에게 알린다.** 통과처럼 다루지 않는다 |

두 번째도 불통과면 고치기를 멈추고 사람 판단을 청한다. 세 번째 시도는 대개 같은 자리를 맴돈다.

## 사람이 정하는 자리

없다. 검토 자체는 관문이 없다 — 검토를 거친 산출물이 사람 관문으로 간다.

## 부르는 것

`reviewer` 하나. 다른 에이전트를 부르지 않는다.

## 다시 불렸을 때

고친 판이면 앞 `.review.md` 경로를 함께 넘긴다. `reviewer` 가 **짚었던 자리가 실제로 고쳐졌는지**부터 본다.
판정 파일은 덮어쓰지 않고 절이 더해진다.

## 걸리는 자리

| 일 | 하는 것 |
|---|---|
| 산출물이 없다 | 검토를 부르지 않는다. 만드는 쪽으로 되돌린다 |
| 검토가 오래 걸린다 | 백그라운드로 띄우고 그 턴은 "검토 중"으로 끝낸다 |
| 판정이 "검증 불가" 다 | 사람에게 그대로 알린다. 원본을 붙여 다시 부를 수 있으면 한 번 다시 부른다 |
| 사람이 "검토 건너뛰자" 한다 | 건너뛴다. 다만 산출물에 "검토 없이 나감"을 적고 그 사실을 말한다 |
