# patent — 특허

## 언제

`/특허` 방. 또는 본방에서 PL 이 특허 말을 꺼낼 때.

## 하는 일 — 네 걸음

### 1. 청구 후보를 카드에서 뽑는다

`charter.md` 의 목적·목표와 `index.json` 의 카드를 훑어 후보를 만든다.

**후보마다 근거 카드 번호가 있어야 한다.** 카드 없는 후보는 올리지 않는다 —
근거 없는 청구는 나중에 무너지고, 무너질 때 돈이 든다.
카드가 `draft` 면 후보로 쓰지 않고 "카드가 아직 확정 전"이라고 적는다.

후보를 방에 보인다:
```
청구 후보 <N>개
1. <한 줄> — 근거 [E-0007, E-0012]
2. …
```

### 2. 조사 범위를 허락받는다

```
범위: <기술 분야> · <기간> · <나라>
이 범위로 선행을 볼까요?
```
범위를 사람이 정한다. 넓히면 시간이 들고 좁히면 놓친다 — 그 판단은 사람 몫이다.

### 3. 선행을 조사한다 (백그라운드)

`patent-analyst` 를 백그라운드로 띄우고 그 턴은 "시작했습니다"로 끝낸다.
넘기는 것: 후보 목록(근거 카드와 함께) · 허락받은 범위 · 과제 폴더 · 산출 경로 `patent/prior-art.md` ·
끝 조건("선행 문헌이 실재하고, 차이가 후보마다 있다").

끝나면 `reviewer` (다른 문맥) → `patent/prior-art.md.review.md`.

### 4. 전략을 낸다 — 세 갈래 이하

`patent/strategy.md` 는 **주 세션이 쓴다.** 에이전트는 사실만 냈다.

```
---
date: <날짜>
based_on: patent/prior-art.md
---
## 갈래 1 <이름>
   무엇을 청구하나 · 근거 카드 · 걸리는 선행 · 이 갈래의 값과 위험
## 갈래 2 …
## 갈래 3 …
## 비교      표: 갈래 · 강한 자리 · 약한 자리 · 필요한 추가 실험
## 권하는 것  하나를 골라 까닭 세 줄
```

**`patent/prior-art.md` · `patent/strategy.md` · 검토 판정 파일을 방에 첨부한다.** 경로는 옆에 (ADR-020).

**세 갈래를 넘기지 않는다.** 넷을 넘으면 사람이 고르지 못하고 판단이 미뤄진다.
갈래마다 "이 갈래를 택하면 무엇이 더 필요한가"를 적는다 — 대개 실험이고, 그것이 일정으로 간다.

## 사람이 정하는 자리

- **조사 범위** (기술 분야 · 기간 · 나라)
- **청구 방향** — 갈래 하나 고르기

## 부르는 것

`patent-analyst` (선행) · `researcher` (배경 기술이 더 필요할 때) · `reviewer` (검토) · `scripts/find.js`

## 다시 불렸을 때

`patent/prior-art.md` 를 읽고 **새 범위·새 후보만** 조사한다. 앞 조사를 지우지 않는다.
사람이 갈래를 골랐으면 `strategy.md` 에 `## 고른 갈래 <날짜>` 를 적고, 필요한 추가 실험을
`schedule` 로 넘겨 일정에 올린다.

## 하지 않는 것

등록 가능성·침해 여부를 판정하지 않는다. 사실과 차이를 낼 뿐이고, 판단은 사람과 변리사가 한다.
문헌 번호를 지어내지 않는다.

## 걸리는 자리

| 일 | 하는 것 |
|---|---|
| 카드가 아직 없다 | 후보를 만들지 않고 "들이기가 먼저"라고 말한다 |
| 선행이 우리 것과 똑같다 | 가장 앞에 적는다. 감추면 나중에 더 크게 든다 |
| 검색이 안 됐다 | 그 사실을 전략 맨 앞에 적는다. 못 본 채로 "선행 없음"이라 하지 않는다 |
| 갈래가 넷 이상 보인다 | 비슷한 것을 묶어 셋으로 줄이고, 묶은 까닭을 적는다 |
