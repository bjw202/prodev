# retro — 회고

## 언제

사람이 돌아보자고 할 때. **cron 은 없다 — 사람이 부른다.**

`brief` 와 다른 점: 브리핑은 **오늘 무엇이 있나**를 말하고, 회고는 **무엇이 되풀이됐나**를 말한다.
`journal` 과 다른 점: 일지는 **적고**, 회고는 그 적힌 것을 **읽는다.**

**여기가 관찰형 진화가 실제로 도는 자리다.** 봇은 반복을 세지 않는다 (카운터도 상태 파일도 없다).
일지에 한 줄씩 쌓아 두고, **회고가 그것을 읽다가 알아챈다.** 읽는 시점을 정하지 않으면 아무도 안 읽는다.

## 무엇을 읽나

```
journal/*.md                     되풀이된 말 · 미해결 · 다음 할 일
bots/<봇>/find.log               못 찾은 물음 (건수 0 인 줄)
cards/*.md · <산출물>.review.md  불통과 판정
```

**대화 DB 가 없어도 돈다.** 일지 파일과 `find.log` 만으로 넷을 채운다.
기간은 사람이 말한 대로. 안 말하면 **최근 2주**로 잡고 그 범위를 첫 줄에 밝힌다.

## 하는 일 — 넷을 낸다

### 1. 되풀이된 것

같은 일을 몇 번 했나. 사람이 같은 지적을 몇 번 했나.
일지의 `## 되풀이된 말` 절과 `## 다음 할 일` 이 재료다.

### 2. 막힌 것

훅에 걸린 것 · 검토 불통과 · **못 찾은 물음** (`find.log` 에서 건수가 0 인 줄).

### 3. 굳힐 후보 — 어디로 갈 것인가

| 갈래 | 가는 곳 |
|---|---|
| 규칙 (문체 · 어휘 · 하지 말 것) | `house.md` |
| 양식 (보고 골격 · 절 제목 · 길이) | `templates/` |
| 방법 (분석 절차 · 배치 만드는 법) | `analysis/methods/` |
| 별칭 (현장 말 ↔ 자료의 말) | 카드의 `aliases` |

**후보를 내기만 한다. 굳히는 것은 사람이 "앞으로" 라고 말할 때다.**

### 4. 스킬이나 에이전트가 필요해 보이는 것

**가장 비싼 제안이다** — PR 이 필요하고 되돌리기 어렵다. 그래서 관문이 있다.

**판별 넷을 통과한 것만 쓴다:**

| 물음 | 예라면 | 왜 |
|---|---|---|
| 결정을 바꾸는 **숫자**가 나오나? | 스크립트로 | 재현과 검수. 틀려도 아무도 모르는 것을 막는다 |
| **시키지 않아도** 그 자리가 열려야 하나? | 스킬로 | 스킬이 사는 것은 능력이 아니라 **타이밍**이다 |
| 출력이 커서 **대화를 덮나**? | 서브에이전트로 | 문맥 격리 |
| 셋 다 아니다 | **쓰지 않는다** | 그냥 비서가 하면 된다. 막는 규약이 있으면 그 규약을 푼다 |

**"데이터로는 왜 안 되는가"에 답하지 못하면 제안하지 않는다.**
통과한 것이 없으면 **"없음"** 이라고 쓴다. 채우려고 만들지 않는다.

## 근거 없는 항목은 쓰지 않는다

**회고의 가장 큰 위험은 봇이 패턴을 지어내는 것이다.** "이런 게 반복됐습니다" 는 그럴듯하게 쓰기 쉽다.

항목마다 근거를 단다 — **일지 날짜 · `find.log` 줄 · 카드 번호 · 파일 경로** 중 하나.
근거를 못 대면 **그 항목을 지운다.** 넷이 다 비면 "이 기간에는 근거로 댈 것이 없습니다" 라고 말한다.
`researcher` 의 "출처 없는 문장 금지" 와 같은 정신이다.

## 제안 글에 들어가는 셋

굳힐 후보와 장치 제안은 **셋이 다 있어야** 사람이 판단할 수 있다:

```
(a) 원본 경로 — 어디서 나온 이야기인가
(b) 바꿀 문장 — house.md 나 templates/ 에 실제로 들어갈 줄
(c) 까닭 — 왜 이것이 굳어야 하나 (근거와 함께)
```

(b) 를 비우고 "문체 규칙을 정하시죠" 라고만 하면 사람이 대신 문장을 짜야 한다. 그러면 회고가 일을 안 한 것이다.

## 내는 꼴

본방에 올린다. 넘치면 파일로 옮겨 첨부하고 경로를 옆에 준다.

```
회고 <기간>  (근거: 일지 <N>개 · find.log <N>줄)

1. 되풀이된 것
   - <무엇> (<일지 날짜> · <일지 날짜>)
2. 막힌 것
   - <무엇> (<find.log 줄> 또는 <판정 파일 경로>)
3. 굳힐 후보
   - [규칙|양식|방법|별칭] <한 줄>
     (a) <원본 경로>  (b) <들어갈 문장>  (c) <까닭>
4. 스킬·에이전트 후보
   - <무엇> — 판별: <어느 물음에 예인가> · 데이터로 안 되는 까닭: <한 줄>
   또는: 없음
```

## 사람이 정하는 자리

- **굳힐지 말지.** 봇은 제안까지만 한다. 사람이 "앞으로" 라고 말해야 굳는다.
- **스킬·에이전트를 만들지 말지.** 만드는 것은 prodev 세션이고 worktree + PR 이다. **봇이 만들지 않는다.**

## 부르는 것

`scripts/find.js` (근거 대조) · `scripts/chat.js` (대화가 있을 때만). 에이전트는 부르지 않는다.

회고는 **판단**이라 서브에이전트로 넘기지 않는다. 넘기면 근거를 못 대는 항목이 섞여 들어온다.

## 다시 불렸을 때

- **앞 회고에서 사람이 이미 물리친 후보는 다시 올리지 않는다.** 같은 것을 또 올리면 회고가 시끄러워진다.
- 기간을 넓히라 하면 넓힌 범위를 첫 줄에 다시 밝힌다.
- "그 제안 자세히" 라 하면 그 항목의 근거를 원문으로 보인다 (일지 줄 · `find.log` 줄 그대로).

## 걸리는 자리

| 일 | 하는 것 |
|---|---|
| 일지가 며칠 없다 | 없는 날을 말하고 있는 날만 읽는다. 없는 날을 메우지 않는다 |
| `find.log` 가 없다 | 2번을 판정 파일과 일지로만 채우고 "못 찾은 물음은 못 봤다"고 밝힌다 |
| 되풀이가 두 번뿐이다 | 올린다. 다만 **몇 번인지 그대로 적는다.** "여러 번" 으로 부풀리지 않는다 |
| 후보가 하나도 없다 | "없음" 이라고 낸다. 빈 회고도 기록이다 |
| 사람이 그 자리에서 "앞으로 그렇게 해" 라고 한다 | 회고를 멈추고 굳히기로 간다 — 범위를 한 줄 되묻고 자리에 적는다 (CLAUDE.md 의 굳는 길) |
| 봇이 스스로 스킬을 만들고 싶어진다 | 만들지 않는다. 제안만 하고 사람에게 넘긴다 |
