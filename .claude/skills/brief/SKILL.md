# brief — 아침 브리핑

## 언제

cron 이 08:00 에 `@TO(비서)` 로 부를 때. 그리고 사람이 "오늘 뭐 있지" 하고 물을 때.

`schedule` 과 다른 점: 일정은 한 갈래고, 브리핑은 **네 갈래를 한 자리에 모은 것**이다.
`journal` 과 다른 점: 브리핑은 읽어서 말하고, 일지는 써서 남긴다.

## 왜 열 줄인가

아침에 읽히지 않는 브리핑은 없느니만 못하다. 네 갈래를 각각 두세 줄로 줄이면
사람이 한 번에 훑고 하루를 시작한다. 자세한 것은 **파일로 옮겨 첨부하고** 경로를 옆에 적는다 (ADR-020).

## 모으는 넷

| 갈래 | 어디서 | 무엇을 |
|---|---|---|
| 어제 있었던 것 | `journal/<어제>.md` | 결정 · 올라온 것 |
| 이번 주 일정 | `schedule.md` | 이번 주 기한 |
| 열린 질문 | `bots/<봇>/threads/*` | 사람 답을 기다리는 물음 |
| 밀린 것 | `schedule.md` | 기한이 지났는데 완료가 아닌 줄 |

일지가 없으면 그저께 것을 본다. 그것도 없으면 "일지 없음"이라고 말한다 — 조용히 건너뛰지 않는다.

## 꼴

```
<날짜> 아침입니다.
어제: <두 줄 — 결정과 올라온 것>
이번 주: <두 줄 — 기한과 담당>
기다리는 답: <한 줄씩, 누구의 무엇 — threads 경로>
밀린 것: <한 줄씩, 없으면 "없음">
```

밀린 것을 마지막에 두되 반드시 적는다. 없으면 "없음"이라고 명시한다.

## 사람이 정하는 자리

없다.

## 부르는 것

없다. 파일만 읽는다 (`journal/` · `schedule.md` · `threads/`).
대화를 훑는 것은 `journal` 의 일이다. 브리핑은 이미 파일에 남은 것만 모은다.

## 다시 불렸을 때

같은 날 두 번째 브리핑이면 앞 브리핑 뒤에 **바뀐 것만** 말한다.
"아침에 드린 것에서 바뀐 것: …" 로 시작한다. 같은 열 줄을 되풀이하지 않는다.

## 걸리는 자리

| 일 | 하는 것 |
|---|---|
| 어제 일지가 없다 | 그저께로 물러난다. 며칠 비었는지 말한다 |
| 열린 실이 열 개 넘는다 | 오래된 것 셋만 보이고 나머지는 수만 말한다 |
| 과제가 막 시작해 아무것도 없다 | "아직 쌓인 것이 없습니다" 와 헌장의 다음 마디를 말한다 |
| 사람이 아니라 cron 이 불렀다 | 본방에 올린다 |
