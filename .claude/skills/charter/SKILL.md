# charter — 과제 발의

## 언제

본방에서 사람이 새 과제를 열자고 할 때. 그리고 이미 있는 헌장을 고칠 때.

## 왜 하나씩 묻나

발의는 사람의 머릿속에 있는 것을 꺼내는 일이다. 여섯 가지를 한꺼번에 물으면 사람은 셋만 답하고
나머지는 흐려진다. 흐린 채로 굳은 헌장은 나중에 판정의 기준이 되지 못한다.
그래서 **한 번에 하나**, 앞 답을 받아 다음 물음을 다듬는다.

**한 글에 물음표는 하나다.** 재생에서 한 글에 셋씩 나갔다.
물음이 둘 이상 떠오르면 가장 앞의 것만 보내고 나머지는 다음 턴으로 미룬다.
"그리고 하나 더" 도 물음 하나다 — 세는 것은 물음표가 아니라 **사람이 답해야 하는 것의 수**다.
곁들이는 말(되짚기 · 보기 · "모르시면 넘어가도 됩니다")은 물음이 아니니 함께 보내도 된다.

## 하는 일

### 1. 이미 있나 본다

`charter.md` 가 있으면 **새로 만들지 않는다.** 읽고 "이 과제가 이미 있습니다" 로 시작해,
사람이 고치자는 자리만 고친다.

### 2. 여섯을 하나씩 묻는다

| 순서 | 묻는 것 | 흐리면 다시 묻는 자리 |
|---|---|---|
| 1 | 목적 — 왜 하나 | "개선"만 있고 무엇을 개선하는지 없을 때 |
| 2 | 목표 — 무엇이 얼마나 되면 된 건가 | 숫자와 단위가 없을 때 |
| 3 | 일정 — 언제까지, 중간 마디는 | 끝날만 있고 마디가 없을 때 |
| 4 | 인원 — PL 은 누구, 과제원은 누구 | 이름이 없을 때 (PL 이름은 결재 대조의 기준이다) |
| 5 | 예산 — 얼마, 무엇에 | 없으면 "없음"으로 적는다. 비워 두지 않는다 |
| 6 | 판정 기준 — 무엇을 보고 성공이라 하나 | 목표와 같은 말이면 "어떻게 잴 건가"를 다시 묻는다 |

답이 오면 그 자리에서 짧게 되짚어 준다 ("목표: 수율 90 → 93%, 12월 말까지"). 사람이 고칠 자리를 만든다.

### 3. 헌장 초안을 낸다

`charter.md`:
```
---
project: <과제 이름>
pl: <PL 이름>            결재 대조의 기준이 이 줄이다
members: [<과제원>]
started: <날짜>
status: draft            draft | active | closed
---
## 목적
## 목표          숫자와 단위. "무엇이 얼마나"
## 판정 기준     무엇을 어떻게 재나
## 일정 요약     마디와 날짜. 자세한 것은 schedule.md
## 인원          이름 · 역할
## 예산          얼마 · 무엇에 (없으면 "없음")
## 범위 밖       이번에 안 하는 것
```

### 4. 일정 뼈대를 낸다

`schedule.md` 는 표 하나다: 항목 · 기한 · 담당 · 상태 · 바뀐 날 · 왜.
헌장의 마디를 그대로 옮겨 첫 줄들을 만든다. 없는 일을 지어 채우지 않는다.

**사람이 말하지 않은 줄을 넣지 않는다.** 재생에서 사람이 정한 적 없는 일정 줄이 들어갔다.
"보통 이쯤에는 중간 점검을 한다" 같은 상식으로 채우면, 사람은 자기가 정한 것과
비서가 지어낸 것을 나중에 가리지 못한다. 필요해 보이면 **줄을 넣지 말고 묻는다.**
결재 전에는 헌장의 마디에서 곧장 옮긴 줄만 있다.

### 5. 방을 연다 · git 을 연다

```
node scripts/setup.js rooms <과제>     방 둘을 만들고 봇을 참여시킨다
git init                                과제 저장소가 아직 git 이 아니면
```
방 둘은 본방 `prodev-<과제>` 와 `prodev-<과제>/files` 다 (ADR-022).
사람에게 한 줄로 알린다: **"말은 아무 데서나, 파일은 files 에."**

### 6. PL 결재를 청한다

본방에 헌장 요약을 올리고 PL 에게 결재를 청한다. 결재가 오면 `status: active` 로 바꾸고 커밋한다.
결재 전에는 `draft` 그대로 둔다.

## 사람이 정하는 자리

- 여섯 항목의 답 (전부)
- 새 주제·방을 열지 말지
- **헌장 결재 — PL 만.** 결재 글의 작성자가 헌장의 `pl` 과 같은지는 기계가 본다.

## 부르는 것

`scripts/setup.js rooms` · `git`. 에이전트는 부르지 않는다.

## 다시 불렸을 때

`charter.md` 를 읽고 사람이 짚은 자리만 고친다. 바뀐 줄은 `## 이력` 에 날짜와 까닭을 남긴다.
PL 이 바뀌면 `pl:` 줄을 고치고 그 사실을 본방에 알린다 — 결재 대조의 기준이 바뀌는 일이다.
헌장이 바뀌어 일정이 흔들리면 `schedule` 로 넘어가 카드 D 를 남긴다.

## 걸리는 자리

| 일 | 하는 것 |
|---|---|
| 사람이 여섯을 한꺼번에 쏟았다 | 받아 적고, 흐린 것만 골라 되묻는다. 순서를 고집하지 않는다 |
| PL 이 자기 이름을 안 준다 | 봉투의 sender 를 쓰되 "PL 을 <이름> 으로 적었습니다" 로 확인받는다 |
| 방 만들기가 실패한다 | 헌장은 그대로 두고, 실패한 방 이름과 까닭을 본방에 알린다. 헌장을 되돌리지 않는다 |
| 같은 이름의 과제가 이미 있다 | 새로 만들지 않는다. 어느 것인지 사람에게 묻는다 |
