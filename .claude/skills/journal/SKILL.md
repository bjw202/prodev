# journal — 하루 일지

## 언제

cron 이 18:30 에 부를 때. 사람이 "정리해 둬" 할 때. 그리고 압축 직전.

`brief` 와 다른 점: 브리핑은 읽어서 말하고, **일지는 써서 남긴다.**
남기는 까닭은 하나다 — 세션은 상주하지 않는다. 껐다 켜면 파일에서 되살아난다.
그날 안 적힌 것은 다음 날 없는 것이 된다.

## 하는 일

### 1. 그날 대화를 훑는다

방마다:
```
node scripts/chat.js since <방> <어제 마지막 id> --limit 200
```
`bots/<봇>/rooms.json` 에 방마다 처리한 마지막 id 가 있다.

### 2. 네 갈래로 가른다

| 갈래 | 무엇이 여기 오나 |
|---|---|
| 결정 | 사람이 정한 것. 누가 · 무엇을 · `#message_id` |
| 미해결 | 물었는데 답이 안 온 것. 답이 갈린 것 |
| 다음 할 일 | 내일 이어야 하는 것. 누가 하는지까지 |
| 올라온 것 | 첨부 · 카드 번호. **카드가 안 된 첨부는 따로 적는다** |

카드 없는 첨부를 따로 적는 까닭: 그것이 다음 날 들이기의 목록이 된다. 안 적으면 잊힌다.

### 3. 파일로 쓴다

`journal/<YYYY-MM-DD>.md`:
```
# <날짜>
## 결정          누가 · 무엇을 · #id
## 미해결        무엇이 · 누구의 답을 기다리나 · threads 경로
## 다음 할 일    누가 · 무엇을 · 언제까지
## 올라온 것     파일 · 방 · 카드 번호
## 카드 없는 첨부  파일 · 방 · #id · 왜 아직 카드가 아닌가
```

### 4. 커밋한다

```
git add journal/<날짜>.md && git commit
```

## 압축 직전에 불렸을 때

인수인계서(`handoff-compact.md`)는 훅이 따로 만든다. 여기서는 **일지만** 쓴다.
둘이 겹치면 어느 쪽이 최신인지 갈린다.

## 사람이 정하는 자리

없다.

## 부르는 것

`scripts/chat.js since` · `git`. 에이전트는 부르지 않는다.

## 다시 불렸을 때

그날 일지가 이미 있으면 **덮어쓰지 않는다.** 마지막으로 적은 뒤의 대화만 훑어 절에 줄을 더한다.
사람이 "그것도 넣어줘" 하면 해당 절에 한 줄 더하고 커밋한다.

## 걸리는 자리

| 일 | 하는 것 |
|---|---|
| 대화 DB 를 못 연다 | 일지를 비우지 않는다. 그날 만진 파일과 커밋에서 아는 것만 적고 "대화 못 읽음"을 맨 위에 적는다 |
| `rooms.json` 에 방이 없다 | `node scripts/chat.js rooms` 로 방을 다시 찾는다 |
| 그날 아무 일도 없었다 | 빈 일지를 쓴다. "없음"도 기록이다 — 며칠 비었는지 세는 근거가 된다 |
| 며칠 치가 밀렸다 | 날짜마다 파일 하나씩 만든다. 한 파일에 몰아 적지 않는다 |
