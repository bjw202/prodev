# prodev — 설계 결정 기록 (ADR)

한 결정에 한 절. 서식: 상태 · 맥락 · 결정 · 까닭(근거가 있으면 경로) · 결과. 뒤집으면 지우지 않고 상태를 바꾸고 새 절을 더한다.

---

## ADR-001 봇은 하나다
**상태** 확정 (사람, 2026-09-09 · 09-10)
**맥락** crew 는 봇 다섯이었다. 순차형 과제에서 같은 품질에 15~19배를 물었고, 사실 셋이 봇 계층을 넘으며 떨어졌다 (`../crew/EVOLUTION.md` S3 부록·정정). 고영혁 팀은 봇 열둘이지만 사람 하나에 병렬 갈래 과제였고 계측이 없다 (`../meta/prodev-review/notes/external-evidence-gonnector.md`).
**결정** 과제마다 상주 비서 하나. 전문 일은 비서 안의 서브에이전트. 별도 봇은 "며칠 이어지고 사람이 직접 말하고 싶고 본방과 섞이면 불편할 때"만 뗀다.
**결과** 기억이 한 곳. 계층 손실 없음. 대신 세션이 한 번에 한 턴이라 긴 일은 백그라운드로 (ADR-009).
**바뀐 자리 (ADR-022)** 갈래 방은 미리 열려 있지 않다. 방은 둘뿐이므로, 봇을 뗄 때 그 방을 새로 연다.

## ADR-002 알갱이는 실험 한 건(카드)이다
**상태** 확정 (사람, 2026-09-10)
**맥락** 파일 하나 = 카드 하나면 한 실험의 파일 넷이 흩어진다. 사람이 말하는 단위는 실험이다.
**결정** 카드 하나가 파일 여럿을 거느린다. 파일마다 사이드카(열·단위·행 수·SHA-256)는 둔다.
**결과** 카드에 `files`·`source_msgs` 칸. 색인은 카드 기준.

## ADR-003 과제마다 git 저장소 하나
**상태** 확정 (사람, 2026-09-10)
**맥락** crew 의 방 저장소 방식이 이력과 되돌리기를 줬다.
**결정** 과제 폴더 = git 하나. 원격은 선택. 봇의 자기 상태(handoff·threads·rooms.json)는 저장소 밖(봇 폴더).
**결과** 서브에이전트는 커밋하지 않는다. 주 턴만 경로 지정 커밋.

## ADR-004 위키는 카드가 valid 될 때마다 즉시 갱신한다
**상태** 확정 (사람, 2026-09-10) · **재는 조건 붙음**
**맥락** crew 에서 위키·색인 반영이 archivist 값의 4분의 3($36/$47)이었고 어느 봇도 읽지 않았다. 검토는 주 1회를 권했다.
**결정** 사람이 즉시 갱신을 택했다. 대신 값을 재고 읽힘을 잰다: 들이기 한 건의 위키 비용(예측 ≤ $0.5), `find.log` 에서 위키 층이 답한 비율. 4주 연속 0 이면 시점을 다시 정한다.
**결과** 갱신 범위는 카드 tags 에 걸리는 페이지의 "지금 아는 것"과 "이력" 뿐. 페이지 전체를 다시 쓰지 않는다.

## ADR-005 대화는 fetch_history 가 아니라 DB 를 직접 읽는다
**상태** 확정 (사람, 2026-09-10)
**맥락** `fetch_history` 는 최근 N 개를 자른 뒤 거른다(OD-9). 말로는 못 찾는다. 대화 DB 는 서버가 켜진 채로 읽기 전용으로 열린다 (실측, `../meta/prodev-review/plans/proto/chat.js`).
**결정** `scripts/chat.js` (search · around · since · tail · show · rooms). 봇은 봉투의 `message_id` 로 자기 자리를 안다.
**결과** minidiscord 서버 수정(FTS·검색창)은 사람 편의로 미룬다. 여러 낱말은 AND.

## ADR-006 서버 커서를 믿지 않는다
**상태** 확정 (검토 2026-09-10)
**맥락** 게이트웨이는 소켓에 보낸 순간 `last_delivered_id` 를 올린다. 턴 도중 압축·사망이면 그 글은 다시 오지 않는다.
**결정** 봇 폴더 `rooms.json` 에 방마다 "내가 처리한 마지막 id". 깨어날 때와 매 턴 첫머리에 `chat.js since` 를 방 전부에 돌린다.
**결과** 놓친 @TO 0 이 검수 항목이 된다.

## ADR-007 오토컴팩트는 켜 두고, 직전에 인수인계서를 만든다
**상태** 확정 (사람, 2026-09-10)
**맥락** 압축은 100만 토큰을 1만으로 깎는다(사람이 인용한 사례). `PreCompact` 는 문맥을 못 넣고, 넣는 자리는 `SessionStart(compact)` 의 `additionalContext` 다. 훅 안에서 `claude -p` 가 돈다 (실측 haiku 7초).
**결정** PreCompact 훅이 기록 꼬리 → `claude -p` → `handoff-compact.md`. SessionStart 가 맨 앞에 싣는다. 행동 전 handoff 저장은 그대로 두어 안전망 둘.
**결과** 대화 원본은 minidiscord DB 라 인용 글의 "백업이 뒤 기록을 지운다" 경고는 해당 없다.

## ADR-008 확정은 기계가 판별한다
**상태** 확정 (검토 2026-09-10)
**맥락** "세라"는 지침으로 세 세대 실패했다. 봇이 머리말에 `confirmed_at` 을 적고 훅이 숫자만 보면 같은 실패다.
**결정** pre-reply 훅이 DB 를 열어 그 글이 사람 글 · 같은 과제의 들이기 방 · 확정 어휘 · 첨부 글보다 뒤 · 직전 봇 글에 같은 카드 번호인지 다섯을 본다. DB 를 못 열면 자료 방만 fail-closed.
**결과** 확정 어휘를 사람에게 고정해 준다 ("맞으면 '확정'이라고 답해 주세요").
**바뀐 자리 (ADR-022)** 조건 ② 의 방 이름은 `/files` 다. 관문의 방아쇠도 방이 아니라 **카드 공지 글의 `[카드]` 표식**이고, DB 를 못 열면 카드 공지와 `[발송]` 이 fail-closed 다. 나머지 넷은 그대로.
**보충 (2026-09-10, T3.3 R2 재생 중)** 확정 어휘는 **봉투를 벗긴 본문의 맨 앞**에서 본다. 사람 글은 언제나 봉투로 시작하므로(`@TO(prodev-<과제>-비서) 확정`), 원문 맨 앞에서 어휘를 찾으면 확정이 영영 안 된다. R2 재생 들이기 #19 에서 실제로 막혔다. `^(\s*@(TO|CC)\([^)]*\)\s*)+` 를 떼고 나서 어휘를 본다 (줄바꿈도 봉투 뒤 공백으로 친다). 나머지 넷은 그대로다. 어휘 자체는 좁게 유지한다 — "네" 는 여전히 확정이 아니다.

## ADR-009 세션은 한 턴, 긴 일은 백그라운드
**상태** 확정 (검토 2026-09-10)
**맥락** 세션 하나는 알림을 순서대로 한 턴씩 처리한다. 3분 리서치가 PL 의 물음을 막는다.
**결정** research·patent·paper·report·큰 파일은 백그라운드 서브에이전트. 그 턴은 "시작했습니다" 한 줄. 결과는 파일로, 다음 턴에 알림. 한 턴에 들이기 문답은 한 건.
**결과** 서브에이전트는 커밋하지 않는다. 그림·임시는 `<과제>/tmp/`.

## ADR-010 세션은 상주하지 않는다. 켤 때마다 파일에서 되살아난다
**상태** 확정 (사람, 2026-09-10)
**맥락** 검토는 매일 재시작을 권했다. 사람은 "주간에 필요시 켠다. 껐다 켜도 문맥을 읽고 되살아나야 한다"고 했다.
**결정** 요건은 "매일 재시작"이 아니라 "언제 켜도 되살아남". session-start 가 열린 실·rooms.json·헌장·일정·어제 일지·마지막 일지 날짜를 싣고, 비서가 `chat.js since` 로 꺼져 있던 동안을 전 방에서 따라잡는다.
**결과** cron 브리핑은 켜져 있을 때만 닿는다. 꺼져 있었으면 다음에 켤 때 일지부터 쓴다.

## ADR-011 검토는 다른 문맥에서
**상태** 확정 (crew 실측 2026-09-09)
**맥락** 주 세션 + 검토 세션($1.69)이 오류 셋을 잡았고, 검토 없는 싱글 셋은 첫 오류가 남았다. 문헌(OpenAI LLM Critics)도 같다.
**결정** `reviewer` 서브에이전트가 사람 결재 전 산출물마다 한 번. 스스로 센 숫자를 다시 세고 출처를 대조한다. "괜찮아 보인다"는 판정이 아니다.

## ADR-012 세는 것과 막는 것은 기계, 정하는 것은 지침
**상태** 확정 (`../meta/crew-eval/INTENT.md`)
**맥락** 분량·멘션 수를 지침으로 세게 한 것이 세 세대 실패했고 `count.js` 로 100% 맞았다.
**결정** 분량(count.js) · 확정 · 결재 · chat_id 는 훅. 색인은 index.js. 찾기 순서는 find.js. 지침은 40줄 안.

## ADR-013 제작은 `/harness:harness`, 훅과 배선은 손으로

**맥락** 하네스 스킬(v1.2.0)은 agents·skills·오케스트레이터 스킬·CLAUDE.md 포인터를 만들고, **훅·settings·MCP 배선은 만들지 않는다** (탐색 확인).

## ADR-014 캐릭터 이름 · 일기의 지혜 승격 · 봇의 성장은 안 한다

## ADR-016 찾기 순서에서 files.md 를 대화보다 먼저 본다
**상태** 확정 (meta, 2026-09-10, T1.3 착수 전)
**맥락** find.js 5층 시험에서 `particle_defects` 가 대화 층(옛 4층)에서 봇이 붙여넣은 코드 17건에 걸려 사이드카 files.md(옛 5층)에 닿지 못했다. 대화에는 코드·승인 요청 글이 섞이고, 그것을 글 형식으로 걸러 내는 규칙은 깨지기 쉽다.
**결정** 순서를 1 index · 2 카드 · 3 위키 · 4 inbox files.md · 5 대화 로 한다. 파일이 대화보다 먼저다. 대화 층은 여러 건(≤10, 최근 것부터)을 그대로 돌려주고 차례 규칙을 두지 않는다. 시험은 대화 층만 "기대 #id 가 결과 안에 든다"로 잰다.
**재는 것** VERIFICATION 의 P8 "1~3층 답한 비율"은 그대로. find.log 의 층 번호는 새 번호다.

## ADR-017 설계 문서에 자리가 없던 것 둘 — 절 작업 자리와 검토 판정 파일
**상태** 확정 (meta, 2026-09-10, T2.3)
**맥락** T2.2 에서 스킬 본문을 쓰다 설계 문서가 경로를 정해 두지 않은 자리가 둘 나왔다. ① `paper` 는 "절마다 초안 + 절마다 사람 통과"인데(B 표) 통과 전 초안과 통과한 원고가 같은 파일에 섞이면, 사람이 아직 안 본 절이 원고에 들어간다. ② PRD F8 은 "검토 판정 파일이 산출물마다 있다"를 요구하는데 그 파일이 어디 놓이는지는 어디에도 없다.
**결정** ① 절 작업 자리는 `paper/sections/<절>.md`. 사람이 절 통과를 준 것만 `paper/draft.md` 에 순서대로 모은다 — B 표의 산출 이름(`outline.md` · `draft.md` · 그림)은 그대로고, `sections/` 는 그 아래 작업 자리다. 그림은 `<과제>/tmp/` 에 그려 결재 뒤 `paper/figures/` 로 옮긴다. ② `reviewer` 의 판정은 `<산출물>.review.md` 에 둔다 (`research/수율.md` → `research/수율.md.review.md`). 산출물 옆에 있어야 어느 것에 대한 판정인지 경로만으로 서고, 산출물이 지워질 때 같이 지워진다.
**재는 것** F8 은 "산출물마다 `.review.md` 가 있다"로 센다. `docs/skill-matrix.md` 의 paper · review 행이 이 경로를 쓴다.

## ADR-018 알림 경로는 사람 계정의 세션 쿠키 + multipart 다
**상태** 확정 (meta, 2026-09-10, T3.1)
**맥락** cron 두 줄(08:00 브리핑 · 18:30 일지)과 `pre-compact` 의 "정리 중" 알림을 `Authorization: Bearer` + JSON 으로 적어 두었는데, 시험 서버(포트 3123 · 빈 DB)에 그대로 넣어 보니 안 된다. 서버는 인증을 쿠키 `md_session` 하나로만 받고(`server/src/auth.ts` 의 `requireAuth`), 글 올리기 라우트는 multipart 만 읽는다(`routes-messages.ts` 의 `req.parts()`). 잰 값: JSON+Bearer → **401** · JSON+쿠키 → **406** · multipart+쿠키 → **200**. 설계에 Bearer+JSON 이라 적은 것은 meta 의 잘못이다. 서버는 손대지 않는다 (PRD 6절 · ARCHITECTURE 11절).
**결정** 부르는 쪽을 고친다. cron 두 줄과 훅의 알림은 `-b "md_session=$PRODEV_NOTIFY_TOKEN"` + multipart 로 보낸다. `-F` 가 아니라 **`--form-string`** 이다 — `-F` 는 `@` 로 시작하는 값을 파일 경로로 읽고, 멘션은 언제나 `@TO(` 로 시작한다 (시험이 이것을 curl 26 으로 잡았다). 토큰의 이름은 `PRODEV_NOTIFY_TOKEN` 하나이고 값은 알림 계정(사람 계정)의 `md_session` 값이다. `MINIDISCORD_URL` 은 그대로 쓴다.
**봇 문맥에 두지 않는다** `setup.js` 가 만드는 `settings.json` 의 `env` 에 `PRODEV_NOTIFY_TOKEN` 을 넣지 않는다. 훅은 봇 폴더의 `.env` 또는 훅을 띄운 실행 환경에서 읽는다. 사람 계정의 토큰이 봇의 문맥에 실리면 봇이 사람인 척 글을 쓸 수 있다.
**재는 것** `test/server/setup.test.js` 가 cron 두 줄에 쿠키·`--form-string` 이 있고 `Bearer` 가 없음을 보고, **낸 줄을 그대로 서버에 쏴 200 과 남은 글**을 확인한다. `test/hooks.test.js` 가 모의 서버로 훅이 보낸 요청의 쿠키·multipart 를 확인한다.
**보충 (사람, 2026-09-10, R5 재측정 뒤)** 알림은 **둘**이다. 압축 직전(`pre-compact`)의 "문맥을 정리 중입니다. 곧 이어서 합니다." 와 압축 **직후**(`session-start`, `source: compact` 일 때만)의 "정리가 끝났습니다. 이어서 하려면 말을 걸어 주세요." 다. 까닭: 압축 뒤에는 사람이 말을 걸어야 봇이 이어서 하므로 사람이 그 시점을 알아야 한다. 껐다 켠 경우(`startup`·`resume`·`clear`)에는 올리지 않는다 — 서버가 놓친 글을 재배달하니 사람이 따로 할 일이 없다 (R5 에서 두 번 확인).
**방을 어떻게 찾나** 앞의 것이 있으면 뒤는 안 본다: ① `PRODEV_NOTIFY_ROOM` ② 봉투의 `chat_id`(PreCompact 입력에는 없다) ③ **인수인계서의 "방과 마지막 message_id" 절 첫 `chat_id`** — 하던 방이 있으면 거기가 맞다 ④ `rooms.json` 의 본방(이름에 갈래가 없는 방). 못 찾으면 **아무 데도 안 보낸다** — 갈래 방에 던지면 자료 방이 더러워진다.
**바뀐 자리 (ADR-022)** 방이 둘뿐이라 ④ 의 "이름에 갈래가 없는 방"은 접미어 `/files` 가 없는 방이다. 못 찾으면 아무 데도 안 보내는 것은 그대로다.
**한 자리에 둔다** 방 찾기·토큰·보내는 꼴은 `common/hooks/places.js` 의 `알릴방` · `알림토큰` · `알린다` 하나뿐이고 훅 둘이 그것을 부른다. 두 곳에 따로 적으면 언젠가 갈리고, 갈리면 한쪽만 조용히 안 나간다 — 이 자리에서 이미 두 번 겪었다 (URL 없음 · 방 번호 없음).

## ADR-019 파일 뿌리는 deny 하지 않는다 — 0층 불변은 0444 와 git 이 지킨다
**상태** 확정 (meta, 2026-09-10, T3.3 R1 재생 중)
**맥락** `setup.js` 가 파일 뿌리(`MINIDISCORD_BOT_FILES_DIR`)와 서버 업로드 폴더를 한 변수로 묶어 두고, 그 자리를 `Write(…/**)` · `Edit(…/**)` 로 막았다. T1.6 의 "업로드 폴더는 읽기만 (0층 불변)" 이 그대로 옮겨진 것이다. 그런데 ARCHITECTURE 11절이 정한 파일 뿌리는 **과제 저장소들의 부모**다 (봇 첨부가 뿌리 밖이면 서버가 조용히 뺀다). 그래서 과제 폴더 자체가 쓰기 금지가 됐다. R1 재생에서 봇이 헌장을 다 만들고도 `charter.md` 를 못 써 봇 폴더의 `pending-charter.md` 에 들고 있었다 (본방 #7 · #9 · #11).
**결정** 파일 뿌리는 `additionalDirectories` 로 **열기만** 하고 deny 하지 않는다. 서버 업로드 폴더(`<DATA_DIR>/uploads`)는 남의 원본이라 읽기 전용으로 두되, **그 폴더가 과제 폴더를 덮으면 넣지 않는다.** 그리고 `setup.js` 가 설정을 쓰기 전에 deny 가운데 과제 폴더를 덮는 것이 있으면 예외로 죽는다 — 조용히 못 쓰는 봇이 되느니 설치가 실패하는 편이 낫다.
**0층은 무엇이 지키나** 권한 목록이 아니라 ① `intake-copy.js` 가 들인 원본에 거는 `0444` ② git 이다. `inbox/**` 를 deny 로 좁히는 길도 있었으나 사이드카(`files.md`)는 같은 폴더에서 계속 고쳐 써야 하고 Claude Code 의 deny 규칙으로 한 파일만 빼기가 안 되므로, 0444 에 맡긴다.
**재는 것** `test/server/setup.test.js` 가 만들어진 `settings.json` 의 deny 에 과제 폴더를 덮는 항목이 0건임을, 그리고 파일 뿌리가 deny 에 없고 `additionalDirectories` 에 있음을 본다.

## ADR-020 사람이 읽을 산출물은 방에 첨부한다. 경로는 그 옆에
**상태** 확정 (사람, 2026-09-10, T3.M 뒤)
**맥락** 스킬 다섯이 산출물을 만든 뒤 방에는 경로만 적었다 (`경로: research/수율.md`). 재생에서 사람이 짚었다 — 경로만 주면 파일을 열러 가야 하고, 대개 열지 않는다. minidiscord 는 첨부를 그대로 실어 주고, 봇은 이미 첨부할 수 있다 (`MINIDISCORD_BOT_FILES_DIR` 안이면 된다. 과제 저장소는 그 안이다).
**결정** 사람이 읽을 파일 — 리서치 문서 · 검토 판정 파일 · 보고서 · 논문 절과 그림 · 브리핑이 가리키는 정리표 — 은 **방에 첨부**하고 경로는 그 옆에 적는다. 경로만 주지 않는다. 대상 스킬: `research` · `patent` · `paper` · `report` · `brief`.
**첨부하지 않는 것** 카드와 위키는 자료 방 글이 이미 6줄로 요약을 싣고 사람이 훑는 색인 노릇을 하므로 그대로 둔다 (자료 방 글에는 **원본**을 첨부한다 — 5.1 그대로). 대화 기록·색인처럼 기계가 읽는 것도 첨부하지 않는다.
**바뀐 자리 (ADR-022)** 카드와 위키를 첨부하지 않는 것은 그대로다. 다만 그것을 요약해 싣던 글은 이제 `files` 방의 **카드 공지 한 줄**(번호 · 제목 · 경로)이고, 원본은 사람이 올린 글에 이미 있으므로 다시 첨부하지 않는다.
**걸리는 자리** 첨부는 `MINIDISCORD_BOT_FILES_DIR` 뿌리 안이어야 한다. 밖이면 서버가 **조용히** 뺀다 — 그래서 그림·임시는 `/tmp` 가 아니라 `<과제>/tmp/` 에 둔다 (ADR-019 와 같은 뿌리 이야기다).

## ADR-021 rooms.json 은 방 이름표다. 놓친 글은 서버 재배달을 믿는다 (ADR-006 뒤집음)
**상태** 확정 (meta, 2026-09-10, T3.M 뒤) — **ADR-006 을 대신한다**
**맥락** ADR-006 은 게이트웨이가 소켓에 보낸 순간 `last_delivered_id` 를 올리므로 턴 도중 압축·사망이면 그 글이 다시 오지 않는다고 보고, 봇 폴더 `rooms.json` 에 "내가 처리한 마지막 id" 를 두고 매 턴 첫머리에 갱신하기로 했다. **재생 다섯(R1~R5)이 그 전제를 반증했다**: `last_seen_id` 가 끝까지 전부 0 이었는데(아무도 갱신하지 않았다) 놓친 글 다섯은 서버 재배달(`room_bots.last_delivered_id`)이 전부 가져왔다. 지침으로 시킨 갱신 걸음은 지켜지지 않았고, 지켜지지 않았는데도 검수 항목("놓친 @TO 0")은 통과했다.
**결정** (나) 를 택한다. `rooms.json` 은 **방 번호 → 방 이름 표**로만 쓴다 (`setup.js` 가 쓰고, `places.js` 가 DB 를 못 열 때 방 갈래를 아는 데 쓴다 — 지금도 그렇게 쓰고 있다). `last_seen_id` 는 아무도 갱신하지 않으므로 **믿지 않는다.** 놓친 글은 서버 재배달에 맡긴다. 매 턴 첫머리 갱신 걸음은 지침에서 뺀다.
**왜 (가) 가 아닌가** 갱신 걸음을 오케스트레이터나 journal 에 넣으면 지침이 한 줄 늘고 매 턴 비용이 는다. 그런데 그 걸음이 막는 일(재배달 실패)이 다섯 대본에서 한 번도 일어나지 않았다. **계측이 없는 것은 안 한다** (ADR-014 와 같은 결). 재배달이 실제로 글을 흘리는 것을 보면 그때 (가) 로 돌아간다 — 그 자리는 "놓친 @TO 0" 검수 항목이 지킨다.
**남는 것** `last_seen_id` 칸은 `setup.js` 가 0 으로 쓰는 채로 둔다. 지우면 `rooms.json` 을 읽는 자리가 모두 바뀐다. 대신 그 값을 **읽는 코드는 없다** — 이 ADR 이 그 약속이다.
**바뀐 자리 (ADR-022)** `rooms.json` 이 아는 방 갈래는 이제 둘(본방 · `/files`)뿐이다. 방 이름표라는 쓰임은 그대로.

## ADR-022 과제 하나 = 방 둘 (본방 · files)
**상태** 확정 (사람, 2026-09-10 저녁)
**맥락** 3단계 재생 다섯을 돌린 뒤, 옛 방 묶음(본방 + 갈래 여섯)에 실제로 오간 글을 셌다: **본방 60 · 들이기 23 · 리서치 14 · 자료 1 · 특허 0 · 논문 0 · 보고 0.** 갈래 방 셋(특허 · 논문 · 보고)은 한 글도 받지 못했고, 카드 방은 한 글이었다. 봇은 방이 아니라 `PRODEV_PROJECT` 로 과제를 알므로(ADR-012) 방을 나눠도 봇이 얻는 것이 없다. 카드 방의 색인 노릇은 아무도 읽지 않았고, 봇 자신도 `find.js` 와 색인 파일로 찾는다. 그리고 비서 지침의 "갈래 방은 사람이 허락해야 연다"와 `setup.js` 의 "방을 다 만든다"가 서로 어긋나 있었다 — 지침은 열지 말라 하고 설치는 미리 다 열었다.
**결정** 과제 하나에 방은 **둘**이다. 본방 `prodev-<과제>` (접미어 없음. 사람에게는 "오피스" 노릇) 와 `prodev-<과제>/files` (파일 올리기와 그 문답. 옛 들이기 자리). 갈래 방 다섯은 없앤다. 방 이름 접미어는 **영어만** 쓴다. 사람이 외우는 규칙은 한 줄이다 — **"말은 아무 데서나, 파일은 files 에."**
**봇의 태도** ① 어느 방에서든 답한다. 방을 이유로 답을 거부하거나 다른 방으로 보내지 않는다. ② 파일은 `files` 방에서 읽고 묻고 확정을 받아 카드로 만든다. 카드가 valid 가 되면 그 방에 **카드 한 줄 공지**(카드 번호 · 제목 · 경로)를 올린다 — 옛 카드 방 글(6줄 + 원본 첨부)을 이 한 줄이 대신한다. 원본은 사람이 올린 그 글에 이미 있으므로 다시 첨부하지 않는다. 색인은 `index.js` 가 만드는 파일이 진실이다. ③ 본방에 파일이 올라오면 한 줄만 안내한다: "파일은 files 방에 올려주시면 거기서 읽고 여쭙겠습니다." 본방에서는 읽기 시작하지 않는다. **이것이 유일한 안내다.** ④ 리서치 브리핑 · 특허 · 논문 · 보고 산출물은 본방에 올린다 (첨부 + 경로, ADR-020 그대로).
**훅의 방아쇠를 방에서 표식으로 옮긴다** 확정 관문(ADR-008 다섯 조건)은 살린다. 조건 ② 의 방 이름은 **`/files`** 가 된다 (옛 문구는 ADR-008 의 결정 절에 그대로 있다). 방아쇠는 "카드 방에 쓸 때"가 아니라 **카드 공지 글**이다. 카드 공지 글의 표식은 이렇다 — 봉투(`@TO(…)` · `@CC(…)`)를 벗긴 본문의 **첫 줄**이 `[카드] <번호> · <제목> · <경로>` 꼴이고, 훅은 `^\[카드\]\s+(E|R|D|N)-\d{4}\s+·` 로 알아본다. 발송 결재 관문은 "보고 방이면"을 버리고 첫 줄의 **`[발송]` 표식**만으로 건다 (어느 방이든). DB 를 못 열 때의 fail-closed 는 카드 공지와 발송에 그대로다.
**파일 규칙에 예외를 두지 않는다 (보탬, 2026-09-10)** "파일은 files 에" 가 예외 없이 참이어야 사람이 규칙 하나만 외운다. 그래서 실험 자료가 아닌 파일 — 보고 양식 · 논문 초안 · 특허 자료 — 도 `files` 방에 올린다. 첨부가 곧 들이기(intake)라는 뜻은 아니다: `files` 방의 첨부 글이라도 **시키는 말**("8월치로 채워 주세요")이 붙으면 `report` · `paper` · `patent` 로 간다. 산출물이 본방으로 가는 것은 그대로다 (위 ④).
**표식의 방아쇠는 `[카드]` 하나다 (보탬, 2026-09-10)** 첫 줄이 `[카드]` 로 시작하면 번호 꼴이 아니어도 관문에 세우고 막는다. 표식을 붙였으면 그것은 공지이고, 번호 없는 공지는 사람이 훑는 색인 줄이 못 되기 때문이다. 번호 꼴 검사는 관문 안에서 한다. 방을 모르는 `chat_id` 여도 표식이 있으면 관문이 걸린다.
**왜 표식인가** 요건이 둘이었다. 확정 없이는 카드 공지가 **기계적으로** 안 나가야 하고, 봇이 평소 답에서 카드 번호를 입에 올리는 것은 막히면 안 된다. 방이 하나로 합쳐진 뒤에는 방으로 이 둘을 가를 수 없다. 표식은 봇이 스스로 붙이는 것이지만, 붙이지 않으면 그 글은 카드 공지가 아니고 사람이 읽는 색인 줄도 아니다 — 붙였을 때만 관문이 걸리는 것으로 충분하다.
**결과** ADR-001 · 008 · 018 · 020 · 021 가운데 방 이름을 든 문장이 바뀐다 (각 절에 "바뀐 자리 (ADR-022)" 한 줄을 달았다. 옛 결정 본문은 지우지 않는다). "방 갈래를 DB 로도 `rooms.json` 으로도 모르면 막지 않는다"는 예외는 없어진다 — 표식이 방아쇠라 방을 몰라도 관문이 걸린다. 이 ADR 은 **설계 문서에만** 들어간다. `setup.js` · `pre-reply.js` · 스킬 열셋 · 시험은 뒤따르는 코드 PR 에서 맞춘다.

## ADR-023 과제 폴더는 setup 이 만든다
**상태** 확정 (사람, 2026-09-10)
**맥락** 지금까지 사람이 과제 폴더를 손으로 만들고 그 **절대 경로**를 `--project` 에 줬다. 자리를 두 번 외워야 했다 — 폴더를 만들 때 한 번, 그리고 `MINIDISCORD_BOT_FILES_DIR` 이 그 **부모**여야 한다는 규칙에서 또 한 번 (ADR-019). 둘이 어긋나면 봇이 첨부를 못 하는데 서버가 **조용히** 빼므로 한참 뒤에야 보인다. 사람이 "과제 하나 = 파일 뿌리 아래 폴더 하나, 만드는 것은 setup" 으로 정했다.
**결정** `--project` 는 이름도 경로도 받는다. `/` 가 들어 있거나 이미 있는 자리면 지금까지처럼 **경로**로 본다. **이름만이면 `$MINIDISCORD_BOT_FILES_DIR/<이름>`** 이다. 폴더가 없으면 하위 열과 함께 만들고 `git init` 까지 한다 (ADR-003 의 "과제 폴더 = git 하나"). 이름만 줬는데 파일 뿌리를 모르면 **죽는다** — 조용히 엉뚱한 자리에 만드느니 설치가 실패하는 편이 낫다 (ADR-019 와 같은 결).
**있는 것은 건드리지 않는다** 다시 돌려도 과제 폴더 안은 그대로다. `.git` 이 이미 있으면 `git init` 을 하지 않는다. `charter` 스킬의 `git init` 걸음도 "아직 git 이 아니면" 그대로 둔다 — 두 자리가 같은 일을 하지만 둘 다 조건부라 겹쳐도 해가 없다.
**git 이 실패해도 설치는 이어 간다** 못 했다는 한 줄만 남긴다. 커밋은 나중 일이고, 여기서 멈추면 봇을 못 띄운다.
**재는 것** `test/server/setup.test.js` 세 건: ① 이름만 줬을 때 과제 폴더 · `.git` · 봇 폴더 셋이 생긴다 ② 있는 폴더에 다시 돌려도 안의 파일 목록과 해시가 같다 ③ 파일 뿌리를 모르면 `MINIDISCORD_BOT_FILES_DIR` 을 이름에 담아 죽는다.
**결과** `docs/launch.md` 3절과 10.8 의 걸음에서 사람이 폴더를 미리 만들 일이 없어진다.

## ADR-024 사람이 마주치는 이름은 영어로, 알림 토큰은 setup 이 받는다
**상태** 확정 (사람, 2026-09-10)
**맥락** 첫 기동을 해 본 사람이 세 마디를 했다. ① "알림이 무슨 말인지 모르겠다" — `prodev-알림` 이라는 계정이 채팅 목록에 앉아 있는데 그것이 봇인지 사람인지 무엇을 하는지 이름만으로는 안 보였다. ② "토큰을 어디서 복사하는지 모르겠다" — `launch.md` 7.1 이 `curl … | grep -i set-cookie` 로 쿠키 값을 꺼내 `.env` 에 붙여 넣으라고 시켰는데, 그 값이 무엇이고 왜 필요한지가 파일 어디에도 없었다. ③ "비서는 영어로" — 코드와 채팅에 `prodev-<과제>-비서` 처럼 한글이 섞이면 눈에 걸린다.
**결정** 둘을 바꾼다. ① **이름**: 봇은 `prodev-<과제>-bot`, 알림 계정은 `prodev-notify`. 과제 이름은 사람이 정하는 것이라 한글이어도 된다 — 바꾸는 것은 **우리가 붙인 이름**뿐이다. ② **토큰**: `setup.js --project` 가 서버가 떠 있으면 `prodev-notify` 로 한 번 로그인해(이름 하나면 계정이 없을 때 생긴다) 응답의 `md_session` 값을 `bots/<봇>/.env` 의 `PRODEV_NOTIFY_TOKEN=` 에 쓴다. 이미 값이 있으면 **덮지 않는다**. 서버가 꺼져 있으면 `rooms` 가 그러듯 "서버를 켜고 다시 돌리면 받는다" 로 넘어간다.
**.env 에 풀이를 붙인다** 토큰 줄 위에 한 줄이 함께 적힌다: `# PRODEV_NOTIFY_TOKEN: prodev-notify 계정의 세션 쿠키. 훅과 cron 이 본방에 알림 글을 올릴 때 쓴다 (봇 글은 게이트웨이만 보낼 수 있어서 사람 계정이 필요하다)`. 사람이 파일을 열었을 때 무엇인지 모를 값이 없어야 한다 — 사람의 두 번째 마디가 그것이었다.
**공용 api() 를 쓰지 않는다** `setup.js` 의 `api()` 는 받은 쿠키를 모듈 변수에 담아 다음 부름에 실어 보낸다. 알림 로그인을 거기로 태우면 그 뒤의 봇 등록이 알림 계정으로 나간다. 그래서 알림 로그인만 `fetch` 를 직접 쓴다.
**봇 문맥에는 여전히 두지 않는다** `settings.json` 의 `env` 에 `PRODEV_NOTIFY_TOKEN` 을 넣지 않는 것은 그대로다 (ADR-018). 사람 계정의 토큰이 봇 문맥에 실리면 봇이 사람인 척 글을 쓸 수 있다. `.env` 는 훅이 읽는 자리이지 봇의 문맥이 아니다.
**재는 것** `test/server/setup.test.js` 둘: ① `setup` 뒤 `.env` 에 풀이 한 줄과 64자리 16진 토큰이 있고, **그 값으로 본방에 글을 올리면 200 이고 쓴 이가 `prodev-notify`** 다 — "파일에 뭔가 있다" 로는 걸음이 없어졌는지 알 수 없다 ② `.env` 에 값이 이미 있으면 덮지 않는다.
**결과** `launch.md` 의 사람 걸음에서 토큰 관련이 **셋에서 둘로** 준다: 알림 계정 만들기와 쿠키 복사가 없어지고, 재생용 PL·과제원 토큰 넘기기만 남는다. crontab 에 붙일 값은 이제 `.env` 에서 그대로 옮기면 된다.

## ADR-025 설계 문서는 판마다 한 폴더 (`design/v<판>/`)
**상태** 확정 (사람, 2026-09-11)
**맥락** 설계 문서 다섯(PRD · ARCHITECTURE · ADR · TASKS · VERIFICATION)이 저장소 뿌리에 낱개로 있었다. 설계를 고치면 원본을 덮어썼고, 앞 판은 git 이력을 뒤져야 보였다. 1차 설계가 2026-09-10 에 닫혔고 지금 2차를 크게 새로 세우는 참이다. 1차의 약속이 2차를 쓰는 동안 덮이면 "그때 무엇을 약속했나" 에 답할 수 없다 — 이 ADR 이 뒤집힌 결정을 지우지 않고 상태만 바꿔 쌓는 것과 같은 결이다.
**결정** 설계 문서는 `design/v<판>/` 에 판마다 모아 둔다. `design/v1/` 이 1차 설계 다섯이다. 다음 판은 `design/v2/` 를 만들어 앞 판을 복사한 뒤 거기서 고친다. **앞 판은 손대지 않는다.** 판 목록과 판 올리는 걸음 다섯은 `design/README.md` 에 있다. `docs/`(as-built · log · launch · skill-matrix · harness-input)는 판과 상관없이 계속 갱신하는 **기록**이라 옮기지 않는다.
**경로 규칙** 설계 문서에 적힌 경로는 **저장소 뿌리 기준**이다 (`docs/as-built.md` · `../meta/…`). 같은 판 안의 문서끼리는 이름만 적는다 (`ARCHITECTURE.md`). 이미 `docs/` 가 그렇게 쓰고 있던 관행을 글로 못 박았을 뿐, 바꾼 것이 아니다. 그래서 옮기면서 문서 본문의 `../meta/` · `../crew/` 는 그대로 두었다.
**왜 git 이력으로 충분하지 않은가** 이력을 뒤져야 보이는 것은 읽히지 않는다. 두 판을 맞대 보려면 나란히 있어야 한다.
**왜 이 절이 v1 안에 있나** "앞 판은 손대지 않는다" 고 해 놓고 v1 의 ADR 을 고치는 셈이다. 그래도 여기에 둔다 — v2 의 ADR 첫 절로 미루면 v2 를 열기 전까지 이 폴더 구조의 까닭이 어디에도 없다. 문서를 어디에 두느냐일 뿐 설계를 바꾸지 않으므로 작은 예외로 본다. 이 절 말고 v1 본문에서 바뀐 것은 `ARCHITECTURE.md` 4.1 의 폴더 나무 두 줄뿐이다 (자기 자리를 가리키는 그림이라서다).
**결과** 저장소 안에서 이 다섯을 가리키던 참조 서른하나를 따라 고쳤다 (`README.md` · `docs/as-built.md` · `docs/log.md` · `docs/skill-matrix.md` · `docs/harness-input.md` · `intake` 스킬). 뿌리 `README.md` 의 문서표는 둘로 갈랐다 — 설계(판마다 얼어붙는다)와 기록(`docs/`, 계속 자란다). 코드는 한 줄도 바뀌지 않았고 시험 아흔넷은 그대로 통과한다.

## ADR-026 검색 층에 과제 문서(헌장 · 일정)를 더한다. 자리는 위키 뒤 · inbox 앞
**상태** 확정 (사람, 2026-09-11)
**맥락** T3.M 관문에서 찾기 성공률이 **10/16 (62.5%)** 로 예측 ≥12 에 미달했다. 관문 뒤 재측정도 **11/16 (68.8%)** 이었다. 빗나간 물음을 하나씩 따라가 보니 원인 셋 가운데 하나가 여기였다 — 예산 · 중간 점검 · 판정 기준은 `charter.md` 와 `schedule.md` 에 또박또박 적혀 있는데, `find.js` 가 **그 두 파일을 아예 보지 않았다.** 잘 넣어 둔 것을 안 보고 있었던 것이지 자료가 없었던 것이 아니다.
**결정** `find.js` 에 층 하나를 더한다. `charter.md` · `schedule.md` 를 뒤지는 **4층 "과제 문서"** 다. 자리는 **위키 뒤 · inbox 앞**. inbox 는 5층, 대화는 6층으로 밀린다.
**왜 위키 뒤인가** 앞에 두면 헌장의 흔한 낱말(수율 · 장비 이름 · 사람 이름)이 카드와 위키를 가로챈다. 뒤에 두면 1~3층이 답할 수 있는 물음은 **구조적으로** 가로챌 수 없다 — 먼저 걸린 층에서 멈추기 때문이다. 순서 하나로 우선권이 정해지므로 점수나 가중치를 들일 필요가 없다.
**왜 일지(`journal/`)는 이번에 안 넣나** 넷이다. ① 날짜마다 파일이 늘어 결과가 폭발한다 — 같은 낱말이 석 달 치 일지에 다 걸린다. ② 낡은 사실이 최신 카드보다 먼저 걸릴 수 있다. 일지에는 `void` 도 `supersedes` 도 없어서, 뒤집힌 사실을 뒤집혔다고 표시할 길이 없다. ③ 대화 층이 이미 같은 사실을 덮는다 — 일지에 적힌 것은 대개 그날 방에서 오간 말이다. ④ 한 번에 둘을 바꾸면 무엇이 성적을 올렸는지 못 잰다. 이번 판으로 성공률이 오르면 그것은 과제 문서 층의 몫이다. 일지를 같이 넣었으면 그 말을 못 한다.
**로그 칸을 하나 더한다** `find.log` 한 줄에 층 **이름** 칸을 넣어 `<when>\t<layer>\t<layer 이름>\t<n>\t<top>\t<q>` 로 한다. 층이 밀리면 T3 때 쌓인 로그의 `4`(옛 inbox)와 새 로그의 `4`(과제 문서)가 다른 뜻이 되어 주간 계측이 **조용히** 어긋난다. 같은 까닭으로 PRD N3 와 VERIFICATION P8 의 지표도 층 번호가 아니라 **층 이름**으로 다시 적었다 — 숫자로 적은 지표는 층이 늘 때마다 틀린 것을 재게 된다.
**닿는 자리가 좁다** 두 파일은 과제 저장소 뿌리의 **고정 경로**라 색인을 거칠 이유가 없다. 그래서 `scripts/index.js` 는 한 줄도 바뀌지 않고, 변경이 `scripts/find.js` 한 파일에 갇힌다. 이 고침의 가장 좋은 점이다.
**재는 것** `test/find.test.js` 의 새 물음 셋 — `예산`(→ `charter.md#예산`) · `중간 점검`(→ `charter.md#일정 요약`) · `장비 반입`(→ `schedule.md`). 그리고 `find.log` 18줄의 층 분포와 층 이름 칸.
**결과** 층이 여섯이 된다 (`ARCHITECTURE.md` 5.3). 과제 초기에는 두 파일이 없으므로 이 층은 조용히 건너뛴다.

## ADR-027 과제 문서는 파일이 아니라 절 · 행 단위로 맞댄다
**상태** 확정 (사람, 2026-09-11)
**맥락** `charter.md` 는 한 파일에 목적 · 목표 · 일정 요약 · 인원 · 예산 · 판정 기준이 다 들어 있다. 다른 층은 알갱이가 작아서 문제가 없었다 — 카드 하나, 위키 페이지 하나, 사이드카 하나가 한 가지를 말한다. 헌장은 그렇지 않다.
**결정** 맞대는 알갱이를 **절과 행**으로 한다. `charter.md` 는 머리말(첫 `---` 블록)을 한 덩이로, 그 뒤는 `## ` **절마다** 하나. 경로는 `charter.md#<절 이름>` 이다. `schedule.md` 는 `|` 로 시작하는 **표 행마다** 하나이고 (구분선과 머리 행은 건너뛴다) 경로는 `schedule.md#<첫 칸>` 이다.
**왜 머리말을 한 덩이로 세나** `project` · `pl` · `members` · `status` 가 거기 있고 "PL 이 누구지"는 흔한 물음이다. `## ` 로만 자르면 머리말이 통째로 빠져 그 물음에 못 답한다.
**파일을 통째로 맞대면 무엇이 깨지나** 낱말들의 AND 가 **같은 절 안에서** 만족되는지를 못 본다. `예산 감광액` 이 그 자리다 — "예산"은 `## 예산` 절에, "감광액"은 `## 목적` 절에 있다. 한 절 안에는 둘 다 없으므로 이 물음은 **안 걸려야 맞다.** 파일을 통째로 맞대면 걸리고, 그것이 거짓 양성이다. 찾기 성공률은 못 찾은 것만 깎는 것이 아니라 엉뚱한 것을 찾아 주는 것으로도 깎인다.
**자르는 것만으로는 모자라다 — 덩이마다 경로가 달라야 한다 (보탬, 2026-09-11, meta 가 PR 검토에서 찾음)** 첫 판에서는 `schedule.md` 의 모든 행에 같은 경로 `schedule.md` 를 붙였다. 결과는 경로로 묶으므로(`dedupe`), 걸린 행이 여럿이어도 **첫 하나만 남고 나머지가 조용히 버려졌다.** 일정 행 다섯인 자료에서 `김과제` 가 세 행에 걸리는데 결과는 한 행이었다. 절·행으로 자른 것은 맞았으나 자른 표시를 경로에 남기지 않아, 자른 것이 도로 뭉개졌다. 그래서 첫 칸(항목 이름)을 경로에 붙여 `schedule.md#장비 반입` 으로 한다 — 첫 칸이 곧 그 행이 무엇인지다. 이름이 같은 두 행은 그때 묶이는 것이 맞다(진짜 중복이다). **덩이를 나누는 규칙과 덩이를 가리키는 이름은 한 벌이다.** "지금 대기 중인 게 뭐뭐야" · "김과제가 맡은 거 뭐야" 는 일정에서 가장 흔한 물음 꼴이고, 이 결함은 답을 틀리게 하는 것이 아니라 **모자라게** 하므로 봇도 사람도 모르고 지나간다.
**재는 것** `test/find.test.js` 의 "없는 것" 에 `예산 감광액` 이 있다. 이 시험이 절 단위 매칭을 지키는 자리다. 행 경로는 `장비 반입` 의 기대 경로가 `schedule.md#장비 반입` 인 것이 지킨다.
**결과** 답이 절 이름 · 항목 이름까지 좁혀지므로 사람이 파일을 열었을 때 어디를 볼지 안다.

## ADR-028 카드 `## 결과` 는 갈래별 요약 표와 원본 실마리를 **둘 다** 싣는다. `conditions` 에는 가르는 축을 적는다
**상태** 확정 (사람, 2026-09-11)
**맥락** T3.M 에서 빗나간 물음의 나머지 둘이 여기였다. ① 카드의 `## 결과` 절이 규격 초과 **5건만** 싣고 정상 29행을 안 실어서, "규격 이내인 것은 몇 개였지" 에 카드가 답하지 못했고 봇이 원본 csv 를 직접 읽었다. ② 초과 목록은 있었으나 `conditions` 에 **공급사** 열이 없어서 "BSTech 것만" 을 가릴 수 없었다. v1 의 5.1 은 "요약 표 **또는** 실마리" 라고 적어 두었고, 봇은 둘 중 쉬운 쪽 하나만 골랐다.
**결정** 셋을 못 박는다. ① `## 결과` 절에 **갈래별 요약 표**(장비별 · 공급사별 · 판정별 수)를 **싣고**, 전체 표는 **원본 실마리 한 줄**로 가리킨다. "또는"을 "둘 다"로 바꾼다. ② `conditions` 에 **가르는 축** 넷 — 장비 · 공급사 · 로트 · 레시피 — 을 자료에 있으면 반드시 적는다. ③ `aliases` 에 같은 물건의 다른 이름(정식 부품명 · 현장 말 · 영문 · 줄임말 · 흔한 오타)을 채운다.
**왜 "둘 다" 인가** 하나만 고를 수 있으면 언제나 짧은 쪽이 골라진다. 이상 자리만 실은 카드는 **이상한 것만** 답하고, 정상 행을 묻는 물음은 전부 원본으로 흘러간다. 그러면 카드가 일을 안 한 것이다. 정상 행을 통째로 베끼자는 것이 아니다 — 요약 표가 세어 주고, 실마리 한 줄이 원본을 가리킨다.
**왜 가르는 축인가** 물음은 언제나 "무엇별로" 들어온다. 축이 `conditions` 에 없으면 1층(`title` · `aliases` · `tags`)에도 2층(카드 본문)에도 그 낱말이 없어서, 가를 수 있는 자료를 손에 쥐고도 못 가른다.
**왜 `aliases` 를 여기서 말하나** `aliases` 는 **1층이 걸리는 유일한 길**인데 그것을 채우라는 안내가 어느 스킬에도 없었다. 규격에는 칸이 있었고 채우는 걸음이 없었다.
**재는 것** `intake` 스킬에 "물어볼 것 다섯" 걸음을 둔다 — 확정 전에 "이 자료로 사람이 물을 만한 것 다섯" 을 스스로 적고, 그 다섯이 **카드만 읽고** 풀리는지 본다. 안 풀리면 카드에 빠진 것이 있다. 봇이 스스로 채점하는 자리가 아니라 빠진 칸을 **찾아내는** 자리다.
**결과** `ARCHITECTURE.md` 5.1 의 카드 규격과 `.claude/skills/intake/SKILL.md` 의 `## 카드` 절이 바뀐다. 코드는 바뀌지 않는다.

## ADR-029 대본 시험은 미니디스코드 없이 세션 대 세션으로 한다
**상태** 확정 (사람, 2026-09-11)
**맥락** 대본 한 번을 돌리려면 시험 서버를 띄우고 · 계정 셋을 만들고 · 토큰을 셋 옮기고 · 방 둘을 열고 · 봇을 참여시켜야 했다 (`docs/launch.md` 1~3절). 걸음이 길어서 대본을 자주 못 돌렸고, 자주 못 돌리니 T3.M 의 성적 미달 같은 것이 늦게 잡혔다.
**결정** 대본은 **세션 대 세션**으로 돌린다. meta 세션이 사람 역할을 맡아 봇 세션에 대본의 글을 건네고 답을 받는다. `setup.js --project <이름>` 은 서버 없이 돌아가고(봇 등록과 알림 토큰은 스스로 건너뛴다), 봇은 `cd bots/<봇> && claude --setting-sources project,local` 로 켠다 — `--mcp-config` 와 개발 채널 옵션을 **주지 않는다.**
**무엇을 못 재게 되나 (솔직하게)** `pre-reply` 훅은 채널 플러그인의 `reply` 도구에 걸린다. 플러그인을 안 붙이면 그 도구를 안 부르므로 훅이 **한 번도 안 걸린다.** 그래서 셋을 못 잰다 — **분량 검사(900자 · 10줄) · 카드 확정 관문 · 발송 결재.** 셋 다 훅 단위 시험(`pre-reply-cases.json` 17건)이 이미 잡고 있으므로 관문 자체는 검증돼 있다. 못 보는 것은 "실제 대화 흐름에서 봇이 그 관문에 걸리는가" 뿐이고, 그것은 서버를 띄우는 판에서 따로 잰다 (실전 이전 T4 에 한 번).
**대화 층이 빈다** `MINIDISCORD_DB` 를 안 붙이면 `find.js` 6층이 조용히 비고(fail-open) 대화에만 있는 사실은 안 걸린다. 대화 층을 재는 대본은 지난 판의 DB 사본을 붙여 돌린다.
**왜 그래도 이쪽인가** 되풀이가 싸지면 대본을 자주 돌리고, 자주 돌리면 잡히는 것이 는다. 못 재는 셋은 **무엇인지 알고 목록으로 적어 두었으므로** 조용히 빠지지 않는다. 검수가 위험한 것은 못 재는 것이 있을 때가 아니라 못 재는 줄 모르고 통과로 셀 때다.
**재는 것** 세션 판에서 못 재는 칸은 검수표에 **"못 잼"** 으로 적는다 (VERIFICATION 4.3). 통과로도 불통과로도 세지 않는다.
**결과** `VERIFICATION.md` 4절이 바뀌고 `docs/launch.md` 에 "미니디스코드 없이 세션으로 시험하는 법" 절이 생긴다. `scripts/replay.js` 는 지우지 않는다 — 서버 판에서 그대로 쓴다.

## ADR-030 과제가 쫓는 갈래는 수가 아니라 개체까지 카드에 내린다
**상태** 확정 (사람, 2026-09-11, 검색 1차 관문 뒤) — **ADR-028 을 보탠다** (뒤집지 않는다)
**맥락** ADR-028 로 카드 `## 결과` 절이 갈래별 요약 표를 싣게 된 뒤, 검색 1차 관문에서 찾기 성공률이 **14/16 (87.5%)** 로 올랐다. 그런데 예측 한 칸(E3, 물음 셋이 카드에서 답한다)이 **2/3** 이었다. 빗나간 물음은 원본 csv 까지 내려갔다 (`../meta/prodev-review/runs/2026-09-11-search.md` 4절 · 사본 `docs/evidence/2026-09-11-search.md`).

원인은 하나다. **요약 표는 수를 주지 개체를 주지 않는다.**

| 판 | 카드가 담은 것 | 그래도 못 답한 물음 |
|---|---|---|
| v1 | 규격을 **벗어난 것만** | "규격 이내인 건 뭐지" |
| v2 1차 (ADR-028) | 갈래별 **수** ("SH-2200 여덟 중 여섯 이내") | "그 여섯이 **어느 것**이냐" |

지난 관문에서 "카드가 이상한 것만 실으면 모자라다"를 배웠고, 이번에 "정상인 것도 **수로만** 실으면 여전히 모자라다"를 배웠다. 같은 결함의 한 걸음 안쪽이다.
**봇이 먼저 찾아낸 규칙이다** 재는 도중 봇이 그 물음에 막히자 스스로 카드를 고쳤다. 그런데 서른세 행 전부를 베낀 것이 아니라 **과제가 쫓는 부품의 여덟 행만** 개체까지 내렸다. 사람이 시키지 않았는데 "무엇을 깊이 실을지" 를 과제의 목적에서 끌어온 것이다. 그 판단을 규칙으로 올린다 — 봇이 매번 다시 발견하게 두지 않는다.
**결정** `## 결과` 절은 갈래마다 **깊이를 다르게** 싣는다. ① **과제가 쫓는 갈래**(카드 `tags` 와 헌장 `## 목적` · `## 목표` 에 **함께** 나오는 것)는 **개체별 표** ② **규격을 벗어난 개체**도 개체별 표 (ADR-028 에 이미 있었다) ③ **나머지 갈래**는 갈래별 요약 표 + 원본 실마리 (ADR-028 그대로).
**왜 "쫓는 갈래" 가 기준인가** 카드가 답해야 하는 물음의 밀도는 갈래마다 다르다. 과제가 쫓는 것에는 "어느 것이냐 · 어디 갔느냐 · 그중 무엇이 이상하냐" 가 계속 들어오고, 나머지 갈래에는 "몇 개냐" 가 한 번 들어온다. 그리고 그 갈래는 **이미 파일에 적혀 있다** — 헌장의 목적과 목표가 그것이다. 사람에게 새로 묻지 않고 알 수 있는 기준이라야 걸음이 늘지 않는다.
**반대 방향의 실패도 막는다 (상한)** 개체가 **20을 넘는** 갈래는 개체별 표 대신 ① 규격 밖 전부 ② 규격 경계에 가까운 것 다섯 ③ 나머지는 수와 범위로 줄인다. "다 실으면 안전하다" 는 규칙은 카드를 못 읽게 만들고, 못 읽는 카드는 안 실은 카드와 같다. ADR-028 이 "너무 적게"를 막았다면 이 상한은 "너무 많이"를 막는다.
**묻는 수를 늘려 풀지 않는다** 쫓는 갈래가 헷갈리면 사람에게 묻되 **들이기 문답의 물음 셋 안에서** 묻는다 (ARCHITECTURE 6.1). 물음을 넷째로 늘리면 성적은 올라도 사람이 더 일한 것이고, 그것은 이 비서가 하려는 일의 반대다 (PRD N2, 들이기 왕복 중앙값 ≤ 4).
**"물어볼 것 다섯" 에 한 줄 더한다** 다섯 가운데 적어도 하나는 **"그게 어느 것이냐"** 로 묻는다. "무엇별로 몇 개냐" 만으로 다섯을 채우면 요약 표만으로 다 풀려서 개체가 빠진 것을 못 본다 — 수를 묻는 물음은 수로 답하는 카드를 통과시킨다. 1차에서 이 자체 점검이 있었는데도 결함이 지나간 까닭이 여기다.
**왜 ADR-028 에 절을 더하지 않고 새 절인가** ADR-028 이 **틀린 것이 아니라 모자랐다.** 틀린 결정은 상태를 바꾸고, 모자란 결정은 보탠 절이 따라붙는다. 그리고 그 모자람이 **실측으로** 드러난 경위 — 1차 관문 · 예측 E3 · 봇이 스스로 고친 자리 — 가 남아야 다음에 같은 갈래를 알아본다.
**코드는 바뀌지 않는다** 찾기 층 구조도 시험도 그대로다. 카드가 담는 것이 달라질 뿐이라 가로챔 위험이 없다.
**재는 것** 다음 관문에서 두 가지를 본다 — **봇이 재는 도중 카드를 고치는 횟수**(규칙이 제대로 들어갔으면 처음부터 옳게 만들어져 0이어야 한다)와 **들이기 왕복**(묻는 수를 늘려서 푼 것이 아니어야 한다).
**결과** `ARCHITECTURE.md` 5.1 과 `.claude/skills/intake/SKILL.md` 의 `## 카드` 절이 바뀐다.

## ADR-031 판을 v3 으로 올린다 — 진화하는 비서
**상태** 확정 (사람, 2026-09-11)
**맥락** v2 는 **검색 안정성**의 판이었다. 찾기 층에 과제 문서를 더하고(ADR-026 · 027) 카드가 담는 깊이를 두 번 고쳤다(ADR-028 · 030). **그 판은 닫혔다** — 찾기 성공률이 62.5% → 87.5% → **16/16 (100%)** 로 올라 더 올릴 것이 없다 (`../meta/prodev-review/runs/2026-09-11-search-2.md` · 사본 `docs/evidence/2026-09-11-search-2.md`).

이제 하려는 것은 성격이 다르다. **쓸수록 이 사람에게 맞아 가는 비서**다 — 보고 양식을 한 번 가르치면 다음부터 그 양식으로 나오고, 분석 방법을 한 번 만들면 다음에 또 짜지 않는 것. 성공 지표는 기능 수가 아니라 **잔소리가 줄어드는 것**이다. 근거 문서는 `../meta/prodev-review/plans/2026-09-11-handoff-evolution.md`.

이것은 찾기를 더 잘하게 만드는 일이 아니다. **과제 폴더에 새 자리를 만들고 · 스킬을 하나 늘리고 · 봇이 지킬 규칙을 새로 약속하는** 일이다. 약속이 바뀌므로 판이 바뀐다.
**결정** `design/v3/` 를 열고 v2 다섯을 복사해 거기서 고친다. **v2 는 한 글자도 손대지 않는다.** `design/README.md` 의 판 목록에서 v2 를 "지난 판"으로 내리고, 뿌리 `README.md` 의 문서표가 v3 를 가리키게 한다. `design/README.md` 의 "판을 올리는 법" 다섯 걸음 그대로다.
**왜 v2 에 절을 더하지 않나** ADR 을 더하는 것은 **같은 약속 안에서 결정이 는 것**이고, 판을 올리는 것은 **약속 자체가 바뀌는 것**이다. v2 를 읽는 사람은 "찾기를 안정시키는 판"을 읽고 있어야 한다. 거기에 과제 폴더 구조와 새 스킬이 섞여 들어가면 석 달 뒤 그 판이 무엇을 하려던 것이었는지 아무도 못 읽는다.
**이 판에서 하는 일 — 관문 셋** A(**자리**: 폴더 · 훅 · 설정. 판단이 없는 배관) → B(**길**: 굳는 규칙 · `retro` 스킬 · `templates` 고리) → C(**짐**: 분석과 DOE). 이번 PR 이 A 다. B · C 의 세부는 관문마다 meta 가 지시할 때 `TASKS.md` 에 채운다.
**왜 여기서 굳히나** 이 맥(`crew-workspace`)은 프레임을 잡는 자리이고 실전 과제 자료가 없다. 회사는 실제로 쓰며 진화시키는 자리인데 **관문도 예측도 정답지도 없다.** 거기서 설계를 새로 정하게 두면 그 판정을 아무도 안 한다. 그래서 **설계는 여기서 굳히고 환경은 거기서 고친다** (근거 문서 1절).
**결과** `design/v3/` 다섯 · `design/README.md` 판 목록 · 뿌리 `README.md` 문서표.

## ADR-032 굳은 것이 사는 자리를 과제 폴더에 둔다 — `house.md` 는 상한 50줄
**상태** 확정 (사람, 2026-09-11)
**맥락** 봇에게 없는 것은 능력이 아니라 **자리**였다. 넷이 비어 있었다.

| 없는 것 | 그래서 무슨 일이 생겼나 |
|---|---|
| `<과제>/house.md` | 사람이 "앞으로 이렇게 해" 라고 말해도 **그 규칙이 꽂힐 데가 없다.** 켜질 때 훅이 싣는 일곱은 전부 **이 과제의 사실**이고(인수인계서 · 헌장 · 일정 · 실 · 어제 일지 · 색인 머리 · 마지막 일지), 봇 설정에는 `CLAUDE_CODE_DISABLE_AUTO_MEMORY: "1"` 로 기억도 꺼져 있다 |
| `<과제>/analysis/` | 분석 산출물이 `tmp/` 로 간다. 다음 주에 같은 자료가 오면 처음부터 다시 짜고, 답이 지난번과 달라도 아무도 모른다 |
| `<과제>/templates/` | 가르친 양식이 남을 데가 없다 |
| `<과제>/.gitignore` | `ARCHITECTURE.md` 4.2 가 `tmp/` 를 "(gitignore)" 라 적어 두었는데 `setup.js` 가 그 파일을 안 만들었다. **문서와 실물이 어긋난 채였다** |

**결정** `setup.js` 가 새 과제 폴더에 넷을 더 만든다 — `analysis/` · `templates/` · `house.md` · `.gitignore`(`tmp/` 한 줄). `session-start.js` 훅이 `house.md` 를 **여덟째 절**로 싣고 **상한은 50줄**이다. 이미 있는 것은 덮지 않는다 — setup 은 다시 돌릴 수 있어야 하고, 다시 돌려서 무엇이 사라지면 아무도 다시 안 돌린다.
**왜 화물마다 자리가 다른가** 양식(`templates/`)과 분석 방법(`analysis/`)은 **쓸 때만** 읽히므로 스킬이 데이터로 읽으면 된다. 문체 · 어휘 · "앞으로 이렇게 해" 류 일반 규칙은 **모든 답변에** 걸려야 하므로 스킬이 못 받는다. "양식은 데이터로 두면 된다" 는 정리는 **상황별 화물에만 맞는 답**이었다. 그래서 규칙만 훅이 싣는다.
**왜 과제 폴더인가** 셋이 맞는다. 과제 폴더 안이라 **봇이 직접 쓸 수 있고**(권한이 이미 있다), git 에 들어가 **이력이 남고**, 사실과 규칙이 섞이지 않는다 — 헌장 · 일정은 사실, `house.md` 는 규칙이다.
**왜 50줄인가** 줄 수가 아니라 **규칙 개수에서 거꾸로** 왔다. 봇이 일관되게 지킬 수 있는 규칙은 많아야 열다섯 안팎이고(사람도 스무 개는 못 지키고 모델도 규칙이 많아지면 일부를 조용히 놓친다), 규칙 하나는 제목 한 줄에 내용 한두 줄이라 15 × 3 ≈ 45줄, 절 제목과 빈 줄을 더해 **50줄**이다. 주변 값과도 맞는다 — 헌장 40 과 일지 60 사이.

**그리고 이것이 장치 없이 폭주를 막는 자리다.** 규칙이 자동으로 늘면 서로 충돌하고, 한 번의 예외가 영구 규칙이 되고, 늘수록 봇이 느려진다. 상한이 있으면 **새 규칙을 넣을 때 낡은 규칙을 빼야 한다.** 카운터도 점수도 상태 파일도 만들지 않는다 — 훅이 이미 갖고 있는 숫자 하나가 그 일을 한다.
**넘칠 때 조용히 죽지 않는다** 훅은 이미 없음 · 못 읽음 · 잘림을 말로 가른다. 잘리면 훅이 봇에게 *"첫 답에 사람에게 말하라"* 고 시키고, 봇은 **스스로 줄이지 않는다** — 스스로 줄이면 사람이 세운 규칙을 봇이 지우는 것이 된다. 새 장치를 만들지 않았다. **훅이 이미 아는 것을 말만 시켰다.**
**그 지시를 왜 훅에 두고 CLAUDE.md 에 두지 않나** **잘렸을 때만** 나와야 하기 때문이다. CLAUDE.md 한 줄로 두면 잘리지 않은 날에도 늘 실려 규칙 예산을 먹고, 잘리지도 않았는데 봇이 그 말을 꺼낼 자리를 만든다. 훅은 잘림을 아는 유일한 자리다.
**`house.md` 를 빈 파일로 두지 않는다** 비어 있으면 봇도 사람도 여기에 무엇을 적는지 모르고, 모르면 아무도 안 적어서 자리만 있고 쓰이지 않는다. **골격이 곧 사용법이다.** 머리에 넷을 못 박는다 — 여기는 규칙이 사는 자리라는 것 · 상한 50줄 · 규칙 하나마다 **언제부터 · 누가 · 무엇을 보고** · "이번에는" 은 들어오지 않는다는 것. 셋째는 되돌리기 위한 것이다. 석 달 뒤 "왜 이렇게 됐지" 라는 물음이 반드시 오고, 그때 정신은 ADR 과 같다. **과제 폴더판 ADR 이다.**
**이번에 하지 않는 것** 분석 한 건마다 카드를 남기는 규칙 · `report` 스킬이 `templates/` 를 읽는 고리 · `retro` 스킬 · 굳는 길의 규칙은 **관문 B** 다. 이번 것은 **자리**뿐이고 판단이 없다. 자리가 먼저 있어야 그 위의 규칙을 약속할 수 있다.
**재는 것** 새 과제 폴더에 넷이 생기는가 · 훅의 여덟째 절이 순서대로 나오는가 · 51줄이면 잘리고 잘렸다고 말하는가. 단위 시험이 본다. **상한 50 이 맞는 숫자인지는 실측이 없다** — 이것은 예상이다. 회사 2주를 돌려 규칙이 실제로 얼마나 빨리 느는지를 보고 고친다. `house.md` 의 줄 수를 주간 계측에 한 줄 더해 두면 자동으로 잡힌다.
**결과** `scripts/setup.js` · `common/hooks/session-start.js` · `ARCHITECTURE.md` 4.2 · `test/setup.test.js` · `test/hooks.test.js` · `docs/as-built.md`.

## ADR-033 허용 목록을 줄이고 Git Bash 길을 봇 설정에 박는다
**상태** 확정 (사람, 2026-09-11)
**맥락** 봇 허용 목록은 41건이었다. 바탕은 crew 에서 물려받은 33건이고 거기에 회차 5 의 승인 31회를 덮는 것을 더한 것이다 (`design/v2/TASKS.md` T1.6 이 "crew 목록 + python3 + 회차 5 의 31건" 이라고 그대로 적었다). **설계해서 고른 목록이 아니라 물려받은 여벌이다.**

실제로 무엇을 부르는지 세어 보면 **스킬 열셋과 에이전트 여섯의 본문에서 유닉스 도구를 부르는 자리가 하나도 없다.** 규정된 길은 전부 `node scripts/*.js` 이고(`find/SKILL.md:37` · `intake/SKILL.md:21,31,77,87` · `journal/SKILL.md:22,81` · `charter/SKILL.md:76` · `close/SKILL.md:55` · `research/SKILL.md:23,66` · `schedule/SKILL.md:41`), 예외는 `intake/SKILL.md:59` 의 `python3 scripts/plot.py` 와 `git` 뿐이다. `data-reader` 는 "큰 파일 전수 읽기"가 일인데도 `awk`·`sort` 를 안 쓴다 (`.claude/agents/data-reader.md:21~28`).

그리고 회사 기계는 PowerShell 이다. 봇은 `--setting-sources project,local` 이라 **user 범위 설정을 못 읽으므로**, Claude Code 가 Git Bash 를 어디서 찾는지를 봇 설정 밖에서 정해 줄 방법이 없다. `../WINDOWS.md:126` 이 그 경로를 적어 두었으나 **자동이 아니었다** — 사람이 손으로 넣어야 했다.
**결정** 둘이다. ① 내장 도구와 `intake-copy.js` 가 덮는 셸 도구 **스물하나**를 allow 에서 뺀다. 41건 → **22건**(그중 Bash 항목 열). ② `setup.js` 가 봇 설정 `env` 에 `CLAUDE_CODE_GIT_BASH_PATH` 를 박는다. 기본값은 `C:\Program Files\Git\bin\bash.exe` 이고 같은 이름의 환경변수로 덮는다.

| 뺀 것 | 무엇이 대신하나 |
|---|---|
| `grep` · `find` | 내장 `Grep` · `Glob` |
| `cat` · `head` · `tail` · `sed` · `awk` · `sort` · `uniq` · `wc` · `cut` · `tr` · `diff` · `stat` · `file` | 내장 `Read` |
| `cp` · `chmod` · `shasum` · `sha256sum` | `intake-copy.js` 가 node 로 한다 — 복사(`:148`) · 0444 잠금(`:149`) · SHA-256(`:47`) |
| `basename` · `dirname` | 경로는 봇이 그냥 안다 |

남긴 열은 `node` · `git` · `gh` · `python3` · `mkdir` · `ls` · `date` · `echo` · `pwd` · `cd` 다.
**왜 봇이 할 수 있는 일이 줄지 않나** 뺀 스물하나는 **하나도 규정된 길 위에 없다.** 위 표의 오른쪽이 전부 이미 있는 것이고, 새로 만든 것이 없다. 줄어든 것은 능력이 아니라 **셸로 새어 나갈 자리**다.
**`Grep` 과 `Glob` 을 allow 에 이름으로 넣었다 — 이것이 이 결정의 핵심 걸음이다** 셸 `grep`·`find` 를 빼면서 내장 도구를 열어 두지 않으면 찾기가 승인 창으로 새고, 그러면 N7(하루 승인 ≤ 3)이 첫날에 깨진다. 에이전트 여섯이 이미 `Grep`·`Glob` 을 선언하고 있으나(`.claude/agents/*.md:4`) **선언은 도구를 고르는 자리이지 허락하는 자리가 아니다.** `Read` 가 이미 이름으로 들어 있던 것과 같은 이유로 둘도 이름으로 넣는다.
**왜 맥에서도 키를 두나** 값이 비면 안 둔 것과 같다. 맥·리눅스에는 그 경로가 없고 Claude Code 는 없는 경로를 그냥 안 보므로 **무해하다.** 대신 작업판을 회사로 통째로 옮겼을 때 **사람이 아무것도 안 해도 그 줄이 이미 있다.** 이 판의 축이 "설계는 여기서 굳히고 환경은 거기서 고친다" 이므로 여기서 박을 수 있는 것은 여기서 박는다.
**남는 위험** 이어 붙인 명령 한 줄(`cd … && …`)은 통째로 하나로 보이므로 허용 목록으로 다 덮이지 않는다. 진짜 고침은 "이어 붙이지 않는다" 규칙이고 목록은 조각만 연다. 회차 5 에서도 규칙 쪽이 먹었다. 이번 결정이 그것을 고치지는 않는다.
**재는 것** allow 에 뺀 스물하나가 없는가 · `Grep`·`Glob` 이 있는가 · `env` 에 `CLAUDE_CODE_GIT_BASH_PATH` 가 있고 값이 비지 않은가. 단위 시험이 본다. **실제로 승인 창이 늘지 않는지는 회사 첫날에 본다** — 이 맥에서는 PowerShell 을 못 밟는다.
**결과** `common/settings.template.json` · `scripts/setup.js` · `test/setup.test.js` · `docs/as-built.md`.

## ADR-034 분석은 자리와 스킬을 함께 갖는다 — 여섯 칸 · 카드 필수 · 관문은 모형 하나
**상태** 확정 (사람, 2026-09-11)
**맥락** ADR-032 로 `analysis/` 폴더가 생겼지만 **거기에 무엇을 어떻게 넣는지가 없었고, 넣기 시작할 자리도 없었다.** "이 자료로 t 검정 해 줘" 는 스킬 열둘 어디에도 안 걸린다 — `intake` 는 파일 받기, `research` 는 바깥 조사, `find` 는 이미 있는 것 찾기다.

그리고 지금 있는 것은 **읽기까지**다. `peek.js`(겉모습) · `data-reader`(전수 읽고 이상 자리) · `plot.py`(한 열 그래프) — 전부 기술(記述) 수준이다. 시험에서 봇이 *"BSTech 셋은 상한에 붙어 있고 AlphaParts 셋은 여유가 있다"* 까지 갔다가 *"여덟 개체로는 경향을 말할 수 없다"* 로 멈췄다. **멈춘 것은 옳았으나 그다음이 없다.** 표본을 더 모아 실제로 갈리는지 보는 것이 분석이고, 무엇을 얼마나 모을지 정하는 것이 DOE 다.
**결정** 넷이다.

① **`analysis` 스킬을 만든다** (도메인 열셋째). 트리거는 사람의 말 — 분석 · 갈리나 · 유의 · 검정 · Cpk · 공정능력 · 회귀 · 상관 · DOE.
② **분석 한 건 = `analysis/<YYYYMMDD>-<slug>/`** 에 `run.py`(돌린 코드)와 `run.md`(대본 여섯 칸). `inbox/` 와 같은 꼴이다 — 받은 것의 짝이 만든 것이라 묶는 법도 같다. 입력은 `inbox/` 경로로 박고(불변 · SHA-256), `run.py`·`run.md` 는 커밋하고 **그림은 `tmp/`** 다.
③ **카드를 하나 반드시 만든다.** 선택이 아니다.
④ **관문은 "모형 고르기" 한 자리에만.** 후보 두셋을 근거와 함께 내고 사람이 고른다. DOE 의 인자·수준·제약도 같은 자리다. **코드 짜는 데는 관문이 없다.**

**`run.md` 여섯 칸** ① 무엇을 알고 싶은가(한 줄 확인) ② 어떤 가정을 깔았나(모형·임계값·정규성) ③ 코드(**seed · python 판 · 꾸러미 판**) ④ 숫자 + 검증치(잔차·χ²·신뢰구간, 또는 경계 겹친 그림) ⑤ 물리적 해석(**추정이라고 표시**) ⑥ 이 해석을 뒤집을 수 있는 것.
**왜 카드가 선택이 아닌가** `find.js` 의 층 순서는 코드에 고정이고(`:6` 이 "층 순서는 부르는 쪽이 바꾸지 못한다"고 못 박았다) **`analysis/` 는 그 여섯 층의 어느 것도 아니다.** 카드(2층)에 결론 한 줄과 경로가 없으면 이 분석은 다음 주에 **없는 것이 된다.** v3 의 한 줄 목표("다음에 또 짜지 않는다")가 이 한 줄에 달려 있다.
**왜 여섯 칸이고, 왜 측정법마다 템플릿이 아닌가** 측정법은 EIS · SEM · XRD · TGA … 수십 가지고 과제가 바뀌면 또 나온다. **이 길로 가면 끝나지 않는다.** 그런데 칸은 측정법이 달라도 같고, 달라지는 것은 2·3 뿐인데 **그것은 AI 가 잘한다.**

그리고 **틀린 템플릿이 즉석 코드보다 위험하다.** 즉석 코드에는 "방금 짠 것" 이라는 경계심이 붙어 사람이 한 번 보지만, 템플릿은 검증된 것처럼 보여서 아무도 안 본다. 등가회로를 한 층으로 고정한 템플릿을 계면이 둘인 시료에 갖다 붙이면 **물리적으로 틀린 답이 아주 깔끔한 표로 나온다.**
**왜 3번 칸(seed · 판)이 따로 못 박혀 있나** 그것이 없으면 **재현성 검수가 성립하지 않는다.** 반년 뒤 숫자가 달라졌을 때 봇이 틀린 것인지 라이브러리가 바뀐 것인지 가를 수 없다 (`VERIFICATION.md` 5.1 의 첫 줄이 이 칸에 기댄다).
**왜 2번과 6번을 굳이 칸으로 두나** 지금 봇이 실제로 빠뜨리는 것이 그 둘이다. 가정을 숨기고 결론만 말하면 **틀렸을 때 어디서 틀렸는지 알 수 없다.** 나머지 넷은 안 쓰면 칸이 비어 눈에 띄는데 이 둘은 **안 써도 글이 완성돼 보인다.**
**왜 관문이 모형 하나뿐인가** 가를 기준은 측정법이 아니라 **"누가 답이 맞는지 확인하나"** 다. 피팅·t 검정·회귀·Cpk 는 **기계가 스스로 확인한다** — 잔차와 χ² 가 출력 안에 있으므로 봇이 즉석에서 짜도 된다. 반면 **모형 고르기는 봇이 그럴싸하게 틀린 선택을 한다** — 등가회로를 몇 층으로 볼지, 어떤 분포를 가정할지. 그 한 자리만 사람이 정한다. 관문을 더 두면 묻는 수가 늘고, 그것은 이 비서가 하려는 일의 반대다.
**숫자와 해석을 가른다** 카드와 4번 칸의 수치는 **스크립트 출력에서 온 것**이어야 한다. AI 가 못해서가 아니라 **틀렸을 때 아무도 모르기 때문**이다 — p 가 0.04 냐 0.06 이냐가 양산 결정을 가른다. 해석은 자유롭게 말하되 (1) 어느 숫자에서 나왔는지 대고 (2) 확인/추정을 표시한다. 이 구분 없이 "출력만 붙인다" 로 못 박으면 **봇이 숫자 표만 내고 입을 닫는다.**
**사람 눈으로만 확인되는 것** 이미지에서 입자·기공·두께를 재는 것은 숫자만 내면 안 된다. **원본 위에 검출 결과를 겹친 그림을 반드시 같이 낸다.**
**못 하는 것을 적어 둔다** 측정 자체의 결함(저주파 드리프트 · 차징 아티팩트)은 자료만 보면 진짜 신호와 구분이 안 된다. 봇은 6번 칸에 "자료가 이상한 것일 수도 있다"를 적고 **대신 판정하지 않는다.**
**스크립트를 미리 만들지 않는다** t 검정 · Cpk · DOE 를 `scripts/` 에 넣지 않는다. 되풀이돼 굳은 방법만 `analysis/methods/` 로 가고, 거기 넣는 것은 **굳는 길을 타는 봇의 일**이지 제작 세션의 일이 아니다 (ADR-035).
**재는 것** `run.md` 의 2번과 6번이 찬 비율 · 같은 물음에 새 폴더가 생긴 수(0이어야 한다) · `run.py` 를 다시 돌려 같은 숫자가 나오나 (`VERIFICATION.md` 5.1).
**결과** `.claude/skills/analysis/SKILL.md`(새) · `prodev-orchestrator` 분기표 · `ARCHITECTURE.md` 6.4 · `PRD.md` F18 · `docs/skill-matrix.md` · `test/skills.test.js`.

## ADR-035 굳는 길 — 입구 둘, 문 하나. "앞으로" 만 굳고, 세지 않는다
**상태** 확정 (사람, 2026-09-11)
**맥락** ADR-032 로 `house.md` · `templates/` · `analysis/methods/` 라는 **자리**가 생겼다. 그런데 **무엇이 언제 거기 들어가는지**가 없었다. 자리만 있고 길이 없으면 아무것도 안 들어간다.

실전에서 이 일은 이렇게 흘러간다. 사람이 보고 자료를 시킨다 → 봇이 만든다(회사 양식도 문체도 아니다) → 사람이 회사 ppt 를 주고 "이 양식과 문체로 다시" 한다 → 몇 턴 돌아 맞는 것이 나온다 → 사람이 **"앞으로 회의 문서는 이 양식대로 해"** 라고 한다 → 봇이 그것을 **어딘가에 남긴다.** 마지막 둘이 진화다. 그리고 그것은 분석 방법이 반복되어 굳는 것과 **똑같은 일**이다 — 종류만 다르고 길은 하나다.
**결정** 입구는 둘, 문은 하나다.

| | 지시형 | 관찰형 |
|---|---|---|
| 발동 | 사람이 **"앞으로"** 라고 말한다 | 봇이 반복을 알아챈다 |
| 승인 | **이미 끝난 상태로 도착** | 받아야 한다 |
| 진짜 위험 | **범위** | 검증 안 된 것이 굳는 것 |

**지시형**: 굳히기 **직전에 범위를 한 줄 되묻고**, 자리에 적고, 머리에 **언제부터 · 누가 · 무엇을 보고**를 단다.
**관찰형**: **세지 않는다.** 일지의 `## 되풀이된 말` 에 한 줄씩 쌓고 `retro` 가 읽다가 묻는다 (ADR-036).
**사는 자리**: 규칙 → `house.md` · 양식 → `templates/` · 방법 → `analysis/methods/` · 별칭 → 카드의 `aliases`.
**지시에서 물어야 할 것은 "해도 될까요" 가 아니다** 사람이 이미 말했으므로 승인은 끝났다. 봇이 정해야 하는 것은 **경계**다 — 회의록만인가, 주간 보고도인가, PL 에게 나가는 모든 문서인가. **넓게 잡으면 특허 초안까지 회의 양식으로 쓰고, 좁게 잡으면 다음 주에 또 시켜야 한다.** 그래서 묻되 승인이 아니라 경계를 묻고, 물음은 하나다.
**"이번에는" 을 "앞으로는" 으로 듣지 않는다** 한 번의 예외가 영구 규칙이 되면 규약이 금방 쓰레기로 찬다. 서로 충돌하는 줄이 쌓이고 봇은 느려진다. **애매하면 굳히지 않는다** — 사람이 "앞으로" 를 명시했을 때만이다. 이것이 `VERIFICATION.md` 5.1 의 둘째 줄이 재는 것이다.
**왜 관찰형을 안 세나** 세면 **횟수를 들고 있는 상태 파일**이 생긴다. "같은 지적을 세 번 받으면 제안한다" 는 규칙은 곧 카운터를 부르고, 카운터는 점수를 부르고, 점수는 등급을 부른다. 그런데 `journal` 스킬이 이미 매일 돌고 파일도 이미 있다. **일지에 한 줄씩 적어 두고 회고가 읽으면 새 장치가 없다.** 검사 문장은 하나다 — *"이 장치 없이 md 한 장으로 되는가? 되면 md 로 한다."*
**경계는 "되돌릴 수 있는가" 로 긋는다** 사실(카드 · 위키 · 일지)은 틀려도 다음 것이 덮으니 **자동으로 늘어도 된다.** 규칙은 한 번 들어가면 그 뒤 모든 판에 **영구히** 작용하니 사람이 세운다. 별칭은 한때 애매한 자리로 봤으나 — 사실인데 검색이 무엇을 찾을지를 바꾸므로 규칙처럼 작용한다 — 이 기준을 그대로 대면 **자동이다.** 한 줄 지우면 원래대로 돌아가고, 잘못 넣어도 검색이 좀 엉뚱해질 뿐 기록이 망가지지 않는다.
**되돌릴 수 있어야 한다** 양식이 v2 가 될 때 v1 이 사라지면 안 된다. 석 달 뒤 "왜 이렇게 됐지" 라는 물음이 반드시 온다. 굳은 파일 머리의 셋이 그 답이다. **정신은 ADR 과 같다 — 과제 폴더판 ADR 이다.**
**왜 `CLAUDE.md` 한 줄인가 (스킬이 아니라)** 굳는 길은 **모든 답변에** 걸려야 한다. "앞으로" 라는 말은 보고를 쓰는 중에도, 분석을 하는 중에도, 그냥 잡담 중에도 나온다. 스킬은 **그 스킬이 도는 동안만** 읽히므로 이것을 못 받는다. 대신 절차의 알맹이는 오케스트레이터의 절에 두어 `CLAUDE.md` 의 40줄 예산을 지켰다 — 오케스트레이터는 사람 말이 올 때마다 어차피 읽힌다.
**재는 것** 굳힌 건마다 범위 물음이 앞에 있나 · "이번엔 짧게" 와 "앞으로 이 양식대로" 를 섞은 대본에서 `templates/` 파일이 하나인가(둘이면 반려) · 봇이 스스로 `house.md` 에 규칙을 더한 건수(0이어야 한다).
**결과** `CLAUDE.md` 한 줄 · `prodev-orchestrator` 의 "굳는 길" 절 · `journal` · `report` · `analysis` 스킬의 걸리는 자리 · `ARCHITECTURE.md` 6.5 · 7 · `PRD.md` F14~F17.

## ADR-036 `retro` 스킬 — 관찰형이 실제로 도는 시점
**상태** 확정 (사람, 2026-09-11)
**맥락** ADR-035 가 "관찰형은 세지 않는다. 일지에 적어 두고 읽다가 알아챈다" 로 정했는데, **그 읽는 시점을 정하지 않았다.** 정하지 않으면 아무도 안 읽고 관찰형 입구는 닫힌 채로 있는다.

그리고 이것이 **사람이 처음 물은 것에 직접 답하는 자리**다 — *"이건 스킬이 필요하다고 판단해서 운영자에게 제안하고 스킬을 만드는 진화하는 장치가 필요해 보여."*
**결정** `retro` 스킬 하나를 둔다 (도메인 열넷째). 트리거는 **사람의 말** — "돌아봐" · "개선할 거 없어?" · "이번 주 어땠어" · "반복되는 거 없나". **cron 은 없다** (자동 브리핑을 안 두기로 했으므로 사람이 부른다).

보고는 넷이다: ① **되풀이된 것**(일지) ② **막힌 것**(훅에 걸린 것 · 검토 불통과 · `find.log` 의 건수 0 줄) ③ **굳힐 후보** — 규칙/양식/방법/별칭 중 어디로 ④ **스킬이나 에이전트가 필요해 보이는 것** — 판별 넷(ADR-037)을 통과한 것만. **봇은 제안까지만 한다.**
**항목마다 근거를 단다 — 이것이 이 스킬의 안전장치다** 회고의 가장 큰 위험은 **봇이 패턴을 지어내는 것**이다. *"이런 게 반복됐습니다"* 는 그럴듯하게 쓰기 아주 쉽고, 틀려도 사람이 알아채기 어렵다. 그래서 **일지 날짜 · `find.log` 줄 · 카드 번호 · 파일 경로** 중 하나를 달게 하고, **근거 없는 항목은 지운다.** `researcher` 의 "출처 없는 문장 금지" 와 같은 정신이다. 넷이 다 비면 "근거로 댈 것이 없습니다" 라고 말한다 — **빈 회고도 기록이다.**
**넷째에 관문을 두는 까닭** 스킬 제안이 **가장 비싸다** — PR 이 필요하고 되돌리기 어렵다. 조건 없이 열어 두면 봇이 뭐든 스킬로 만들자고 한다. **"데이터로는 왜 안 되는가" 에 답하지 못하면 제안하지 않는다.** 통과한 것이 없으면 "없음" 이라고 쓰고, 채우려고 만들지 않는다.
**제안 글에 셋이 있어야 한다** (a) 원본 경로 (b) **실제로 들어갈 문장** (c) 까닭. (b) 를 비우고 "문체 규칙을 정하시죠" 라고만 하면 **사람이 대신 문장을 짜야 하고, 그러면 회고가 일을 안 한 것이다.** 검수도 건수가 아니라 이 셋으로 잰다 — 건수는 봇이 늘리기 쉽고 셋은 못 늘린다.
**만드는 것은 봇이 아니다** 스킬과 에이전트를 만드는 것은 prodev 제작 세션이고 worktree + PR 이다. 봇은 과제 저장소와 제 봇 폴더에만 쓴다.
**왜 지금 여기서 만드나** **회사에서는 스킬을 못 만든다.** 관문도 예측도 없고 PR 절차가 무겁다. 관찰형 진화가 실제로 도는 자리를 회사에서 새로 설계하게 두면 아무도 그 판정을 안 한다 (ADR-031).
**대화 DB 가 없어도 돈다** 일지 파일과 `find.log` 만으로 넷을 채운다. 세션 대 세션 시험에서 대화 층이 비기 때문이다 (ADR-029).
**재는 것** 제안 글에 셋이 있나 (`VERIFICATION.md` 5.1 다섯째). **채택률은 여기서 못 잰다** — 쌓인 일지가 없다. 실전 2주(T4)의 것이다.
**결과** `.claude/skills/retro/SKILL.md`(새) · `journal` 의 `## 되풀이된 말` · `prodev-orchestrator` 분기표 · `ARCHITECTURE.md` 10 · `PRD.md` N9 · `docs/skill-matrix.md` · `test/skills.test.js`.

## ADR-037 스킬을 만드는 기준은 능력이 아니라 판별 넷이다
**상태** 확정 (사람, 2026-09-11)
**맥락** v3 에서 스킬이 둘 늘었다(`analysis` · `retro`). 늘릴 때마다 같은 물음이 온다 — **"AI 가 잘하는데 굳이 만들 필요가 있나."**

그 물음이 사실 틀렸다. **스킬과 에이전트는 능력을 주는 장치가 아니라 다른 것 셋을 주는 장치다.** 기준을 적어 두지 않으면 이 물음이 스킬을 만들 때마다 처음부터 다시 논의된다. 그리고 `retro` 의 넷째 보고(스킬 제안)에는 **관문이 필요한데 그 관문이 이것이다.**
**결정** 넷으로 판별한다. 하나라도 예가 아니면 **만들지 않는다.**

| 물음 | 예라면 | 왜 |
|---|---|---|
| 결정을 바꾸는 **숫자**가 나오나? | 스크립트로 | 재현과 검수. **틀려도 아무도 모르는 것**을 막는다 |
| **시키지 않아도** 그 자리가 열려야 하나? | 스킬로 | 스킬이 사는 것은 능력이 아니라 **타이밍**이다 |
| 출력이 커서 **대화를 덮나**? | 서브에이전트로 | 문맥 격리. `data-reader` 가 하는 일이 정확히 이것 |
| 셋 다 아니다 | **만들지 않는다** | 그냥 AI 가 하게 두고, 막는 규약이 있으면 **그 규약을 푼다** |

**이 표로 v3 의 둘을 판별하면** `analysis` 는 둘째다 — "분석해 줘" 를 받을 자리가 스킬 열둘 어디에도 없었다. `retro` 도 둘째다 — 일지에 쌓인 것을 **읽는 시점**이 없었다. **둘 다 능력이 없어서가 아니라 타이밍이 없어서 만든 것이다.**
**만들지 않기로 한 것도 적어 둔다** **물리적 의미를 논의하는 것은 넷째라 만들지 않는다.** 해석은 매번 달라야 하는 일이라 절차로 묶으면 체크리스트 채우기가 되고 **지금보다 못해진다.** DOE 후보를 여럿 만들어 비교하는 것은 셋째(문맥 격리)라 서브에이전트 자리이고, t 검정·Cpk 같은 계산은 첫째라 스크립트인데 — **미리 만들지는 않는다.** 되풀이돼 굳은 것만 `analysis/methods/` 로 간다 (ADR-034).
**검사 문장 하나** *"이 장치 없이 md 한 장으로 되는가? 되면 md 로 한다."* 본보기는 400 단어 · 원칙 넷 · 장치 없는 `CLAUDE.md` 이고, 각 원칙에 스스로 판별할 수 있는 검사 문장이 하나씩 붙어 있다. **AI 가 똑똑하므로 장치가 할 일을 문장이 대신할 수 있다.**
**예외 하나** **meta 의 계측은 기계여야 한다.** 손으로 센 숫자는 근거가 아니라는 규칙은 그대로다. 다만 그 계측 장치를 **봇 안에 넣지 않는다** — 밖에서 파일과 방 기록을 세면 된다. 봇은 md 만 갖는다.
**재는 것** `retro` 의 넷째 보고에 판별을 통과하지 못한 제안이 섞이는가 (`VERIFICATION.md` 5.1 다섯째가 함께 본다).
**결과** `.claude/skills/retro/SKILL.md` 의 판별 표 · `ARCHITECTURE.md` 10 · `design/README.md` 는 바뀌지 않는다.
