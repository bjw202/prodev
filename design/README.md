# design — 판(版)별 설계 문서

설계 문서는 **판마다 한 폴더**에 모아 둔다. 코드와 기록은 계속 자라지만,
"그때 무엇을 약속했나"는 판이 바뀌어도 그대로 남아 있어야 하기 때문이다.

## 판 목록

| 판 | 언제 | 무엇 | 상태 |
|---|---|---|---|
| [`v1/`](v1/) | 2026-09-10 | 1차 설계. 방 둘 · 비서 하나 · 스킬 열둘 · 에이전트 여섯 · 훅 셋 | 지난 판 |
| [`v2/`](v2/) | 2026-09-11 | 검색 안정성. 찾기 층 여섯(과제 문서를 더함) · 카드 결과 절 규격(갈래마다 깊이를 다르게) · 세션 대 세션 시험 (ADR-026~030) | **지금 판** |

## 한 판은 문서 다섯이다

| 문서 | 무엇 |
|---|---|
| `PRD.md` | 무엇을 왜 만드나 — 시나리오 · 요구 · 범위 밖 |
| `ARCHITECTURE.md` | 어떻게 생겼나 — 자리 · 흐름 · 부품 |
| `ADR.md` | 왜 그렇게 정했나 — 결정과 근거 |
| `TASKS.md` | 누가 언제 무엇을 — 단계와 관문 |
| `VERIFICATION.md` | 어떻게 검수하나 — 층 · 대본 · 예측표 |

## 판을 올리는 법

1. `design/v<다음>/` 을 만들고 앞 판의 다섯을 복사한다.
2. 새 판에서 고친다. **앞 판은 손대지 않는다** — 지난 약속을 지우면 "왜 이렇게 했지"에 답할 수 없다.
3. 이 파일의 판 목록에 줄을 더하고, 앞 판의 상태를 `지난 판` 으로 바꾼다.
4. 뿌리 `README.md` 의 문서표가 새 판을 가리키게 한다.
5. 판이 바뀐 까닭은 새 판의 `ADR.md` 에 절로 남긴다.

## 경로 규칙

이 아래 문서에 적힌 경로는 **prodev 저장소 뿌리 기준**이다.
`docs/as-built.md` 는 `prodev/docs/as-built.md` 이고, `../meta/` 는 prodev 의 형제 폴더다.
같은 판 안의 문서끼리는 이름만 적는다 (`ARCHITECTURE.md`).
