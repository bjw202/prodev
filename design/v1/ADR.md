# prodev — 설계 결정 기록 (ADR)

한 결정에 한 절. 서식: 상태 · 맥락 · 결정 · 까닭(근거가 있으면 경로) · 결과. 뒤집으면 지우지 않고 상태를 바꾸고 새 절을 더한다.

---

## ADR-001 봇은 하나다
**상태** 확정 (사람, 2026-09-09 · 09-10)
**맥락** crew 는 봇 다섯이었다. 순차형 과제에서 같은 품질에 15~19배를 물었고, 사실 셋이 봇 계층을 넘으며 떨어졌다 (`../crew/EVOLUTION.md` S3 부록·정정). 고영혁 팀은 봇 열둘이지만 사람 하나에 병렬 갈래 과제였고 계측이 없다 (`../meta/prodev-review/notes/external-evidence-gonnector.md`).
**결정** 과제마다 상주 비서 하나. 전문 일은 비서 안의 서브에이전트. 별도 봇은 "며칠 이어지고 사람이 직접 말하고 싶고 본방과 섞이면 불편할 때"만 뗀다.
**결과** 기억이 한 곳. 계층 손실 없음. 대신 세션이 한 번에 한 턴이라 긴 일은 백그라운드로 (ADR-009).
**바뀐 자리 (ADR-022)** 갈래 방은 미리 열려 있지 않다. 방은 둘뿐이므로, 봇을 뗄 때 그 방을 새로 연다.

## ADR-002 알갱이는 실험 한 건(카드)이다
**상태** 확정 (사람, 2026-09-10)
**맥락** 파일 하나 = 카드 하나면 한 실험의 파일 넷이 흩어진다. 사람이 말하는 단위는 실험이다.
**결정** 카드 하나가 파일 여럿을 거느린다. 파일마다 사이드카(열·단위·행 수·SHA-256)는 둔다.
**결과** 카드에 `files`·`source_msgs` 칸. 색인은 카드 기준.

## ADR-003 과제마다 git 저장소 하나
**상태** 확정 (사람, 2026-09-10)
**맥락** crew 의 방 저장소 방식이 이력과 되돌리기를 줬다.
**결정** 과제 폴더 = git 하나. 원격은 선택. 봇의 자기 상태(handoff·threads·rooms.json)는 저장소 밖(봇 폴더).
**결과** 서브에이전트는 커밋하지 않는다. 주 턴만 경로 지정 커밋.

## ADR-004 위키는 카드가 valid 될 때마다 즉시 갱신한다
**상태** 확정 (사람, 2026-09-10) · **재는 조건 붙음**
**맥락** crew 에서 위키·색인 반영이 archivist 값의 4분의 3($36/$47)이었고 어느 봇도 읽지 않았다. 검토는 주 1회를 권했다.
**결정** 사람이 즉시 갱신을 택했다. 대신 값을 재고 읽힘을 잰다: 들이기 한 건의 위키 비용(예측 ≤ $0.5), `find.log` 에서 위키 층이 답한 비율. 4주 연속 0 이면 시점을 다시 정한다.
**결과** 갱신 범위는 카드 tags 에 걸리는 페이지의 "지금 아는 것"과 "이력" 뿐. 페이지 전체를 다시 쓰지 않는다.

## ADR-005 대화는 fetch_history 가 아니라 DB 를 직접 읽는다
**상태** 확정 (사람, 2026-09-10)
**맥락** `fetch_history` 는 최근 N 개를 자른 뒤 거른다(OD-9). 말로는 못 찾는다. 대화 DB 는 서버가 켜진 채로 읽기 전용으로 열린다 (실측, `../meta/prodev-review/plans/proto/chat.js`).
**결정** `scripts/chat.js` (search · around · since · tail · show · rooms). 봇은 봉투의 `message_id` 로 자기 자리를 안다.
**결과** minidiscord 서버 수정(FTS·검색창)은 사람 편의로 미룬다. 여러 낱말은 AND.

## ADR-006 서버 커서를 믿지 않는다
**상태** 확정 (검토 2026-09-10)
**맥락** 게이트웨이는 소켓에 보낸 순간 `last_delivered_id` 를 올린다. 턴 도중 압축·사망이면 그 글은 다시 오지 않는다.
**결정** 봇 폴더 `rooms.json` 에 방마다 "내가 처리한 마지막 id". 깨어날 때와 매 턴 첫머리에 `chat.js since` 를 방 전부에 돌린다.
**결과** 놓친 @TO 0 이 검수 항목이 된다.

## ADR-007 오토컴팩트는 켜 두고, 직전에 인수인계서를 만든다
**상태** 확정 (사람, 2026-09-10)
**맥락** 압축은 100만 토큰을 1만으로 깎는다(사람이 인용한 사례). `PreCompact` 는 문맥을 못 넣고, 넣는 자리는 `SessionStart(compact)` 의 `additionalContext` 다. 훅 안에서 `claude -p` 가 돈다 (실측 haiku 7초).
**결정** PreCompact 훅이 기록 꼬리 → `claude -p` → `handoff-compact.md`. SessionStart 가 맨 앞에 싣는다. 행동 전 handoff 저장은 그대로 두어 안전망 둘.
**결과** 대화 원본은 minidiscord DB 라 인용 글의 "백업이 뒤 기록을 지운다" 경고는 해당 없다.

## ADR-008 확정은 기계가 판별한다
**상태** 확정 (검토 2026-09-10)
**맥락** "세라"는 지침으로 세 세대 실패했다. 봇이 머리말에 `confirmed_at` 을 적고 훅이 숫자만 보면 같은 실패다.
**결정** pre-reply 훅이 DB 를 열어 그 글이 사람 글 · 같은 과제의 들이기 방 · 확정 어휘 · 첨부 글보다 뒤 · 직전 봇 글에 같은 카드 번호인지 다섯을 본다. DB 를 못 열면 자료 방만 fail-closed.
**결과** 확정 어휘를 사람에게 고정해 준다 ("맞으면 '확정'이라고 답해 주세요").
**바뀐 자리 (ADR-022)** 조건 ② 의 방 이름은 `/files` 다. 관문의 방아쇠도 방이 아니라 **카드 공지 글의 `[카드]` 표식**이고, DB 를 못 열면 카드 공지와 `[발송]` 이 fail-closed 다. 나머지 넷은 그대로.
**보충 (2026-09-10, T3.3 R2 재생 중)** 확정 어휘는 **봉투를 벗긴 본문의 맨 앞**에서 본다. 사람 글은 언제나 봉투로 시작하므로(`@TO(prodev-<과제>-비서) 확정`), 원문 맨 앞에서 어휘를 찾으면 확정이 영영 안 된다. R2 재생 들이기 #19 에서 실제로 막혔다. `^(\s*@(TO|CC)\([^)]*\)\s*)+` 를 떼고 나서 어휘를 본다 (줄바꿈도 봉투 뒤 공백으로 친다). 나머지 넷은 그대로다. 어휘 자체는 좁게 유지한다 — "네" 는 여전히 확정이 아니다.

## ADR-009 세션은 한 턴, 긴 일은 백그라운드
**상태** 확정 (검토 2026-09-10)
**맥락** 세션 하나는 알림을 순서대로 한 턴씩 처리한다. 3분 리서치가 PL 의 물음을 막는다.
**결정** research·patent·paper·report·큰 파일은 백그라운드 서브에이전트. 그 턴은 "시작했습니다" 한 줄. 결과는 파일로, 다음 턴에 알림. 한 턴에 들이기 문답은 한 건.
**결과** 서브에이전트는 커밋하지 않는다. 그림·임시는 `<과제>/tmp/`.

## ADR-010 세션은 상주하지 않는다. 켤 때마다 파일에서 되살아난다
**상태** 확정 (사람, 2026-09-10)
**맥락** 검토는 매일 재시작을 권했다. 사람은 "주간에 필요시 켠다. 껐다 켜도 문맥을 읽고 되살아나야 한다"고 했다.
**결정** 요건은 "매일 재시작"이 아니라 "언제 켜도 되살아남". session-start 가 열린 실·rooms.json·헌장·일정·어제 일지·마지막 일지 날짜를 싣고, 비서가 `chat.js since` 로 꺼져 있던 동안을 전 방에서 따라잡는다.
**결과** cron 브리핑은 켜져 있을 때만 닿는다. 꺼져 있었으면 다음에 켤 때 일지부터 쓴다.

## ADR-011 검토는 다른 문맥에서
**상태** 확정 (crew 실측 2026-09-09)
**맥락** 주 세션 + 검토 세션($1.69)이 오류 셋을 잡았고, 검토 없는 싱글 셋은 첫 오류가 남았다. 문헌(OpenAI LLM Critics)도 같다.
**결정** `reviewer` 서브에이전트가 사람 결재 전 산출물마다 한 번. 스스로 센 숫자를 다시 세고 출처를 대조한다. "괜찮아 보인다"는 판정이 아니다.

## ADR-012 세는 것과 막는 것은 기계, 정하는 것은 지침
**상태** 확정 (`../meta/crew-eval/INTENT.md`)
**맥락** 분량·멘션 수를 지침으로 세게 한 것이 세 세대 실패했고 `count.js` 로 100% 맞았다.
**결정** 분량(count.js) · 확정 · 결재 · chat_id 는 훅. 색인은 index.js. 찾기 순서는 find.js. 지침은 40줄 안.

## ADR-013 제작은 `/harness:harness`, 훅과 배선은 손으로
**상태** 확정 (사람, 2026-09-10)
**맥락** 하네스 스킬(v1.2.0)은 agents·skills·오케스트레이터 스킬·CLAUDE.md 포인터를 만들고, **훅·settings·MCP 배선은 만들지 않는다** (탐색 확인).
**결정** 스킬 열둘 · 에이전트 여섯은 하네스로. 훅 셋 · 스크립트 · settings · setup.js 는 제작 세션이 손으로. meta 는 예측을 먼저 적고 검수한다.

## ADR-014 캐릭터 이름 · 일기의 지혜 승격 · 봇의 성장은 안 한다

**맥락** 고영혁 사례의 세 요소는 계측이 없다. 우리 실측(위키 미읽힘)은 반대 방향이다.

## ADR-016 찾기 순서에서 files.md 를 대화보다 먼저 본다
**상태** 확정 (meta, 2026-09-10, T1.3 착수 전)
**맥락** find.js 5층 시험에서 `particle_defects` 가 대화 층(옛 4층)에서 봇이 붙여넣은 코드 17건에 걸려 사이드카 files.md(옛 5층)에 닿지 못했다. 대화에는 코드·승인 요청 글이 섞이고, 그것을 글 형식으로 걸러 내는 규칙은 깨지기 쉽다.
**결정** 순서를 1 index · 2 카드 · 3 위키 · 4 inbox files.md · 5 대화 로 한다. 파일이 대화보다 먼저다. 대화 층은 여러 건(≤10, 최근 것부터)을 그대로 돌려주고 차례 규칙을 두지 않는다. 시험은 대화 층만 "기대 #id 가 결과 안에 든다"로 잰다.
**재는 것** VERIFICATION 의 P8 "1~3층 답한 비율"은 그대로. find.log 의 층 번호는 새 번호다.

## ADR-017 설계 문서에 자리가 없던 것 둘 — 절 작업 자리와 검토 판정 파일
**상태** 확정 (meta, 2026-09-10, T2.3)
**맥락** T2.2 에서 스킬 본문을 쓰다 설계 문서가 경로를 정해 두지 않은 자리가 둘 나왔다. ① `paper` 는 "절마다 초안 + 절마다 사람 통과"인데(B 표) 통과 전 초안과 통과한 원고가 같은 파일에 섞이면, 사람이 아직 안 본 절이 원고에 들어간다. ② PRD F8 은 "검토 판정 파일이 산출물마다 있다"를 요구하는데 그 파일이 어디 놓이는지는 어디에도 없다.
**결정** ① 절 작업 자리는 `paper/sections/<절>.md`. 사람이 절 통과를 준 것만 `paper/draft.md` 에 순서대로 모은다 — B 표의 산출 이름(`outline.md` · `draft.md` · 그림)은 그대로고, `sections/` 는 그 아래 작업 자리다. 그림은 `<과제>/tmp/` 에 그려 결재 뒤 `paper/figures/` 로 옮긴다. ② `reviewer` 의 판정은 `<산출물>.review.md` 에 둔다 (`research/수율.md` → `research/수율.md.review.md`). 산출물 옆에 있어야 어느 것에 대한 판정인지 경로만으로 서고, 산출물이 지워질 때 같이 지워진다.
**재는 것** F8 은 "산출물마다 `.review.md` 가 있다"로 센다. `docs/skill-matrix.md` 의 paper · review 행이 이 경로를 쓴다.

## ADR-018 알림 경로는 사람 계정의 세션 쿠키 + multipart 다
**상태** 확정 (meta, 2026-09-10, T3.1)
**맥락** cron 두 줄(08:00 브리핑 · 18:30 일지)과 `pre-compact` 의 "정리 중" 알림을 `Authorization: Bearer` + JSON 으로 적어 두었는데, 시험 서버(포트 3123 · 빈 DB)에 그대로 넣어 보니 안 된다. 서버는 인증을 쿠키 `md_session` 하나로만 받고(`server/src/auth.ts` 의 `requireAuth`), 글 올리기 라우트는 multipart 만 읽는다(`routes-messages.ts` 의 `req.parts()`). 잰 값: JSON+Bearer → **401** · JSON+쿠키 → **406** · multipart+쿠키 → **200**. 설계에 Bearer+JSON 이라 적은 것은 meta 의 잘못이다. 서버는 손대지 않는다 (PRD 6절 · ARCHITECTURE 11절).
**결정** 부르는 쪽을 고친다. cron 두 줄과 훅의 알림은 `-b "md_session=$PRODEV_NOTIFY_TOKEN"` + multipart 로 보낸다. `-F` 가 아니라 **`--form-string`** 이다 — `-F` 는 `@` 로 시작하는 값을 파일 경로로 읽고, 멘션은 언제나 `@TO(` 로 시작한다 (시험이 이것을 curl 26 으로 잡았다). 토큰의 이름은 `PRODEV_NOTIFY_TOKEN` 하나이고 값은 알림 계정(사람 계정)의 `md_session` 값이다. `MINIDISCORD_URL` 은 그대로 쓴다.
**봇 문맥에 두지 않는다** `setup.js` 가 만드는 `settings.json` 의 `env` 에 `PRODEV_NOTIFY_TOKEN` 을 넣지 않는다. 훅은 봇 폴더의 `.env` 또는 훅을 띄운 실행 환경에서 읽는다. 사람 계정의 토큰이 봇의 문맥에 실리면 봇이 사람인 척 글을 쓸 수 있다.
**재는 것** `test/server/setup.test.js` 가 cron 두 줄에 쿠키·`--form-string` 이 있고 `Bearer` 가 없음을 보고, **낸 줄을 그대로 서버에 쏴 200 과 남은 글**을 확인한다. `test/hooks.test.js` 가 모의 서버로 훅이 보낸 요청의 쿠키·multipart 를 확인한다.
**보충 (사람, 2026-09-10, R5 재측정 뒤)** 알림은 **둘**이다. 압축 직전(`pre-compact`)의 "문맥을 정리 중입니다. 곧 이어서 합니다." 와 압축 **직후**(`session-start`, `source: compact` 일 때만)의 "정리가 끝났습니다. 이어서 하려면 말을 걸어 주세요." 다. 까닭: 압축 뒤에는 사람이 말을 걸어야 봇이 이어서 하므로 사람이 그 시점을 알아야 한다. 껐다 켠 경우(`startup`·`resume`·`clear`)에는 올리지 않는다 — 서버가 놓친 글을 재배달하니 사람이 따로 할 일이 없다 (R5 에서 두 번 확인).
**방을 어떻게 찾나** 앞의 것이 있으면 뒤는 안 본다: ① `PRODEV_NOTIFY_ROOM` ② 봉투의 `chat_id`(PreCompact 입력에는 없다) ③ **인수인계서의 "방과 마지막 message_id" 절 첫 `chat_id`** — 하던 방이 있으면 거기가 맞다 ④ `rooms.json` 의 본방(이름에 갈래가 없는 방). 못 찾으면 **아무 데도 안 보낸다** — 갈래 방에 던지면 자료 방이 더러워진다.
**바뀐 자리 (ADR-022)** 방이 둘뿐이라 ④ 의 "이름에 갈래가 없는 방"은 접미어 `/files` 가 없는 방이다. 못 찾으면 아무 데도 안 보내는 것은 그대로다.
**한 자리에 둔다** 방 찾기·토큰·보내는 꼴은 `common/hooks/places.js` 의 `알릴방` · `알림토큰` · `알린다` 하나뿐이고 훅 둘이 그것을 부른다. 두 곳에 따로 적으면 언젠가 갈리고, 갈리면 한쪽만 조용히 안 나간다 — 이 자리에서 이미 두 번 겪었다 (URL 없음 · 방 번호 없음).

## ADR-019 파일 뿌리는 deny 하지 않는다 — 0층 불변은 0444 와 git 이 지킨다
**상태** 확정 (meta, 2026-09-10, T3.3 R1 재생 중)
**맥락** `setup.js` 가 파일 뿌리(`MINIDISCORD_BOT_FILES_DIR`)와 서버 업로드 폴더를 한 변수로 묶어 두고, 그 자리를 `Write(…/**)` · `Edit(…/**)` 로 막았다. T1.6 의 "업로드 폴더는 읽기만 (0층 불변)" 이 그대로 옮겨진 것이다. 그런데 ARCHITECTURE 11절이 정한 파일 뿌리는 **과제 저장소들의 부모**다 (봇 첨부가 뿌리 밖이면 서버가 조용히 뺀다). 그래서 과제 폴더 자체가 쓰기 금지가 됐다. R1 재생에서 봇이 헌장을 다 만들고도 `charter.md` 를 못 써 봇 폴더의 `pending-charter.md` 에 들고 있었다 (본방 #7 · #9 · #11).
**결정** 파일 뿌리는 `additionalDirectories` 로 **열기만** 하고 deny 하지 않는다. 서버 업로드 폴더(`<DATA_DIR>/uploads`)는 남의 원본이라 읽기 전용으로 두되, **그 폴더가 과제 폴더를 덮으면 넣지 않는다.** 그리고 `setup.js` 가 설정을 쓰기 전에 deny 가운데 과제 폴더를 덮는 것이 있으면 예외로 죽는다 — 조용히 못 쓰는 봇이 되느니 설치가 실패하는 편이 낫다.
**0층은 무엇이 지키나** 권한 목록이 아니라 ① `intake-copy.js` 가 들인 원본에 거는 `0444` ② git 이다. `inbox/**` 를 deny 로 좁히는 길도 있었으나 사이드카(`files.md`)는 같은 폴더에서 계속 고쳐 써야 하고 Claude Code 의 deny 규칙으로 한 파일만 빼기가 안 되므로, 0444 에 맡긴다.
**재는 것** `test/server/setup.test.js` 가 만들어진 `settings.json` 의 deny 에 과제 폴더를 덮는 항목이 0건임을, 그리고 파일 뿌리가 deny 에 없고 `additionalDirectories` 에 있음을 본다.

## ADR-020 사람이 읽을 산출물은 방에 첨부한다. 경로는 그 옆에
**상태** 확정 (사람, 2026-09-10, T3.M 뒤)
**맥락** 스킬 다섯이 산출물을 만든 뒤 방에는 경로만 적었다 (`경로: research/수율.md`). 재생에서 사람이 짚었다 — 경로만 주면 파일을 열러 가야 하고, 대개 열지 않는다. minidiscord 는 첨부를 그대로 실어 주고, 봇은 이미 첨부할 수 있다 (`MINIDISCORD_BOT_FILES_DIR` 안이면 된다. 과제 저장소는 그 안이다).
**결정** 사람이 읽을 파일 — 리서치 문서 · 검토 판정 파일 · 보고서 · 논문 절과 그림 · 브리핑이 가리키는 정리표 — 은 **방에 첨부**하고 경로는 그 옆에 적는다. 경로만 주지 않는다. 대상 스킬: `research` · `patent` · `paper` · `report` · `brief`.
**첨부하지 않는 것** 카드와 위키는 자료 방 글이 이미 6줄로 요약을 싣고 사람이 훑는 색인 노릇을 하므로 그대로 둔다 (자료 방 글에는 **원본**을 첨부한다 — 5.1 그대로). 대화 기록·색인처럼 기계가 읽는 것도 첨부하지 않는다.
**바뀐 자리 (ADR-022)** 카드와 위키를 첨부하지 않는 것은 그대로다. 다만 그것을 요약해 싣던 글은 이제 `files` 방의 **카드 공지 한 줄**(번호 · 제목 · 경로)이고, 원본은 사람이 올린 글에 이미 있으므로 다시 첨부하지 않는다.
**걸리는 자리** 첨부는 `MINIDISCORD_BOT_FILES_DIR` 뿌리 안이어야 한다. 밖이면 서버가 **조용히** 뺀다 — 그래서 그림·임시는 `/tmp` 가 아니라 `<과제>/tmp/` 에 둔다 (ADR-019 와 같은 뿌리 이야기다).

## ADR-021 rooms.json 은 방 이름표다. 놓친 글은 서버 재배달을 믿는다 (ADR-006 뒤집음)
**상태** 확정 (meta, 2026-09-10, T3.M 뒤) — **ADR-006 을 대신한다**
**맥락** ADR-006 은 게이트웨이가 소켓에 보낸 순간 `last_delivered_id` 를 올리므로 턴 도중 압축·사망이면 그 글이 다시 오지 않는다고 보고, 봇 폴더 `rooms.json` 에 "내가 처리한 마지막 id" 를 두고 매 턴 첫머리에 갱신하기로 했다. **재생 다섯(R1~R5)이 그 전제를 반증했다**: `last_seen_id` 가 끝까지 전부 0 이었는데(아무도 갱신하지 않았다) 놓친 글 다섯은 서버 재배달(`room_bots.last_delivered_id`)이 전부 가져왔다. 지침으로 시킨 갱신 걸음은 지켜지지 않았고, 지켜지지 않았는데도 검수 항목("놓친 @TO 0")은 통과했다.
**결정** (나) 를 택한다. `rooms.json` 은 **방 번호 → 방 이름 표**로만 쓴다 (`setup.js` 가 쓰고, `places.js` 가 DB 를 못 열 때 방 갈래를 아는 데 쓴다 — 지금도 그렇게 쓰고 있다). `last_seen_id` 는 아무도 갱신하지 않으므로 **믿지 않는다.** 놓친 글은 서버 재배달에 맡긴다. 매 턴 첫머리 갱신 걸음은 지침에서 뺀다.
**왜 (가) 가 아닌가** 갱신 걸음을 오케스트레이터나 journal 에 넣으면 지침이 한 줄 늘고 매 턴 비용이 는다. 그런데 그 걸음이 막는 일(재배달 실패)이 다섯 대본에서 한 번도 일어나지 않았다. **계측이 없는 것은 안 한다** (ADR-014 와 같은 결). 재배달이 실제로 글을 흘리는 것을 보면 그때 (가) 로 돌아간다 — 그 자리는 "놓친 @TO 0" 검수 항목이 지킨다.
**남는 것** `last_seen_id` 칸은 `setup.js` 가 0 으로 쓰는 채로 둔다. 지우면 `rooms.json` 을 읽는 자리가 모두 바뀐다. 대신 그 값을 **읽는 코드는 없다** — 이 ADR 이 그 약속이다.
**바뀐 자리 (ADR-022)** `rooms.json` 이 아는 방 갈래는 이제 둘(본방 · `/files`)뿐이다. 방 이름표라는 쓰임은 그대로.

## ADR-022 과제 하나 = 방 둘 (본방 · files)
**상태** 확정 (사람, 2026-09-10 저녁)
**맥락** 3단계 재생 다섯을 돌린 뒤, 옛 방 묶음(본방 + 갈래 여섯)에 실제로 오간 글을 셌다: **본방 60 · 들이기 23 · 리서치 14 · 자료 1 · 특허 0 · 논문 0 · 보고 0.** 갈래 방 셋(특허 · 논문 · 보고)은 한 글도 받지 못했고, 카드 방은 한 글이었다. 봇은 방이 아니라 `PRODEV_PROJECT` 로 과제를 알므로(ADR-012) 방을 나눠도 봇이 얻는 것이 없다. 카드 방의 색인 노릇은 아무도 읽지 않았고, 봇 자신도 `find.js` 와 색인 파일로 찾는다. 그리고 비서 지침의 "갈래 방은 사람이 허락해야 연다"와 `setup.js` 의 "방을 다 만든다"가 서로 어긋나 있었다 — 지침은 열지 말라 하고 설치는 미리 다 열었다.
**결정** 과제 하나에 방은 **둘**이다. 본방 `prodev-<과제>` (접미어 없음. 사람에게는 "오피스" 노릇) 와 `prodev-<과제>/files` (파일 올리기와 그 문답. 옛 들이기 자리). 갈래 방 다섯은 없앤다. 방 이름 접미어는 **영어만** 쓴다. 사람이 외우는 규칙은 한 줄이다 — **"말은 아무 데서나, 파일은 files 에."**
**봇의 태도** ① 어느 방에서든 답한다. 방을 이유로 답을 거부하거나 다른 방으로 보내지 않는다. ② 파일은 `files` 방에서 읽고 묻고 확정을 받아 카드로 만든다. 카드가 valid 가 되면 그 방에 **카드 한 줄 공지**(카드 번호 · 제목 · 경로)를 올린다 — 옛 카드 방 글(6줄 + 원본 첨부)을 이 한 줄이 대신한다. 원본은 사람이 올린 그 글에 이미 있으므로 다시 첨부하지 않는다. 색인은 `index.js` 가 만드는 파일이 진실이다. ③ 본방에 파일이 올라오면 한 줄만 안내한다: "파일은 files 방에 올려주시면 거기서 읽고 여쭙겠습니다." 본방에서는 읽기 시작하지 않는다. **이것이 유일한 안내다.** ④ 리서치 브리핑 · 특허 · 논문 · 보고 산출물은 본방에 올린다 (첨부 + 경로, ADR-020 그대로).
**훅의 방아쇠를 방에서 표식으로 옮긴다** 확정 관문(ADR-008 다섯 조건)은 살린다. 조건 ② 의 방 이름은 **`/files`** 가 된다 (옛 문구는 ADR-008 의 결정 절에 그대로 있다). 방아쇠는 "카드 방에 쓸 때"가 아니라 **카드 공지 글**이다. 카드 공지 글의 표식은 이렇다 — 봉투(`@TO(…)` · `@CC(…)`)를 벗긴 본문의 **첫 줄**이 `[카드] <번호> · <제목> · <경로>` 꼴이고, 훅은 `^\[카드\]\s+(E|R|D|N)-\d{4}\s+·` 로 알아본다. 발송 결재 관문은 "보고 방이면"을 버리고 첫 줄의 **`[발송]` 표식**만으로 건다 (어느 방이든). DB 를 못 열 때의 fail-closed 는 카드 공지와 발송에 그대로다.
**파일 규칙에 예외를 두지 않는다 (보탬, 2026-09-10)** "파일은 files 에" 가 예외 없이 참이어야 사람이 규칙 하나만 외운다. 그래서 실험 자료가 아닌 파일 — 보고 양식 · 논문 초안 · 특허 자료 — 도 `files` 방에 올린다. 첨부가 곧 들이기(intake)라는 뜻은 아니다: `files` 방의 첨부 글이라도 **시키는 말**("8월치로 채워 주세요")이 붙으면 `report` · `paper` · `patent` 로 간다. 산출물이 본방으로 가는 것은 그대로다 (위 ④).
**표식의 방아쇠는 `[카드]` 하나다 (보탬, 2026-09-10)** 첫 줄이 `[카드]` 로 시작하면 번호 꼴이 아니어도 관문에 세우고 막는다. 표식을 붙였으면 그것은 공지이고, 번호 없는 공지는 사람이 훑는 색인 줄이 못 되기 때문이다. 번호 꼴 검사는 관문 안에서 한다. 방을 모르는 `chat_id` 여도 표식이 있으면 관문이 걸린다.
**왜 표식인가** 요건이 둘이었다. 확정 없이는 카드 공지가 **기계적으로** 안 나가야 하고, 봇이 평소 답에서 카드 번호를 입에 올리는 것은 막히면 안 된다. 방이 하나로 합쳐진 뒤에는 방으로 이 둘을 가를 수 없다. 표식은 봇이 스스로 붙이는 것이지만, 붙이지 않으면 그 글은 카드 공지가 아니고 사람이 읽는 색인 줄도 아니다 — 붙였을 때만 관문이 걸리는 것으로 충분하다.
**결과** ADR-001 · 008 · 018 · 020 · 021 가운데 방 이름을 든 문장이 바뀐다 (각 절에 "바뀐 자리 (ADR-022)" 한 줄을 달았다. 옛 결정 본문은 지우지 않는다). "방 갈래를 DB 로도 `rooms.json` 으로도 모르면 막지 않는다"는 예외는 없어진다 — 표식이 방아쇠라 방을 몰라도 관문이 걸린다. 이 ADR 은 **설계 문서에만** 들어간다. `setup.js` · `pre-reply.js` · 스킬 열셋 · 시험은 뒤따르는 코드 PR 에서 맞춘다.

## ADR-023 과제 폴더는 setup 이 만든다
**상태** 확정 (사람, 2026-09-10)
**맥락** 지금까지 사람이 과제 폴더를 손으로 만들고 그 **절대 경로**를 `--project` 에 줬다. 자리를 두 번 외워야 했다 — 폴더를 만들 때 한 번, 그리고 `MINIDISCORD_BOT_FILES_DIR` 이 그 **부모**여야 한다는 규칙에서 또 한 번 (ADR-019). 둘이 어긋나면 봇이 첨부를 못 하는데 서버가 **조용히** 빼므로 한참 뒤에야 보인다. 사람이 "과제 하나 = 파일 뿌리 아래 폴더 하나, 만드는 것은 setup" 으로 정했다.
**결정** `--project` 는 이름도 경로도 받는다. `/` 가 들어 있거나 이미 있는 자리면 지금까지처럼 **경로**로 본다. **이름만이면 `$MINIDISCORD_BOT_FILES_DIR/<이름>`** 이다. 폴더가 없으면 하위 열과 함께 만들고 `git init` 까지 한다 (ADR-003 의 "과제 폴더 = git 하나"). 이름만 줬는데 파일 뿌리를 모르면 **죽는다** — 조용히 엉뚱한 자리에 만드느니 설치가 실패하는 편이 낫다 (ADR-019 와 같은 결).
**있는 것은 건드리지 않는다** 다시 돌려도 과제 폴더 안은 그대로다. `.git` 이 이미 있으면 `git init` 을 하지 않는다. `charter` 스킬의 `git init` 걸음도 "아직 git 이 아니면" 그대로 둔다 — 두 자리가 같은 일을 하지만 둘 다 조건부라 겹쳐도 해가 없다.
**git 이 실패해도 설치는 이어 간다** 못 했다는 한 줄만 남긴다. 커밋은 나중 일이고, 여기서 멈추면 봇을 못 띄운다.
**재는 것** `test/server/setup.test.js` 세 건: ① 이름만 줬을 때 과제 폴더 · `.git` · 봇 폴더 셋이 생긴다 ② 있는 폴더에 다시 돌려도 안의 파일 목록과 해시가 같다 ③ 파일 뿌리를 모르면 `MINIDISCORD_BOT_FILES_DIR` 을 이름에 담아 죽는다.
**결과** `docs/launch.md` 3절과 10.8 의 걸음에서 사람이 폴더를 미리 만들 일이 없어진다.

## ADR-024 사람이 마주치는 이름은 영어로, 알림 토큰은 setup 이 받는다
**상태** 확정 (사람, 2026-09-10)
**맥락** 첫 기동을 해 본 사람이 세 마디를 했다. ① "알림이 무슨 말인지 모르겠다" — `prodev-알림` 이라는 계정이 채팅 목록에 앉아 있는데 그것이 봇인지 사람인지 무엇을 하는지 이름만으로는 안 보였다. ② "토큰을 어디서 복사하는지 모르겠다" — `launch.md` 7.1 이 `curl … | grep -i set-cookie` 로 쿠키 값을 꺼내 `.env` 에 붙여 넣으라고 시켰는데, 그 값이 무엇이고 왜 필요한지가 파일 어디에도 없었다. ③ "비서는 영어로" — 코드와 채팅에 `prodev-<과제>-비서` 처럼 한글이 섞이면 눈에 걸린다.
**결정** 둘을 바꾼다. ① **이름**: 봇은 `prodev-<과제>-bot`, 알림 계정은 `prodev-notify`. 과제 이름은 사람이 정하는 것이라 한글이어도 된다 — 바꾸는 것은 **우리가 붙인 이름**뿐이다. ② **토큰**: `setup.js --project` 가 서버가 떠 있으면 `prodev-notify` 로 한 번 로그인해(이름 하나면 계정이 없을 때 생긴다) 응답의 `md_session` 값을 `bots/<봇>/.env` 의 `PRODEV_NOTIFY_TOKEN=` 에 쓴다. 이미 값이 있으면 **덮지 않는다**. 서버가 꺼져 있으면 `rooms` 가 그러듯 "서버를 켜고 다시 돌리면 받는다" 로 넘어간다.
**.env 에 풀이를 붙인다** 토큰 줄 위에 한 줄이 함께 적힌다: `# PRODEV_NOTIFY_TOKEN: prodev-notify 계정의 세션 쿠키. 훅과 cron 이 본방에 알림 글을 올릴 때 쓴다 (봇 글은 게이트웨이만 보낼 수 있어서 사람 계정이 필요하다)`. 사람이 파일을 열었을 때 무엇인지 모를 값이 없어야 한다 — 사람의 두 번째 마디가 그것이었다.
**공용 api() 를 쓰지 않는다** `setup.js` 의 `api()` 는 받은 쿠키를 모듈 변수에 담아 다음 부름에 실어 보낸다. 알림 로그인을 거기로 태우면 그 뒤의 봇 등록이 알림 계정으로 나간다. 그래서 알림 로그인만 `fetch` 를 직접 쓴다.
**봇 문맥에는 여전히 두지 않는다** `settings.json` 의 `env` 에 `PRODEV_NOTIFY_TOKEN` 을 넣지 않는 것은 그대로다 (ADR-018). 사람 계정의 토큰이 봇 문맥에 실리면 봇이 사람인 척 글을 쓸 수 있다. `.env` 는 훅이 읽는 자리이지 봇의 문맥이 아니다.
**재는 것** `test/server/setup.test.js` 둘: ① `setup` 뒤 `.env` 에 풀이 한 줄과 64자리 16진 토큰이 있고, **그 값으로 본방에 글을 올리면 200 이고 쓴 이가 `prodev-notify`** 다 — "파일에 뭔가 있다" 로는 걸음이 없어졌는지 알 수 없다 ② `.env` 에 값이 이미 있으면 덮지 않는다.
**결과** `launch.md` 의 사람 걸음에서 토큰 관련이 **셋에서 둘로** 준다: 알림 계정 만들기와 쿠키 복사가 없어지고, 재생용 PL·과제원 토큰 넘기기만 남는다. crontab 에 붙일 값은 이제 `.env` 에서 그대로 옮기면 된다.

## ADR-025 설계 문서는 판마다 한 폴더 (`design/v<판>/`)
**상태** 확정 (사람, 2026-09-11)
**맥락** 설계 문서 다섯(PRD · ARCHITECTURE · ADR · TASKS · VERIFICATION)이 저장소 뿌리에 낱개로 있었다. 설계를 고치면 원본을 덮어썼고, 앞 판은 git 이력을 뒤져야 보였다. 1차 설계가 2026-09-10 에 닫혔고 지금 2차를 크게 새로 세우는 참이다. 1차의 약속이 2차를 쓰는 동안 덮이면 "그때 무엇을 약속했나" 에 답할 수 없다 — 이 ADR 이 뒤집힌 결정을 지우지 않고 상태만 바꿔 쌓는 것과 같은 결이다.
**결정** 설계 문서는 `design/v<판>/` 에 판마다 모아 둔다. `design/v1/` 이 1차 설계 다섯이다. 다음 판은 `design/v2/` 를 만들어 앞 판을 복사한 뒤 거기서 고친다. **앞 판은 손대지 않는다.** 판 목록과 판 올리는 걸음 다섯은 `design/README.md` 에 있다. `docs/`(as-built · log · launch · skill-matrix · harness-input)는 판과 상관없이 계속 갱신하는 **기록**이라 옮기지 않는다.
**경로 규칙** 설계 문서에 적힌 경로는 **저장소 뿌리 기준**이다 (`docs/as-built.md` · `../meta/…`). 같은 판 안의 문서끼리는 이름만 적는다 (`ARCHITECTURE.md`). 이미 `docs/` 가 그렇게 쓰고 있던 관행을 글로 못 박았을 뿐, 바꾼 것이 아니다. 그래서 옮기면서 문서 본문의 `../meta/` · `../crew/` 는 그대로 두었다.
**왜 git 이력으로 충분하지 않은가** 이력을 뒤져야 보이는 것은 읽히지 않는다. 두 판을 맞대 보려면 나란히 있어야 한다.
**왜 이 절이 v1 안에 있나** "앞 판은 손대지 않는다" 고 해 놓고 v1 의 ADR 을 고치는 셈이다. 그래도 여기에 둔다 — v2 의 ADR 첫 절로 미루면 v2 를 열기 전까지 이 폴더 구조의 까닭이 어디에도 없다. 문서를 어디에 두느냐일 뿐 설계를 바꾸지 않으므로 작은 예외로 본다. 이 절 말고 v1 본문에서 바뀐 것은 `ARCHITECTURE.md` 4.1 의 폴더 나무 두 줄뿐이다 (자기 자리를 가리키는 그림이라서다).
**결과** 저장소 안에서 이 다섯을 가리키던 참조 서른하나를 따라 고쳤다 (`README.md` · `docs/as-built.md` · `docs/log.md` · `docs/skill-matrix.md` · `docs/harness-input.md` · `intake` 스킬). 뿌리 `README.md` 의 문서표는 둘로 갈랐다 — 설계(판마다 얼어붙는다)와 기록(`docs/`, 계속 자란다). 코드는 한 줄도 바뀌지 않았고 시험 아흔넷은 그대로 통과한다.
